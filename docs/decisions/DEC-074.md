## DEC-074 — What a local build gives up, and the RULE-009 amendment it needs first

**Closed 2026-08-17** — the feature list is an agent default under Default-and-notify,
surfaced at this batch's gate; the rule amendment itself is **not** decided here and is its
own standalone change (RULE-017, WI-088).

- **The rule conflict.** RULE-009 reads: "Firebase serverless on the **Spark** tier.
  Firestore = durable state; RTDB = high-frequency ephemeral; Anonymous Auth (+ optional
  Google link) = identity; static hosting …". A build with no Firebase contradicts it as
  written. Per the `RULES.md` preamble the agent must stop, flag, obtain approval, amend the
  rule in a **separate, standalone** change, and only then resume. **WI-088 is that
  amendment and must land on its own branch and its own `RULE-AMENDMENT:`-prefixed commit
  before WI-089 begins** — the same shape WI-037 and WI-065 took.
- **What the amendment should say** (drafted here, decided at WI-088's own gate): RULE-009
  describes the **hosted** deployment, which stays exactly as it is and remains the default
  build. A second, **local** deployment has no backend, no identity, and no network: the
  campaign is a file. Nothing about the hosted build's rules changes.
- **What a local build gives up, deliberately.** Anything whose meaning is "another person":
  multiplayer and room join, player seats beyond the single local one, presence and the
  disconnect badges, live cursors, pings, drag frames and in-progress carve strokes
  (RULE-003's whole RTDB half), shared rolls and roll readiness, GM transfer, account
  linking and the rooms list. The referee is the only actor.
- **What it keeps.** Everything that is a property of the campaign rather than of the
  session: maps and every piece of vector geometry, backgrounds, hex tiles, tokens, groups,
  profiles and templates, the encounter board, dice (RULE-013's seed model is client-side
  already, so rolls work unchanged), the log, handouts, notes and tables.
- **Rules that simply do not apply, rather than being broken.** RULE-003 (write discipline)
  and RULE-004 (security rules are tested code) govern a Firebase backend; a local build has
  neither service. RULE-011 (no login wall on the join path) and RULE-012 (the roomId is the
  capability) govern a join path that does not exist locally. None of these needs amending —
  the amendment to RULE-009 is what scopes them to the hosted build.
- **Rules that get *stronger*.** RULE-001, because the local store must pass the same
  contract suite or the mode is a fork. RULE-014, because in local mode `.vttcamp` is not an
  export format any more — it is the database, and a round-trip that loses a field loses the
  user's campaign.
