## DEC-073 — Local mode is a `LocalStore` over a `.vttcamp` file handle

**Closed 2026-08-17** — answered by the user at this batch's gate (option (a) of three).

- **Question.** IN-065 asks for the app to run with Firebase "completely circumvented". What
  backs `CampaignStore` when there is no Firebase?
- **Answer.** A second `CampaignStore` implementation — **`LocalStore`** — built on the
  existing `MemoryStore` and persisting to a single `.vttcamp` the user picks or creates in
  the lobby. Single-user. No auth, no presence, no RTDB.
- **Why this and not the alternatives.** `MemoryStore` already passes the same
  `campaign-store.contract.ts` suite `FirebaseStore` does, and
  `packages/shared/src/portability/vttcamp.ts` is already a pure, Firebase-free archive core
  with a migration-on-read path. The local backend is those two joined by a file handle plus
  a debounced write-back — the cheapest of the three by a wide margin, and the one RULE-001
  was written to make cheap. An IndexedDB store would hide the campaign inside one browser
  profile and would not answer "select a `.vttcamp` in the lobby". A bundled Firebase
  emulator would keep multiplayer but needs Java and a running node process, and is not a
  removal of the Firebase dependency at all.
- **File access.** The File System Access API (`showOpenFilePicker` / `showSaveFilePicker`)
  where it exists, which is Chromium; elsewhere the build falls back to the `.vttcamp`
  download + file-input path the app already ships in `Lobby.svelte` and
  `SessionActivity.svelte`, with saving as an explicit action rather than automatic. The
  fallback is a degraded experience, not a missing one, and must be labelled as such in the
  UI rather than failing silently.
- **Impact.** `apps/web/src/lib/firebase/client.ts` — by RULE-001 the only concrete-store
  touchpoint in the app — chooses the implementation from a build flag. The Firebase SDK
  must not be reachable from a local build's bundle at all, which is the real test of
  "circumventing Firebase as a dependency" and is a build-level assertion, not a code
  comment. `LocalStore` joins the contract suite alongside `MemoryStore` and
  `FirebaseStore`.
- **This is blocked on a rule amendment.** RULE-009 states the backend as fact. See DEC-074.
