## DEC-106 — A `SessionStart` bootstrap joins the harness, and the hook count is read per event

**Closed 2026-09-18** — agent default under the `/work-item` chain (IN-144). Notified at the
WI-142 gate; overridable there.

- **Question.** Every recent completion record says the emulator battery could not run in the
  session — so the rules, store and e2e suites are first exercised by CI, after the session that
  wrote them has ended. `firebase-tools` is a `devDependency` and Java is in the image; the
  missing step is `pnpm install` plus the emulator jars. Putting that in a hook adds a fourth
  hook to a harness `CLAUDE.md` fixes at three (DEC-016, superseded in part by DEC-029).
- **Answer.** **Add it, as a `SessionStart` hook**, and read the count **per event**: three
  `PreToolUse` guards, one `SessionStart` bootstrap, none added on either event without a work
  item and a `DECISIONS.md` entry. This entry is the `SessionStart` event's first.
- **Why the count clause survives being read this way.** What DEC-016 fixed was the number of
  *guards* — things that deny a tool call — because each one is a rule the agent cannot see
  until it trips. A bootstrap denies nothing and changes no decision; it makes a command that
  should already work, work. Counting it against the guard budget would price it as a
  restriction, which it is not.
- **Why not a documented manual step.** It exists — README carries the install and the proxy
  trap — and the evidence is that it is not run: a dozen consecutive completion records say the
  battery did not run. A step that is skipped every time is not a step.
- **Why not have it run the suite too.** What to verify and when is the session's decision and
  the session's allocation (SPEC-035 §5). A hook that spends ten minutes of emulator time
  before the agent has read the work item is a cost imposed on every session, including the
  docs-only ones.
- **Impact.** `.claude/settings.json` gains a `SessionStart` entry and `.claude/hooks/` a
  script; `CLAUDE.md`'s harness paragraph is updated in the same change to enumerate it. The
  hook is best-effort and never edits a tracked file, so its worst failure is a session that is
  no better off than today's.
- **Overridable**: yes, at the WI-142 gate.
