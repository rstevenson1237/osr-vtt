## DEC-120 — What goes in `PLAN.md`'s Effort column, and how is it assigned?

**Closed 2026-09-23** — **agent default** under `/work-item` (IN-196), surfaced at WI-196's
gate. The direction — effort levels replace sizes — is the user's; the assignment heuristic
below is the agent's.

- **Question.** The column holds `XS / S / M / L`, which no session can be set to. What
  replaces it, and by what rule is each row assigned?
- **Answer.** The allowed values are Claude's effort levels — `low`, `medium`, `high`,
  `xhigh`, `max` — or `—` where the model takes none (Haiku 4.5). Effort is **advisory**, a
  guide beside the binding model target (SPEC-035 §4 is unchanged). Assigned by how hard the
  item is to *reason about*, not by its size:
  - `—` — `haiku` rows.
  - `low` — a bounded follow-up with little reasoning (turning playtest notes into intake).
  - `medium` — ordinary `sonnet` work: a Simple UI or copy change, a measurement.
  - `high` — any Deceptive item, a contract or identical-outputs refactor, an `opus` schema /
    migration / rules item, or an investigation whose output is a design.
  - `xhigh` — a long-horizon item (large, multi-slice, or schema + rules + contract in one).
  - `max` — only when a gate names it.
  - A batch runs at the highest effort among its rows.
- **Impact.** `PLAN.md` §2 only; completed rows in `PLAN-COMPLETED.md` keep what they
  recorded. Docs only.
- **Alternatives.** Map sizes one-for-one (XS→`low` … L→`xhigh`) — rejected: WI-170 is `L`
  but mechanical, WI-186 is `S` but subtle. Keep Size beside a new Effort column — rejected
  by the user: every open item is already scheduled. Make effort binding like the model —
  not taken: the user asked for a guide.
