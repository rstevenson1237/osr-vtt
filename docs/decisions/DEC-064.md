## DEC-064 — Edit/View becomes one binary button, and reverses WI-053's default to View

**This entry names and supersedes WI-053's stated default**, per `CLAUDE.md`'s rule that a
reversal must find the original entry and supersede it rather than silently overwrite it.
`README.md`'s Edit/View soft-lock paragraph (IN-031, WI-053) states: "`MapToolController
.mapMode` (`'edit' | 'view'`)... Defaults to `'edit'`, unchanged from every prior session's
behaviour." This entry changes that default going forward; WI-053's original reasoning for
building the toggle at all (a soft lock against a stray click starting a carve gesture) is
untouched.

- **Question.** IN-058 asks that Edit and View become one binary button instead of two, and
  that a freshly joined session default to View rather than Edit.
- **Recommendation.** Do both. The button merge is mechanical — one `<button>` with
  `aria-pressed` toggling between the two labels/states, replacing the two-button
  `map-mode-toggle` group in `MapToolbar.svelte`. The default flip is the substantive part:
  every seat now lands in View on session join and opts into Edit deliberately, which is a
  safer default for a room whose players are not all mid-edit, and matches the direction
  DEC-001 already pushes (drawing stays open to everyone, but nothing should be *armed* by
  default).
- **Impact.** Per-viewer client state only — `MapToolController.mapMode` is unchanged as a
  concept, only its `$state` initial value moves from `'edit'` to `'view'`. Not a resolution
  of DEC-001: map drawing stays open to every room member: this only changes what a fresh
  tab starts pointed at. `map-draw-feedback.spec.ts` (`map-mode-view` / `map-mode-edit`
  testids) and any e2e spec that assumes edit-tools are immediately clickable on load need
  an explicit `map-mode-edit` click added at the top, in the same PR.
- **Alternatives.** (a) Merge the button but keep the Edit default — no reversal, no
  decision entry, schedulable as a Simple item; declined because the default flip was
  explicitly requested. (b) Default View for players but Edit for the referee — declined:
  it would make a per-viewer client latch depend on role, which DEC-001 deliberately avoided
  when it kept the toolbar open to all.
- **Answer.** User, 2026-08-11 — default View, on one binary button, as recommended.
