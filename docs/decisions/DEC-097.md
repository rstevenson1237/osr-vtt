# DEC-097 — Does an open Call for Initiative stop other rolls?

> **Superseded in part by DEC-115 (user, 2026-09-23):** the referee is exempt from the block, and a referee-only Resolve now joins Cancel. Players' controls stay blocked as below.

- **Question.** IN-132, and the project owner's fourth point: "there should be one clear
  workflow once initiative has been entered — play has stopped until this is resolved." Today
  only **actor-bound** controls divert into staging (`rollOrStage`): a card's die button, a
  profile roll shortcut. The plain Roll-sheet dice, macros and the referee's hidden rolls all
  still publish an ordinary `Roll` mid-call. So a call is a soft state that some controls
  observe and others ignore.

  **(a) Keep rolling normally** — the call banner communicates the stop, nothing is disabled.
  **(b) Block unrelated rolls** until the call resolves. **(c) Warn but allow** — the roll
  lands, flagged as having happened during a call.

- **Recommendation.** The agent recommended **(a)** on the grounds that (b) also catches the
  referee's own mid-call adjudication. **The user chose (b)**, which is the literal reading of
  their own requirement, and it is recorded as their pick rather than as an agent default.

- **Impact.** While `sharedRoll.kind === 'initiative' && status === 'staging'`, every die
  control that is **not** this call's staging path is disabled and says why. That reaches the
  Roll sheet, the dice tray, macros, and the referee's `roll-button`/`roll-hidden-button` — the
  referee is **not** exempt, per the answer.

  **This forces a Cancel path, and that is the load-bearing consequence.** `SharedRollStatus` is
  `'staging' | 'resolved'` — there is no cancel — and `combat-roll-initiative` is disabled while
  `readyCount === 0`. So a call opened by mistake with nobody staged would, under (b), disable
  every die in the room **with no way out**. The work item therefore ships a referee-only
  **Cancel call** that returns the room to a rollable state. It sets the existing staging doc to
  `resolved` **without writing a `Roll`** and without touching the tracker, so no new status
  value enters the schema, nothing is migrated, and no `Roll` doc records a roll that never
  happened.

  `rollOrStage`'s existing divert is unchanged — this is a gate around everything else, not a
  replacement for it.

- **Alternatives.** **(a)** is the smallest change and the one the agent advised; it makes the
  stop a matter of attention rather than of enforcement, and it was not chosen. **(c)** costs a
  flag on the `Roll` document, which turns a UI question into a stored-schema one (RULE-007) for
  a warning nobody acts on; not chosen.

  Considered and explicitly **not** taken: exempting the referee. It would have preserved
  mid-call adjudication, but the answer was given knowing that cost, and a referee who needs an
  unrelated roll can cancel the call — which is why Cancel is in scope rather than optional.

- **Answer.** **(b)** — block unrelated rolls until the call resolves, referee included (user,
  2026-09-15, against the agent's recommendation of (a), with the trade-off stated). The Cancel
  path is an agent default under Default-and-notify, surfaced at the gate: it is the minimum
  that makes (b) safe. Specified as **SPEC-050 §3**, scheduled as **WI-136**.
