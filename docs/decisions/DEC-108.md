## DEC-108 — Undo is one stack per client, cleared when the viewed map changes

**Closed 2026-09-23** — answered by the user under `/work-item` (IN-166, IN-184).

- **Question.** Undo covers floor, fog, wall and door edits but not object deletes, token moves
  or group changes; the stack lives in `VectorMapView` and is discarded on a map switch
  (`{#key}` remount); the Keys (map-room) sheet keeps its own second stack
  (`RoomsPanel.svelte`). What should Ctrl+Z cover, and for how long?
- **Answer.** **One undo stack per client**, owned outside `VectorMapView`, covering map
  geometry, object deletes, token moves and group changes, and the Keys sheet's edits — and
  **cleared whenever the viewed map changes** (user, 2026-09-23). Undo only ever reverses the
  client's own actions.
- **Why.** Ctrl+Z should undo the last thing you did, wherever on the map you did it. Clearing
  on map change keeps every entry about the map on screen, so an undo never reaches a map the
  user cannot see.
- **Impact.** SPEC-037's statement that deletes are not undoable, and README → "The selection
  model", change. `RoomsPanel`'s local stack is folded in. Multiplayer: undo restores the
  entry's `from` state, last-writer-wins, as every other write.
- **Alternatives.** A room-wide stack surviving map switches (with switch-then-undo, or silent
  apply) was offered and declined; so were a per-map stack and a deletes-only step.
