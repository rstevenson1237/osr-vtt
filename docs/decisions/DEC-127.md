## DEC-127 — What does a store update method do when its document is gone?

**Closed 2026-10-06** — answered by the user under `/work-item` (IN-226).

- **Question.** DEC-123 settled this for the three background patch methods only. Across
  the rest of `CampaignStore`, `MemoryStore`/`LocalStore` silently skip a patch to a
  missing document (`patchDoc`'s `if (!cur) return`), while `FirebaseStore`'s bare
  `updateDoc`s (≈40 sites: tokens, maps, player seats, groups, `gmPrivate`, shared-roll
  meta, the room doc) reject with `not-found`. Realistic case: GM2 deletes a token while
  GM1 drags it, or GM1 undoes a move of a token since deleted. `moveTokens` and
  `transferGM` are batched, so in Firestore one missing doc fails the whole write, while
  `MemoryStore` applies the rest. The contract suite asserts none of it (RULE-001).
- **Recommendation.** **(a)** Extend DEC-123 to the whole store. Every single-document
  patch method resolves as a no-op when its document is missing, in every store;
  `FirebaseStore` routes them through one helper that swallows only `not-found`.
  `moveTokens` moves the tokens that exist and skips the rest (`FirebaseStore` falls back
  to per-token writes only when the batch hits `not-found`). `transferGM` stays
  all-or-nothing and **rejects** in every store if the room or either seat is missing,
  since a half-applied GM handover is worse than an error. Methods that already throw on a
  missing room (`ensureActiveMap`, `migrateRoomCollections`, `createBattleMap`) are
  unchanged. The contract suite asserts each method against all three stores.
- **Impact.** A stated guarantee on every `CampaignStore` update method (RULE-001); no
  schema, rules or RULE change. `MemoryStore` changes only for `transferGM`.
- **Alternatives.** (b) Reject everywhere: `MemoryStore` throws too, and every caller,
  many fire-and-forget (`void store.updateGroup(…)`), needs a catch. (c) Only the
  race-prone documents (tokens, maps, groups) get the no-op; the rest stay divergent and
  documented per method: smaller, but the contract stays split.
- **Answer.** **(a) Quiet no-op** (user, 2026-10-06). SPEC-061; scheduled as WI-219.
