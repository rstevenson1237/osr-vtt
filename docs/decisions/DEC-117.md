## DEC-117 — `CampaignStore` splits by domain; the contract file still runs every suite

**Closed 2026-09-23** — answered by the user under `/work-item` (IN-174).

- **Question.** ~150 methods on one interface, and one 3,318-line contract that every feature
  runs whole. Split it — and does RULE-001's "the shared contract suite
  (`campaign-store.contract.ts`)" then need amending?
- **Answer.** **Split, no rule amendment** (user, 2026-09-23). Per-domain interfaces —
  `RoomStore`, `MapStore`, `EncounterStore`, `DiceStore`, `PresenceStore`, `CollabStore` — are
  composed into `CampaignStore`, so no caller changes. The contract splits into per-domain
  files that **`campaign-store.contract.ts` imports and runs**, so a new method still lands in
  the shared contract suite and still passes against all three stores — RULE-001 as written.
  A focused run may target one domain's file.
- **Impact.** Interface reorganisation only: no method's signature or guarantee changes.
  Sequenced after WI-184, whose `collectionOf` primitive makes the split mechanical.
- **Alternatives.** The same split with a standalone RULE-001 amendment ("suites"); postponing.
