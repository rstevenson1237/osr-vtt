## DEC-110 — The hosted build uses Firestore's persistent, multi-tab offline cache

**Closed 2026-09-23** — answered by the user under `/work-item` (IN-169).

- **Question.** No `persistentLocalCache` is configured, so a dropped connection blanks live
  data. Should the hosted build cache Firestore locally, and how?
- **Answer.** **Yes: `persistentLocalCache` with `persistentMultipleTabManager`**, configured
  where the Firestore instance is created (`packages/shared/src/firebase-config.ts`), falling
  back silently to the memory cache where IndexedDB is unavailable (user, 2026-09-23).
- **Impact.** A subscriber may now receive a cached snapshot before the server's; snapshot
  metadata (`fromCache`) is available to the shell for IN-168's banner, which reads
  "Offline — changes will sync" while writes are pending. Offline writes queue and flush on
  reconnect — still one settled write each (RULE-003). **Hosted build only**: the local build
  has no Firestore (RULE-009) and is unaffected. No store method or rule changes.
- **Alternatives.** A single-tab cache (a second tab gets memory only), and no cache at all
  with IN-168's banner alone.
