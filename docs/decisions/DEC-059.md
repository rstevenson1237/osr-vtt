## DEC-059 — A coarse pointer gets a target, not a gesture

- **Question.** SPEC-033 §4 says every hover-only affordance gets a coarse-pointer
  equivalent or is recorded as desktop-only, but it deliberately leaves the room-label
  tooltip's trigger undecided — "deciding this is the substance of the work item". The
  difficulty is real: `VectorMapView` binds one-finger tap and one-finger drag to the
  active tool (`wireStagePointerEvents` → `onPointerDown`/`onPointerMove`) and two fingers
  to pan/pinch (`map/pan-zoom.ts`, which raises `gestureActive` and suppresses the tool),
  so **every touch gesture on that canvas is already spoken for**. A tooltip trigger has
  to take one of them away from a tool, or not be a gesture at all. The same question,
  less sharply, hangs over the Select tool's handle highlight.
- **Recommendation.** One rule, applied to all three affordances: **a coarse pointer never
  gets a gesture. It gets a visible target it can tap, or a target big enough to hit.**
  - **Room-label tooltip → a tap target.** On a coarse pointer, a `MapRoom` whose players'
    notes are non-empty renders a small **note dot** pinned to its label cell. A
    `pointerdown` inside the dot is consumed before the tool dispatch — the pattern
    `handleCollabPointerDown` already establishes at the top of the stage handler — and
    pins the tooltip open for that room. The dot is the whole trigger: no long-press, no
    two-finger tap, no tool suppression anywhere else on the canvas.
  - **Select-tool handle highlight → desktop-only, and the equivalent is size.** The
    highlight is pre-aim feedback for a grab; touch has no pre-aim phase, and a fingertip
    covers what the highlight would show. It is recorded desktop-only under §4's own
    carve-out. What touch gets instead is the ability to hit the handle: the canvas pick
    radius becomes `PICK_PX` — **9px fine, 22px coarse** — and vertex handles render at
    their enlarged radius unconditionally on a coarse pointer, so the target you aim at is
    the size you can actually hit.
  - **Plain `:hover` → `@media (hover: hover)`.** 23 rules across 17 files, wrapped, so iOS
    stops latching a lit state after a tap. Mechanical, and the only mechanical part.

  `isCoarsePointer` reaches the map as a **prop from `RoomShell`**, which already owns the
  single `createShellMedia()` instance and already derives `isNarrow` from it.

- **Impact.** Five consequences worth stating.

  First, **no tool loses a gesture.** The alternative everyone reaches for first —
  long-press — has to cancel the tool's action on release, because today a press-and-hold
  that ends without movement _is_ a tap: it places a symbol, places a label, drops a carve
  dot, commits a click-to-start point. Long-press would therefore change what touch means
  for every tool on the canvas in order to serve one read-only affordance. The note dot
  changes what a tap means only inside a ~22px dot the user can simply not tap.

  Second, **the dot is discoverable in a way the hover never was.** On desktop today the
  only way to learn a room has notes is to sweep the pointer over its label and see what
  happens. The dot advertises it. That makes the coarse-pointer path better than the fine
  one on this specific point, which is an argument for showing the dot on desktop too —
  deliberately **not** taken here, because it changes shipped desktop rendering for a
  reason §4 does not ask for. It is a fair intake item later.

  Third, **`PICK_PX` deliberately reaches past the affordance §4 names.** The Select tool's
  handle picks are two of six `latticeThreshold(9)` sites; the others are the door click and
  the object picks. Widening only the two named ones leaves the canvas with two pick radii
  and no rule saying which applies where. One radius is the coherent answer, and it is the
  canvas analogue of DEC-054's `--hit`: the Pixi stage is a bitmap, so a CSS token cannot
  reach it and the 44px coarse floor has to be re-expressed in lattice units. The cost is
  that a coarse pointer's picks get looser everywhere on the map at once, including for
  doors — intended, but it is a behaviour change on touch beyond §4's letter, and it is
  named here rather than discovered in the diff.

  Fourth, **the fine-pointer path is untouched.** No dot renders, the hover tooltip works
  exactly as it does today, `PICK_PX` evaluates to the same 9, and every wrapped `:hover`
  rule still matches. A mouse-driven desktop is pixel-identical, and `map-label-tooltip`
  keeps its testid and its three existing assertions in `map-draw-feedback.spec.ts`
  (RULE-005).

  Fifth, **the dot is drawn in Pixi, so it is invisible to Playwright** unless it is
  mirrored. It goes in `VectorMapView`'s `vf-readouts` block, the established way this
  component makes bitmap state assertable, as a new per-room testid alongside
  `maproom-name-*` / `maproom-key-*`. Adding a testid is not a RULE-005 event.

- **Alternatives.** (a) **Long-press on the label** — the conventional touch idiom, and
  the reason it loses is above: it can only be built by taking the tap-release away from
  every tool. (b) **Two-finger tap** — no tool collision, since two fingers already mean
  "not the tool", but it races the pan/pinch recogniser on the frame where the second
  finger lands, and nothing about the map advertises it; an undiscoverable gesture is not
  an equivalent. (c) **Record the tooltip desktop-only** — permitted by §4's letter, and
  cheap, since touch can still reach the same notes through Select → Object → the Room
  quick sheet. Rejected on §4's spirit: that path is a tool switch and two taps mid-play to
  replace what a mouse gets by resting on the label. (d) **Draw every edge handle
  unconditionally on a coarse pointer**, which is the answer §4 itself guesses at — it
  re-outlines the entire map, since `edgeHandles` returns every edge of every region, wall
  and door. Size, not overlay. (e) **Widen only the Select handle picks** rather than
  introducing `PICK_PX` — strictly narrower and strictly in-scope, at the cost of the
  incoherence in the third point above.
- **Answer.** Agent default (Default-and-notify), surfaced in WI-063's approval gate.
  Reversible in three independent pieces: the dot and its consumed `pointerdown`, the
  `PICK_PX` constant, and the `@media (hover: hover)` wrapping are separable changes with
  no shared state.
