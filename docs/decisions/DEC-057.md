## DEC-057 — The `PLAN.md` model target binds the execution session

**Closed 2026-08-07** — agent default under Default-and-notify, surfaced in WI-069's
completion summary. Reversible in one paragraph of `CLAUDE.md`.

- **Question.** Every work item has recorded a model target (`opus` / `sonnet` / `haiku`)
  since WI-044, and nothing has ever consulted it — sessions run on whatever the user
  happens to be in. Is the column advisory or binding?
- **Recommendation.** **Binding**, with `sonnet` as the execution default. The heavier
  line consumes the monthly allocation several times faster for identical output on the
  kind of work most items describe.
- **Impact.** This is the largest single saving available and it costs no doc churn. It
  changes how a session starts, not what it produces. The risk is a genuinely
  architectural item running too light; `/execute-wi` therefore says to **stop and ask**
  when running lighter than the target, and merely to note it when running heavier.
- **Alternatives.** (a) Leave it advisory — that is the status quo, and the status quo is
  what the allocation is being spent on. (b) Drop the column as decoration — throws away
  a judgement already made at planning time, when the cost of making it is lowest.
- **Answer.** Binding. `opus` for schema, migration, render-pass, auth and
  security-rules work and for planning; `sonnet` the execution default; `haiku` for
  mechanical bounded items. Recorded in `CLAUDE.md` → Sessions and SPEC-035 §4.
