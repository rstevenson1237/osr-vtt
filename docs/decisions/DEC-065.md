## DEC-065 — The v13→v14 migration is pinned to a frozen literal, decoupled from the live default

- **Question.** IN-056 asks that `DEFAULT_ENCOUNTER_TEMPLATE` (Difficulty/Danger/Clock)
  change to just an Initiative field. But `migrations/index.ts`'s v13→v14 step backfills an
  un-migrated room's `encounterTemplate` from that exact constant, on the stated theory that
  it "hands an old room the widgets it already had." Changing the constant would silently
  change what that migration produces for a room migrating today, years after v14 shipped —
  which is not what "the widgets it already had" means.
- **Recommendation.** Freeze the migration's input. Add a `LEGACY_ENCOUNTER_TEMPLATE_V14`
  constant, a literal copy of today's `DEFAULT_ENCOUNTER_TEMPLATE` value, local to
  `migrations/index.ts`, and point the v13→v14 step at it instead of at the live default.
  `DEFAULT_ENCOUNTER_TEMPLATE` itself then becomes free to change for what a freshly created
  room seeds, per RULE-007's migration-timestamp discipline (the migration seeds what a v14
  room genuinely had, not today's opinion of what one should have).
- **Impact.** One new frozen constant, one migration step re-pointed at it — no schema
  version bump, since the *stored shape* of `encounterTemplate` doesn't change, only which
  value seeds a fresh room versus an old one being migrated. `DEFAULT_ENCOUNTER_TEMPLATE`'s
  doc comment needs updating to stop citing the migration as a second consumer.
- **Alternatives.** (a) Leave the migration reading the live default and accept that it now
  produces Initiative-only for a room migrating today — declined, it contradicts the
  migration's own stated purpose and RULE-007's backfill discipline. (b) Bump the schema and
  add a fresh v22→v23 (or whichever version lands) migration step specifically for the
  encounter-template default change — unnecessary, since no room's *stored* field is being
  touched, only the seed value for new rooms.
- **Answer.** User, 2026-08-11 — no objection; proceeds as recommended, folded into WI-074.
