## DEC-061 — Free snap attracts to an existing vertex, within the existing pick radius

- **Question.** IN-050 asks that Free snap also snap to an existing vertex, "to make it
  easier to connect existing free snap work." `snapPoint(p, mode)` documents Free as pure
  identity (`map/vector/snap.ts`). Attracting to geometry is a new behaviour for that mode —
  what triggers it, and which tools does it apply to?
- **Recommendation.** A pointer within a pick-radius threshold of an existing vertex snaps
  to that vertex exactly; outside the threshold, Free stays identity. Reuse the existing
  hit-test constants (`PICK_PX_FINE` / `PICK_PX_COARSE`, gated by `pickPx(isCoarsePointer)`
  in `vector-tools.ts`) rather than inventing a new threshold, so the attraction feels like
  the same precision the Select lasso and object-picking already use, and scales with
  pointer coarseness the same way. Applies to the tools whose gesture already places
  vertices on vertices under snap — Wall, Door, Polygon — plus the new lasso's vertex
  handles; it does **not** apply to the cell-anchored tools (Room, Corridor, N-gon, Carve,
  Path), whose anchor is a cell, not a vertex, per SPEC-028 §2's standing constraint.
- **Impact.** `snapPoint` gains an optional third parameter (existing vertex list) so it
  stays a pure function for every caller that doesn't pass one; only the vertex-snapped
  tools' point collectors are touched. New SPEC-028 §12 documents this as free-snap's one
  exception to "identity." No schema change — this is purely how a raw pointer position is
  interpreted before it becomes a stored point.
- **Alternatives.** (a) A fixed lattice-unit threshold instead of the pixel-based pick radius
  — simpler, but would not scale with zoom or pointer coarseness the way every other
  hit-test in the map already does. (b) Apply attraction to the cell-anchored tools too —
  rejected; it would contradict the SPEC-028 §2 standing constraint that those tools receive
  raw points and do their own cell-based snapping, not vertex-based.
- **Answer.** User, 2026-08-11 — no objection raised to the recommendation; proceeds as
  written.
