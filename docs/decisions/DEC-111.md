## DEC-111 — Collection backfills share one ledger: a version stamp on the room doc

**Closed 2026-09-23** — answered by the user under `/work-item` (IN-176).

- **Question.** `ensureActiveMap`, `migrateMapBackgrounds` and `migrateTokenLetters` each read
  a whole subcollection on every GM room open, forever, because an absent field is invisible
  from a room-doc update. How should collection backfills be versioned?
- **Answer.** (user, 2026-09-23) A new optional **`Room.collectionsMigratedTo: number`**
  (next schema version). **Absent means "never walked"** — no backfill is needed. One new store
  method, **`migrateRoomCollections(roomId)`**, runs every collection step above the stamp
  and then sets it; the three per-open effects in `RoomShell` become one call that is a no-op
  when the stamp is current. A `.vttcamp` import writes the current version (the archive is
  migrated to current on import).
- **Impact.** RULE-001 (contract suite for the new method against all three stores), RULE-007
  (migration + migration test + `.vttcamp` round-trip test). GM-written, like the other room
  fields. A future collection backfill adds a step, not an effect.
- **Alternatives.** A stamp per collection — finer-grained, more fields, no present need.
