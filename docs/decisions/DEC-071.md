## DEC-071 — Corner handles preserve the native ratio; edge handles change it. Supersedes SPEC-038 §3

**Closed 2026-08-17** — answered by the user (IN-063, stated as "change from previous
behavior"). This entry exists to **name and supersede** the clause it reverses, per the
Shape-A reversal rule in `CLAUDE.md`; SPEC-038 §3 is annotated in place, never deleted
(RULE-019).

- **What is reversed.** SPEC-038 §3 states: "A resize **always** preserves the image's
  native aspect ratio — dragging one resize handle scales both `w` and `h` together from
  the image's own width:height, never producing a stretched image. There is exactly one
  resize handle interaction, not independent width/height handles." Shipped in WI-081.
- **What replaces it.** Eight handles. The four **corners** scale `w` and `h` together from
  the image's native ratio — the old behaviour, now one of two. The four **edges** move a
  single dimension: left/right change `w` alone, top/bottom change `h` alone, and the image
  stretches. SPEC-039 §3 is the successor clause.
- **Why the original rule was written, and why it goes.** "Never stretched" was a guard
  against a referee accidentally distorting map art, and it is a good default — which is
  why the corners keep it. But a scanned or photographed floor plan is very often *already*
  distorted relative to the grid it must line up with, and with only a ratio-locked handle
  there is no gesture in the app that can correct it. The ratio lock was protecting the
  common case by making the corrective case impossible.
- **Impact.** `resizeBackground` in `map/background-transform.ts` is replaced by a
  handle-parameterised function, and `backgroundHitTest` grows from one handle to eight —
  both pure and unit-tested, so the reversal is provable without a Playwright drag. The
  stored shape is untouched: `x, y, w, h` already admit any rect, so **no migration**. The
  `MIN_BACKGROUND_CELLS` clamp and the no-inversion rule apply per-axis rather than to the
  single driving edge.
- **What is *not* reversed.** SPEC-038 §§1–2 (the subcollection, the per-sprite render) and
  §4 (the alignment overlay) stand unchanged, and §4 becomes more load-bearing: the overlay
  is now the only way to see whether a freely-stretched image matches the grid.
