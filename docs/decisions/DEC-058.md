## DEC-058 — CI is checked once, not polled; automerge is declined

**Closed 2026-08-07** — the automerge half was **decided by the user** (2026-08-07,
"No automerge"); the poll-loop half is an agent default under Default-and-notify.

- **Question.** Step 8 polled CI every 30 seconds for up to 20 attempts. Each poll is a
  turn, and each turn re-sends the entire session context, so learning one boolean cost up
  to twenty full-context turns — frequently more than the implementation it was checking.
  The audit that prompted WI-069 proposed replacing the loop with GitHub automerge
  (`gh pr merge --auto --squash`).
- **Recommendation.** **Drop the loop; decline the automerge.** The loop is the expense;
  the merge is not. Automerge would additionally land agent-authored diffs on a protected
  `main` with no human reading them — the step-5 gate approves a _plan_, not a diff, so it
  would leave the diff unreviewed by anyone.
- **Impact.** `/execute-wi` now checks CI once, a couple of minutes after pushing, and
  ends the turn if the run is still going — the user or a later session picks it up. A red
  build still gets exactly one mechanical re-push, then stops and reports. Nothing about
  branch protection changed, and `settings.json` gained no `gh pr merge` permission.
  Trade-off accepted: a green PR can now sit unnoticed until someone looks.
- **Alternatives.** (a) Automerge as proposed — declined by the user. (b) Automerge
  gated on an approving review — still requires the human, so it saves nothing the single
  check does not. (c) Keep the loop but lengthen the interval — fewer turns, still a loop,
  still quadratic in context.
- **Answer.** Single check, no loop, no automerge. Recorded in
  `.claude/commands/execute-wi.md` step 8 and SPEC-035 §5.
