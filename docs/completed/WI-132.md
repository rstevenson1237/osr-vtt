## WI-132 — A token snaps to the hex it is dropped on

**Status: Completed 2026-09-15**

SPEC-047 §15. The character quick sheet's `token-snap-mode` control and `SnapMode`/
`snapTokenPosition` (`packages/shared/src/map/snap.ts`) previously offered and understood
only Cell/Half/Free, all three of which quantize against a square lattice a hex map does not
declare (RULE-006). A hex map now offers Hex and Free, and Hex resolves through
`pixelToAxial`/`axialToPixel` — the same render boundary a hex map already crosses once —
instead of dividing by `cellSize`. Every token size centres on the hex; a larger token
overflows it and that is correct (DEC-094, user).

### Changes made

- **`packages/shared/src/map/snap.ts`** — `SnapMode` gains `'hex'`. `snapTokenPosition` takes
  an optional `hexSize` and, under `'hex'`, resolves `pixelToAxial(pos, hexSize)` then back
  through `axialToPixel`, ignoring `size` entirely (no size-aware rule to port — a hex lattice
  has no point where four hexes meet). `snapModeFromModifiers` now ignores `Alt` when `base`
  is `'hex'` (there is no half-grid to force on a hex map) while `Alt+Shift` still forces
  `'free'` either way.
- **`packages/shared/src/map/snap.test.ts`** — new cases: hex mode resolves to the hex centre
  under the pointer and round-trips through `pixelToAxial`; a 1× and a 3× token land on the
  same centre; `Alt` under a `'hex'` base is a no-op, `Alt+Shift` still forces `'free'`.
- **`apps/web/src/lib/shell/map-tool-controller.svelte.ts`** — `setHexMap` now also switches
  `tokenSnap` to `'hex'` on entering a hex map and back to `'cell'` on leaving, mirroring the
  existing `setSnapMode('hex')`/`setSnapMode('full')` pairing (same reason: a `<select>` whose
  value matches no offered option renders blank).
- **`apps/web/src/lib/components/CharacterDock.svelte`** — the `token-snap-mode` select's
  options are now `$derived` on `mapCtrl.isHexMap`: Cell/Half/Free on a square map, Hex/Free on
  a hex map — exactly the pattern `MapToolbar`'s tool-snap selector already uses (§3, DEC-080).
  `SnapMode` newly imported for the option-list type.
- **`apps/web/src/lib/components/VectorMapView.svelte`** — both `snapTokenPosition` call sites
  (sheet-to-map drop, and drag-release on the map) now pass `hexGrid?.size` as the new
  `hexSize` argument. `hexGrid` was already derived here (`isHexMap(map) ? map.hex ?? null :
  null`); nothing new is read from the map doc.
- **Docs** — `docs/spec/SPEC-047.md` §15 (no change needed, already describes the landed
  shape), `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md`.

### Visible behavior changes

- **A hex map's quick sheet offers Hex and Free** for token snap, instead of Cell/Half/Free.
  Entering a hex map switches the control to Hex automatically (mirroring the map toolbar's
  own snap-mode switch); leaving returns it to Cell.
- **Dropping or dragging a token on a hex map under Hex snap lands on the centre of the hex
  under the pointer**, for every token size — a 2× or 3× token now visibly overflows its hex
  rather than trying to straddle a corner that doesn't exist on a hex lattice.
- Square-map token snapping (Cell/Half/Free) is unchanged.

### How to verify

1. `pnpm verify` — lint, typecheck, unit. Green.
2. `packages/shared/src/map/snap.test.ts` — new hex-mode and modifier-override cases pass.
3. Open a hex-crawl map: the quick sheet's Snap control reads "Hex" and offers only Hex/Free.
   Drop a token (any size) near a hex's edge — it lands centred on that hex.
4. Switch to a square map: the control reverts to Cell/Half/Free and behaves as before.
5. `dice-overlay.spec.ts` (touches `token-snap-mode` on a square map) — unaffected, since the
   square option set and default are unchanged; runs in CI's `test-emulators` job (see
   Deviations).

### Deviations

- **The emulator battery could not be run in this session.** `pnpm verify` (lint + typecheck +
  unit) is green locally; `pnpm verify:all` and `dice-overlay.spec.ts` need the Firebase
  emulators, and the `firebase` CLI is not installed in this sandbox (`spawn firebase ENOENT`,
  same gap WI-130/WI-131 hit). CI's `test-emulators` job runs the full suite on the PR.
- **`setHexMap` also drives `tokenSnap`, beyond the file the spec named.** Not called out in
  §15 explicitly, but required to unblock it: without switching `tokenSnap` on grid-kind
  transition the same way `snapMode` already is, the quick sheet's `<select>` would render
  blank on a hex map (its bound value, `'cell'`, matches none of the offered `'hex'`/`'free'`
  options) — the same failure mode `setHexMap`'s existing `snapMode` handling exists to avoid.
  Logged here per RULE-015's exception rather than as a separate item, since it is the same
  control this work item's gate names.
- No `data-testid` moved, renamed or removed (RULE-005); `token-snap-mode` keeps its id and
  place, per the spec. No store method added or changed (RULE-001). No stored field changed
  and no migration is owed (RULE-007) — `Token.pos` stays world pixels under every mode.
