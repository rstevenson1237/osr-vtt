# WI-137 — The tracker reads a seat's `displayName` and a creature's letter, never an id

**Spec:** SPEC-050 §4 · **From:** IN-133 · **Agent:** `claude-code` · **Model:** `sonnet` ·
**Effort:** S · **Closed:** 2026-09-17

## Changes made

- `apps/web/src/lib/encounter/labels.ts` — `tokenLabel` now takes an optional `players:
  PlayerSeat[]` and, when the token carries an `ownerSeatId`, resolves that seat's
  `displayName` before falling back to `Token.name`. The old id-fragment/imageRef fallback
  chain now checks `Token.letter` (SPEC-048) first, reading it as a creature designation.
  `refLabel` grew the same `players` parameter and threads it through to `tokenLabel`.
- `apps/web/src/lib/components/CombatTracker.svelte` — both `refLabel` call sites (the order
  list and the "is up" line) now pass the component's existing `players` prop.
- `apps/web/src/lib/components/TurnStrip.svelte` — added a `players?: PlayerSeat[]` prop
  (default `[]`) and threaded it into its `refLabel` call.
- `apps/web/src/lib/components/shell/MobileTopBar.svelte` and
  `apps/web/src/lib/components/shell/SessionTab.svelte` — both already held a `players` prop
  for their own use; both now forward `{players}` to `<TurnStrip>`.
- `apps/web/src/lib/encounter/labels.test.ts` — new file; covers seat-owned-token resolution,
  the name/letter/id-fragment fallback order, and `refLabel`'s side/actor branches.

## Visible behavior changes

A player-character's row in the Encounter Board's initiative order, and the "X is up" readout
on both the Board and the top-bar Turn Strip, now shows the seat's display name instead of an
id fragment. An unnamed creature's row now shows its stored letter (e.g. "A") instead of an id
fragment, when it has one.

## How to verify

`pnpm verify` (lint + typecheck + unit) — green. Manually: seat a player, give their token no
`name` (the normal seat-token shape per SPEC-040 §3), call initiative in Individual mode, and
confirm the tracker row and "is up" readouts show the seat's display name. Give an unnamed
creature token a letter and confirm its row shows the letter rather than an id fragment.

## Deviations

None — the change is exactly SPEC-050 §4: no new storage, no new naming policy, just wiring
`players` into a label function that already existed and adding the one missing fallback step
(`Token.letter`).
