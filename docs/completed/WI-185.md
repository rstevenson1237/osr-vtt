# WI-185 — One migration ledger

SPEC-056 §6, DEC-111. Single unit (Deceptive). IN-176. Schema v30 → **v31**.

**Changes made**

- `packages/shared/src/types.ts` — `CURRENT_SCHEMA_VERSION` 30 → 31. `Room` gains
  optional `collectionsMigratedTo: number`: the schema version the room's sub-collections
  were last walked to. Absent means "never walked".
- `packages/shared/src/schemas.ts` — `RoomSchema` accepts `collectionsMigratedTo`
  (optional non-negative int, never defaulted, since absence is the signal).
- `packages/shared/src/migrations/index.ts` — the v30->v31 room-doc step, a deliberate
  no-op: seeding a stamp would claim a walk that never happened. New ledger:
  `COLLECTION_MIGRATION_STEPS` (`adoptFlatMaps`@11 → `backgrounds`@27 →
  `tokenLetters`@30, in run order), `pendingCollectionSteps(stamp)`,
  `collectionsNeedMigration(room)` and `runCollectionMigrations(store, roomId, stamp)`,
  which runs the pending steps sequentially through a structural slice of the store.
- `packages/shared/src/store/campaign-store.ts` — new interface method
  `migrateRoomCollections(roomId)` (RULE-001), documented. The doc comments on
  `ensureActiveMap`, `migrateMapBackgrounds` and `migrateTokenLetters` now say they run
  as ledger steps rather than as separate calls on room open. All three stay on the
  interface unchanged.
- `packages/shared/src/store/firebase-store.ts`, `memory-store.ts` — implement it: one
  raw room read, then return if the stamp is current or ahead; otherwise
  `runCollectionMigrations`, then write `collectionsMigratedTo: CURRENT_SCHEMA_VERSION`.
  The stamp is written only after every step resolves, so a walk that fails part-way is
  retried on the next open. `LocalStore` inherits the `MemoryStore` implementation.
- `packages/shared/src/portability/vttcamp.ts` — `archiveToSnapshot` stamps the imported
  room `CURRENT_SCHEMA_VERSION`. Each ledger step already has an import-side twin there
  (the flat-map adoption, `foldMapBackgrounds`/`lockLegacyBackgrounds`,
  `backfillLetterCollections`).
- `apps/web/src/lib/components/RoomShell.svelte` — the three GM effects (`ensureActiveMap`
  on a missing `activeMapId`, and the latched `migrateMapBackgrounds` and
  `migrateTokenLetters`) are replaced by one GM-gated, per-open-latched effect. It calls
  `store.migrateRoomCollections(roomId)` only when `collectionsNeedMigration(room)` is
  true.
- Tests:
  - `campaign-store.contract.ts` gains two cases, run against `MemoryStore`, `LocalStore`
    and `FirebaseStore`:
    - A never-walked room runs every step (a background is folded and locked, a token
      letter is backfilled), is stamped current, and a second call walks nothing: a legacy
      background seeded after the stamp is not folded.
    - A room imported stamped at 27 runs only the v30 letter step.
  - `migrations/index.test.ts` gains the v30->v31 no-op test and tests for
    `pendingCollectionSteps`, the step ordering, `collectionsNeedMigration` and the
    sequential order of `runCollectionMigrations`.
  - `vttcamp.test.ts`: the current-build fixture carries the stamp, so the identity
    round trip covers it. A new test checks that an unstamped or behind archive imports
    stamped current and re-exports unchanged. The pre-v11 migration exercise asserts the
    stamp too.
- `README.md` — new subsection "Collection backfills — one ledger" under "Schema
  versioning", covering the schema-version history obligation. The token-letter and
  background passages now describe their backfills as ledger steps rather than
  once-per-open calls.
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — ledger updates for the closure.

**Visible behavior changes** — none in the UI. What a referee's client does on room open
changes. A room stamped at v31 or later makes no call and no sub-collection read. A room
without a stamp (every room created before v31, and every new room until its first
referee open) is walked once, the same work the old effects did on every open, and gets
one extra room-doc write (`collectionsMigratedTo`). Imported `.vttcamp` rooms arrive
stamped. New rooms and imports are at `schemaVersion` 31.

**How to verify** — `pnpm verify` (lint, typecheck, unit, including the new migration and
`.vttcamp` tests) and `pnpm verify:all` (adds the store contract suites against the
emulators, rules and Playwright e2e). By hand: open a room as referee with an older build's
data. The room doc gains `collectionsMigratedTo: 31` after the first open, and a second
open issues no reads of `maps`, `backgrounds`, `tokens` or `profiles` from `RoomShell`.

**Deviations** — none. Two points where the spec text left room for interpretation:

- **Ordering against WI-191.** `PLAN.md` said WI-191 would run first so that its schema
  bump sat ahead of this one. WI-191 has not run yet, and this item was executed on
  explicit invocation, so WI-185 takes v31 and WI-191 takes the next version.
- **No stamp at `createRoom`.** DEC-111 names only the import as writing the stamp, and
  the contract tests rely on a fresh room being unstamped. A new room's first referee open
  therefore walks its (empty) collections once and stamps it.
