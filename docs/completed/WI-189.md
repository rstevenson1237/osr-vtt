# WI-189 — Edit/View remembered for the tab session

SPEC-057 §1, DEC-114 (supersedes DEC-064 in part). Single unit (Shape A). IN-156.

## Changes made

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `MapToolController` takes an
  optional `roomId` in its constructor. With one, `mapMode` is loaded from and persisted to
  `sessionStorage['vtt-mapmode:{roomId}']` (new private `#storageKey`/`#loadMapMode`/
  `#persistMapMode`, mirroring `ShellState`'s own `localStorage` pattern); `setMapMode`
  persists on every change. Both read and write are wrapped in `try/catch` and guard
  `typeof sessionStorage === 'undefined'`, falling back to `'view'` on any failure. With no
  `roomId` (every existing call site but `RoomShell`, and every unit test that constructs a
  bare controller), the mode behaves exactly as before — defaults to `'view'`, never
  persisted.
- `apps/web/src/lib/components/RoomShell.svelte` — `new MapToolController(roomId)`
  (`roomId` is stable for the instance, as `ShellState` already relies on; same
  `eslint-disable-next-line svelte/valid-compile` as that line).
- `apps/web/src/lib/shell/map-tool-controller.test.ts` — new `installSessionStorage()`
  in-memory stand-in (same shape as `shell-state.svelte.test.ts`'s `installStorage`), a
  test that a bare controller (no `roomId`) never persists, and a new describe block:
  persists and restores per room, a different room starts in view, and read/write failures
  both fall back to/tolerate `'view'` without throwing.
- `README.md` — the Edit/View soft-lock paragraph now describes the sessionStorage
  remember (SPEC-057 §1, DEC-114) instead of DEC-064's plain "defaults to `'view'`ˮ.

## Visible behavior changes

- Reloading the page, switching maps, or flipping the lock and back keeps whichever of
  Edit/View a referee last chose, for that room, for the rest of the browser tab's session.
- Opening the room in a new browser session (or with storage blocked/unavailable) still
  starts in `'view'`, exactly as before — the one binary `map-mode-toggle` button and its
  default are unchanged in every other respect.

## How to verify

- `pnpm verify` — lint, typecheck, unit, including the new persistence tests in
  `map-tool-controller.test.ts`.
- By hand: open a room as referee, switch to Edit, reload the page — still Edit. Open the
  same room in a different room id — starts in View. Open the room in a fresh incognito
  window (or a second tab counts as the same session storage only if it's the same tab
  reloading) — starts in View.

## Deviations

None against the gate. `MapToolController`'s constructor gained an optional parameter
(default `undefined`, matching every pre-existing bare-constructor call site and test)
rather than a required one — this keeps every other test file and call site unchanged, since
only `RoomShell` has a `roomId` to hand it. No rules change, no `data-testid` moved.
