# WI-041 — Hex crawl: per-hex notes, the hex-tile quick sheet, tool filtering

**Spec:** SPEC-030 §§4–5 · **From:** IN-011 · **Model:** `opus` ·
**Closed:** 2026-08-14

The last of the Hex Crawl series, and the one that makes the previous three
reachable. WI-038 gave a hex map its coordinate space, WI-039 drew the grid, and
WI-040 modelled and rendered what a hex carries — but nothing *set* any of it.
This is the authoring half: Select picks a hex, a sheet edits its terrain, its
contents and (new here) its note, and the note shows on hover. It also replaces
WI-039's blunt View-tools-only palette with the one a hex crawl actually keeps.

SPEC-030 goes to **Completed** with it.

## Changes made

**The note (SPEC-030 §4) — schema v26.**

- `packages/shared/src/types.ts` — `HexTile.note?: string`, and
  `CURRENT_SCHEMA_VERSION` 25 → **26**. The field doc records why it is a plain
  Firestore field rather than a `room-notes` Yjs entry like a *map-room*'s
  players' notes: that doc is keyed by map-room id and is per-**room**, not
  per-map, so it has nowhere to file a coordinate that repeats on every hex map
  in the session — and a field here rides the `.vttcamp` export, the map delete
  and the rules the rest of the tile already has.
- `packages/shared/src/schemas.ts` — `HexTileSchema.note`, optional and
  non-empty like its two siblings.
- `packages/shared/src/converters.ts` — `hexTileBody` carries `note` through.
- `packages/shared/src/migrations/index.ts` — the **v25 → v26** step. A no-op on
  the room doc for the same reason v24 → v25 was (the field lives on a
  `maps/{mapId}/hexTiles/{axialKey}` document, which `migrateRoom` never sees),
  with no document half either: absence already means "nobody wrote a note
  here", and seeding one would invent text a referee never typed. It earns the
  bump by stamping `.vttcamp` archives.

**The store (RULE-001).**

- `packages/shared/src/store/campaign-store.ts` — `setHexNote(roomId, mapId,
  hex, note | null)` joins the contract beside `setHexTerrain`/`setHexContents`,
  with the same clear-prunes-the-document guarantee.
- `packages/shared/src/store/memory-store.ts`,
  `packages/shared/src/store/firebase-store.ts` — both `patchHexTile` helpers
  take `note` as a third independent field, and the "is anything left?" test
  that decides whether the document survives now counts all three. No rules
  change: `hexTiles` is already member-or-GM write and validates no field list.

**Tool filtering (SPEC-030 §5).**

- `apps/web/src/lib/map/tool-groups.ts` — `HEX_TOOL_IDS` (Select plus the View
  tools, read off `TOOL_GROUPS` so the palette and the subset cannot drift) and
  `isHexTool`. The long comment there is the argument for why it is narrower
  than §5's wording; see **Deviations**.
- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `selectedHex`
  (an `Axial`, never a lattice `Point`), `selectedHexTile` (mirrored out of the
  map view's subscription), and the three `onSetHex*` write callbacks.
  `setHexMap` now falls back to Pan on anything outside `HEX_TOOL_IDS` rather
  than outside the view group, so Select survives; leaving a hex map, and
  `release()`, both drop the selection.
- `apps/web/src/lib/components/shell/sheets/MapToolsSheet.svelte` — passes
  `HEX_TOOL_IDS` for a hex map (`VIEW_TOOL_IDS` still for a battle map) and
  renders the hex-tile body above the palette.

**The hex-tile sheet (SPEC-030 §5).**

- `apps/web/src/lib/components/shell/HexTilePanel.svelte` (new) — the terrain
  and contents palettes read straight off `HEX_TERRAIN_CATALOG` /
  `HEX_CONTENTS_CATALOG` (minus their `unknown` entry, which is a *resolution*
  fallback and not something to author), a `MarkdownEditor` for the note
  committed **on blur** — one settled write per edit (RULE-003), not one per
  keystroke — and a "Done" button that drops the selection. Clicking the kind a
  hex already carries clears it, so erasing needs no eraser. Store-free like
  every quick-sheet body: it writes through the controller's callbacks. The
  swatch art reproduces the render boundary's tint with a CSS filter rather than
  a second tone table, so a re-coloured terrain's chip flips with its hex.

## Visible behavior changes

- **A hex crawl's palette gains the Select tool** and keeps the four View tools;
  it is otherwise unchanged (still no carve, overlay, or capture tools).
- **Clicking a hex with Select picks it**, outlining it in the selection colour;
  clicking it again deselects. Nothing else on the canvas responds to Select on
  a hex map.
- **The Map tools sheet grows a hex-tile section** while a hex crawl is on
  stage: the picked hex's coordinate, a terrain palette, a contents palette and
  a note editor — or a one-line hint when no hex is picked. Picking a terrain or
  contents kind paints the hex for every seat; picking the same kind again
  clears it; clearing everything unpaints the hex.
- **Hovering a hex that has a note shows the note**, in the same popover a room
  label's notes use.
- New rooms are created at **schema v26**; existing rooms migrate on read with
  no visible change.

## How to verify

```sh
pnpm verify        # lint + typecheck + unit
pnpm verify:all    # the above + rules/store/e2e against the emulator
```

By hand: Assets → **+ New hex crawl** → switch to it → Map. Flip the Map tools
sheet to **Edit**, pick **Select**, click a hex — the sheet's hex-tile section
names its coordinate. Click a terrain swatch, then a contents icon, then type
in the note field and click away. Hover the hex from anywhere on the canvas and
the note appears; clear all three from the sheet and the hex goes blank again.
`map-selected-hex` and `map-hex-tile-count` mirror both in the DOM.

## Deviations

1. **The palette is Select + View, not "View and overlay tools" as SPEC-030 §5
   says.** §5's stated reasoning is about carved floor, which the overlay tools
   do not touch — but that is not the test that decides. RULE-006, as amended by
   WI-037, forbids two coordinate spaces inside one map, and every overlay tool
   stores square-lattice units multiplied by `grid.cellSize`: `MapSymbol.cell`,
   `MapRoom.labelAnchor`, `Drawing.points`, a door's endpoints. A hex map's
   multiplier is `hex.size`, so a symbol or a pen stroke placed on one would sit
   in a space the map does not declare. Label is doubly out — §1 makes the
   coordinate the addressing scheme, replacing the labels a referee used to
   invent and place. `RULES.md` outranks the specs, so the spec paragraph is
   annotated in place rather than the rule bent. Giving any overlay tool an
   axial-space form is a new intake item, not this one.

   **Select was added in its place**, which §5 does not name: without it there
   is no way to pick the hex the sheet is supposed to edit, and on a hex map
   "the pointer decides what it grabs" (SPEC-037) has exactly one answer.

2. **The hex-tile sheet is the Map tools sheet's hex body, not a seventh
   `QUICK_SHEETS` entry.** §5 calls it "a new hex-tile quick sheet". A real
   entry would add a rail button and a digit shortcut that are dead on every
   square-grid map — the dead button `quickSheetsFor` exists to prevent — and
   the Map tools sheet is already the one component that knows which map is on
   stage and narrows the palette for it. So it is a contextual body of that
   sheet, above the (now very short) palette.

3. **No coarse-pointer note dot.** A room label's tooltip has one (SPEC-033 §4)
   because a finger has no hover. A hex's equivalent already exists and is
   better: a tap with Select picks the hex, and the sheet shows the note in full
   and editable. Adding a second per-hex tap target would compete with the
   selection tap on the same pixels.

4. **One in-scope edit outside the new code**: the sparseness test in both
   stores' `patchHexTile` now counts three fields rather than two. Without it a
   note-only hex would be pruned the moment it was written, so it is the field's
   own requirement rather than a side fix — but it is the one place WI-041
   changed existing behaviour instead of adding to it, so it is recorded here.
   `packages/shared/src/portability/vttcamp.test.ts` also carried a hardcoded
   `schemaVersion` of 25, which the v26 bump made stale; it moves to 26.
