# WI-206 — Firebase-strip check in CI

Batch 6 (WI-206 – WI-212), one pull request (RULE-016). IN-071. Model `sonnet`, effort medium. Spec: SPEC-042 §3.

## Changes made

- `scripts/check-local-strip.mjs` (new) — walks `apps/web/dist-local` (or argv[2]) and fails on (1) the SDK words `firebase`, `firestore`, `firebaseio`, `appspot`, `identitytoolkit` (case-insensitive) and (2) the project's real identifiers read from `.firebaserc` and `apps/web/.env.production`. The bare project id `osr-vtt` is matched only as a whole token, because the app's "report an issue" link (`github.com/<owner>/osr-vtt/issues`) legitimately carries the repository's name.
- `.github/workflows/ci.yml` — `static` gains a "Local build has no Firebase" step after the bundle-size check, wired into the existing "Fail if any step above failed" roll-up.
- `README.md` — the CI-shape paragraph, a new "Firebase-strip check" paragraph, and the stale "zero matches" note in "The build boundary".

## Visible behavior changes

None to the app. A pull request whose local build ships Firebase now fails `static`.

## How to verify

`pnpm build:local && node scripts/check-local-strip.mjs` prints `Strip check passed`. Copy `apps/web/dist-local` elsewhere, add a file containing `firestore` or `"osr-vtt"`, run the script with that directory as its argument — it exits 1 and names the file (done in this session).

## Deviations

- **Found, not fixed:** `release-local.yml`'s own grep (`osr-vtt` as a substring) matches the issue-report link in the current `dist-local`, so it would fail a release. The workflow is not a file this item changes, so this is logged as IN-221 (RULE-015) rather than fixed here.
