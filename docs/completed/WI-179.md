# WI-179 — Undo: object deletes (canvas and Keys sheet)

SPEC-056 §2.2, DEC-108. Single unit (Deceptive). IN-166, IN-184.

**Changes made**

- `apps/web/src/lib/map/vector-tools.ts` — `VectorEditorOp` gains three new kinds,
  `symbol`, `mapRoom` and `drawing` — each `{ id, from, to }` with `to: null` a delete,
  mirroring the existing `door` shape. `isNoopVectorOp`, `invertVectorOp` and
  `commitVectorOpForward` handle all three (`placeSymbol`/`removeSymbol`,
  `upsertMapRoom`/`removeMapRoom`, `writeDrawing`/`deleteDrawing`). New
  `buildObjectRemovalOp(objects, removedDoorIds, records)` — the object-selection
  counterpart to the existing `buildHandleRemovalOp` — builds one op per selected
  symbol/label/door/drawing, skipping a door already covered by a vertex-handle removal
  in the same gesture (caught both as an object and by one of its endpoints), and wraps
  more than one into a `batch`.
- `apps/web/src/lib/components/VectorMapView.svelte` — `deleteSelection` now snapshots
  the pre-delete record of every selected object (alongside the existing handle
  snapshotting), builds an object-removal op with `buildObjectRemovalOp`, and combines it
  with the existing handle-removal op into **one** `applyOp` call — one Backspace is one
  Ctrl+Z, whatever the selection mixed. The direct `store.removeSymbol` /
  `store.removeMapRoom` / `store.removeDoor` / `store.deleteDrawing` calls the canvas used
  for object deletes are gone; every canvas object delete now goes through the shared undo
  stack (`UndoController`, WI-178).
- `apps/web/src/lib/map/vector-tools.test.ts` — unit coverage: invert/no-op for the three
  new op kinds, `commitVectorOpForward` routing to the right store methods, and a
  `buildObjectRemovalOp` describe block (null on nothing selected, a lone delete is a
  plain op not a batch, a mixed selection batches with the right invert order, a door
  already removed by a handle op is skipped even alongside another object, and undo
  re-creates the object via the right store call).
- `docs/spec/SPEC-037.md` §3 — updated: object deletes are no longer described as going
  through "existing store calls" outside the undo stack; both member kinds now land as one
  combined `VectorEditorOp` per Backspace.
- `README.md` → "The selection model" — the Backspace/Delete paragraph rewritten to
  describe `buildObjectRemovalOp` alongside `buildHandleRemovalOp` and the combined single
  `applyOp` call, replacing the prior "objects are not on the undo stack" statement.

The Keys sheet's own delete (`RoomsPanel.svelte`'s `deleteRoom`) was already
undo-integrated through its separate `MapRoomOp`/`undoCtrl` path from before this item —
nothing there needed to change.

**Visible behavior changes** — Backspace/Delete on the canvas for a selected symbol, map
label, door or drawing is now undoable (Ctrl+Z re-creates it with the same id; Ctrl+Shift+Z
re-deletes it), matching how vertex/geometry deletes already worked and how the Keys
sheet's own delete already worked. A selection mixing objects and vertex handles (e.g. a
lasso catching a symbol and a wall endpoint) now undoes as a single step instead of leaving
the object deletion permanent.

**How to verify** — `pnpm verify` (lint/typecheck/unit) and `pnpm verify:all` (adds
rules/store contract suites and the full Playwright e2e suite against the emulators) both
green. Manually: as referee, place a symbol and a label on the canvas, select both (Shift or
lasso) plus an adjacent wall's endpoint, press Backspace, then Ctrl+Z once — the symbol, the
label and the wall segment all reappear together; Ctrl+Shift+Z removes them all again.

**Deviations** — none.
