## WI-148 — `RULE-AMENDMENT`: RULE-016 gains a batch lane

**Closed 2026-09-20.** Spec: — (rule). From: IN-142 / DEC-100 (answered **(b)**, user,
2026-09-18). Agent: `claude-code`, model `opus`, effort S. Standalone `RULE-AMENDMENT:`
change (RULE-017) — no implementation is bundled with it.

### Changes made

- **`RULES.md`** — RULE-016 retitled "One session, one **approved unit**" and rewritten.
  A unit is a single work item, or a **batch** of items classified Simple and approved
  together at one gate. Four binding conditions are stated: every item Simple; one gate,
  naming each item; each item keeps its own `IN-` row, `WI-` id and
  `docs/completed/WI-nnn.md`; the batch ships as one pull request with one combined
  four-section summary naming each item. Deceptive, Investigation, Unclear and
  rule-amendment items stay one per session, and nothing may be added to a batch after its
  gate. An amendment note in the RULE-006/RULE-009 style records what the rule previously
  said, DEC-100's answer, and that option (c)'s trivial lane was declined.
- **`CLAUDE.md`** — the §Sessions line becomes "One session, one approved unit
  (RULE-016)", with a paragraph after the phase bullets stating the batch lane and its
  per-item record obligation.
- **`docs/spec/SPEC-035.md`** — §3's opening line now reads "RULE-016 gives one approved
  unit per session"; an amendment note is added **in place** (the section is not
  overwritten), stating that the phase rule itself is unchanged and applies to a batch the
  same way — one gate, one execution session, never both in one.
- **`.claude/commands/execute-wi.md`** — step 6's "One session, one work item (RULE-016)"
  restated as the unit rule, naming what a batch execution owes: one pull request, one
  combined summary, a `docs/completed/` file per item.
- **`DECISIONS.md` / `docs/decisions/DEC-100.md`** — DEC-100 moved out of §Open into its
  own closed file with a `**Closed 2026-09-18**` header, and indexed in §Closed.
- **Ledgers** — `PLAN.md` §2 drops the WI-148 row and its batch-ordering paragraph now
  records the amendment as landed; `PLAN-COMPLETED.md` §3 gains the row; `INTAKE.md` moves
  IN-142 from §1.1 to §1.2.

### Visible behavior changes

None in the application. No source file under `apps/` or `packages/` was touched, and no
build, schema, store, rule or testid changed. The change is to the process rules that
govern future sessions: an execution session may now carry a batch of Simple items
approved at one gate.
