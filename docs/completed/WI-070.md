## WI-070 — Un-quarantine and refactor `portability.spec.ts`

**Spec:** SPEC-036 · **From:** IN-043 · **Closed:** 2026-08-09 · `claude-code`, `opus`,
effort `high`

### Changes made

- **`apps/web/tests/e2e/portability.spec.ts`** — rewritten. `test.fixme` is gone, and the
  single quarantined flow is split into the two flows it always was:
  - _"Gate 5: a revealed handout reaches players, and concurrent Notes converge"_ — two
    browser contexts. The handout leg no longer switches the player's activity at all (a
    joining player is already on the Map, where `HandoutViewer` renders), and the Notes
    leg now ends with an admin read of the stored CRDT, so convergence is proven in
    storage rather than in two views that happen to agree.
  - _"Gate 5: portability — `.vttcamp` export/import round-trips the room"_ — one context.
    Every post-import assertion reads Firestore and RTDB directly instead of driving the
    imported room's UI, and the browser is closed before the comparison runs.
  - New admin-REST helpers in the file: `decodeValue`/`decodeFields` collapse Firestore's
    typed REST values to plain JS (normalising `integerValue` to a number so a value that
    survived `.vttcamp`'s JSON round-trip as a double still compares equal); `adminDoc`
    and `adminCollection` read documents over `Authorization: Bearer owner`; `adminNotes`
    pulls RTDB `rooms/{id}/yjs/notes` and decodes it through `Y.applyUpdate` →
    `getText('notes')`; `portableFacts` assembles the comparison subject.
  - Round-trip fidelity is now an exact `toEqual` over both rooms' stored documents —
    room `name`, `schemaVersion`, `handout`, `profileTemplate`, plus the whole of
    `tokens`, `log`, `gmPrivate` and `maps`, plus the decoded Notes text — replacing the
    handful of spot-checks the rendered UI could reach. Excluded, because an import or a
    live client is meant to change them: the room id, `gmUid`, `lastActivityAt`, and
    `players` (presence rewrites `lastPresentAt` on every heartbeat).
  - Two small shared steps factored out: `revealHandout` and `openNotes`.
- **`docs/spec/SPEC-036.md`** — created. States what the portability e2e must prove (§1),
  the flake and the rule that follows from it — after a navigation that remounts the map
  stage, assert stored state, not UI (§2) — the deterministic-emulator-assertion method
  (§3), the two-test shape (§4), and the standing invariant that the battery carries no
  quarantined tests (§5).
- **`SPEC.md`** — SPEC-036 added to the index as Completed.
- **`PLAN.md`** — WI-070 removed from §2 and its detail block deleted.
- **`PLAN-COMPLETED.md`** — WI-070 row added to §3.
- **`INTAKE.md`** — IN-043 moved from §1.1 to §1.2, closed via WI-070 / SPEC-036.

more tests than it did, and the battery no longer contains a `test.fixme`.

### Deviations

- **`docs/spec/SPEC-036.md` did not exist.** `PLAN.md` and `INTAKE.md` both cited SPEC-036
  for this work item, but no spec body was ever written — the id was allocated at
  disposition and left unfilled. Written here from the approved gate's What/Why/Impact,
  the quarantine comment's own account of the failure mode, and the implementation, and
  indexed in `SPEC.md`. Same situation and same resolution as WI-069's SPEC-035.
- **The work item was split into two tests, not kept as one.** The gate said "refactor
  into deterministic emulator assertions and remove the quarantine" without prescribing a
  shape. Splitting halves the work per test, lets CI's per-test retry recover one without
  re-running the other, and makes a failure name which property broke. Recorded as
  SPEC-036 §4.
- **Two assertions from the original flow were dropped rather than ported.** The
  post-import `handout-image` visibility check and the post-import `notes-input` text
  check were exactly the UI-driving steps that caused the hang; both are now covered more
  strictly by the document comparison (`handout` on the room doc, the decoded Notes text).
  The pre-import player-side handout reveal check is kept in full, since that leg is the
  live-sync property and cannot be proven from storage alone.
- **`PLAN.md`'s §2 ordering paragraph was not rewritten.** It never listed WI-070 (the
  item was appended to the table after that paragraph was last revised), so removing the
  row leaves it correct as-is.
