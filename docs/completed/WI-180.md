# WI-180 — Undo: token moves and group changes

SPEC-056 §2.3, DEC-108. Single unit (Deceptive). IN-166.

**Changes made**

- `apps/web/src/lib/components/VectorMapView.svelte` — the token drag handlers capture
  the token's (or, for a collapsed-group anchor, the anchor's) pixel position at pickup
  (`tokenMoveFrom`), alongside the existing lattice-unit `tokenDragStart` the measure
  chip already used. Two new helpers, `moveTokenUndoable` and `moveTokensUndoable`,
  wrap the existing `store.moveToken`/`store.moveTokens` settled-drag writes: each
  writes forward first, then pushes one entry onto the shared undo stack
  (`UndoController`, WI-178) whose `undo`/`redo` closures replay the same store calls at
  the `from`/`to` positions — skipped outright when the drop lands back where the drag
  started. The canvas drag `stop()` handler and the sheet-portrait-onto-an-existing-token
  drop path (`onCanvasDrop`) both now go through these helpers instead of calling the
  store directly; a drop that creates a brand-new token (no existing token under the
  drag) is unchanged, since a create is not a move.
- `apps/web/src/lib/components/EncounterBoard.svelte` — `onSectionDrop` (a card dragged
  between, or reordered within, a cast box) now snapshots every touched group's
  `memberTokenIds` before writing, then pushes one undo entry covering the whole drop —
  however many groups it touched (moving a creature out of one box and into another
  writes both) — onto the same shared stack, read via the new `UNDO_KEY` context import.
- `apps/web/tests/e2e/encounter-board-v2.spec.ts` — two new e2e cases: a lone token's
  canvas drag and a collapsed group's batched anchor drag each undo with Ctrl+Z (the
  group case restores every member from one entry, not just the anchor); and moving a
  creature between Encounter Board cast boxes undoes the same way, from the Map view's
  Ctrl+Z (the board itself has no Ctrl+Z listener of its own).
- `README.md` → "The selection model" (SPEC-037) — new paragraph documenting that token
  moves and Encounter Board group changes push onto the shared undo stack the same way
  geometry edits and object deletes already do, and that a board-made change is undone
  from the Map view since only `VectorMapView` wires the keyboard shortcut.

**Visible behavior changes** — Ctrl+Z now also undoes: dragging a token on the map
canvas (a lone token, or a collapsed group's anchor, which restores every member in one
step); dragging a character-sheet portrait onto an existing token's own map spot (moving
it); and moving a creature between Encounter Board groups (or reordering it within one).
A drag that lands back where it started leaves no undo entry. Dropping a sheet portrait
where no token exists yet still creates one, and that creation is not undoable (unchanged
from before — the same as any other create).

**How to verify** — `pnpm verify` (lint/typecheck/unit) and `pnpm verify:all` (adds
rules/store contract suites and the full Playwright e2e suite against the emulators,
including the two new `encounter-board-v2.spec.ts` cases) both green. Manually: as
referee, drag a token on the map and press Ctrl+Z — it snaps back; collapse a 3-token
group, drag the anchor, and Ctrl+Z — all three members return to their prior formation in
one step; on the Encounter Board, drag a card into another box, switch to the Map view
and press Ctrl+Z — the card returns to its original box.

**Deviations** — none.
