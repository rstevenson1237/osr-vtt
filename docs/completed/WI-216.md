# WI-216 — Each background image renders independently

SPEC-059 §2, DEC-124. IN-068. Model `opus`, effort high.

## Changes made

- `apps/web/src/lib/map/background-view.ts` — new pure `settleBackgroundTextures(bgs, load)`:
  loads every texture with `Promise.allSettled` and returns `{ loaded, failed }`, `loaded`
  in input (paint) order. One rejected load no longer rejects the whole pass.
- `apps/web/src/lib/components/VectorMapView.svelte` — `applyBackgrounds` uses it in place
  of `Promise.all`. A loaded image is placed, moved, restacked or removed as before; an
  unloadable one has no sprite (an existing one is destroyed) and logs
  `background image failed to load: <ref>`. Each settled, non-superseded pass writes its
  failures to `mapCtrl.setBrokenBackgrounds(mapId, ids)`, even when the canvas unmounted
  mid-pass. A sprite under the local GM's drag is placed from `liveBackgroundRect(bg,
  bgDrag)`, so an incoming snapshot no longer snaps it back to its stored rect.
- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — new `brokenBackgrounds` (per map
  id, the ids the latest pass could not load), `setBrokenBackgrounds` and
  `isBackgroundBroken`. Not cleared by `release()`: the panel reads it while the canvas is
  unmounted.
- `apps/web/src/lib/components/shell/BackgroundsPanel.svelte` — a row whose image failed
  shows "Image could not be loaded" (`background-error-{id}`, new testid). Lock, Fit, Remove
  and restack are unchanged.
- `apps/web/src/lib/strings/BackgroundsPanel.ts` — the note's copy.
- Tests: `map/background-view.test.ts` (settling: one failure blocks none, all-fail
  resolves, empty; the live rect survives a snapshot that moves the dragged background),
  `shell/map-tool-controller.test.ts` (per-map record, a later pass clears it, survives
  `release()`), `tests/e2e/backgrounds.spec.ts` (new case: a CORS-refused image's row shows
  the note, the starter map's row does not, and the broken image can be removed).
- `README.md` — "Background management" describes the behaviour and lists the new testid.
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — ledger close-out; IN-068 closed.

## Visible behavior changes

- A placed background whose image cannot be loaded no longer freezes the whole background
  layer: every other image keeps updating, and the broken one draws nothing.
- In Assets → Backgrounds, that image's row reads "Image could not be loaded" until a later
  render pass loads it. The note reflects the last pass this client's map canvas ran.
- While the GM drags a background, a remote change to the backgrounds no longer jumps that
  image back to its stored position mid-gesture.

No schema, store, rules or existing `data-testid` change.

## How to verify

- `pnpm verify` and `pnpm verify:all` — green.
- `tests/e2e/backgrounds.spec.ts` → "SPEC-059 §2: an image the canvas cannot load draws
  nothing, its panel row says so, and it can still be removed".
- By hand: save an image URL from a host without CORS headers under Assets → By URL, add it
  as a background beside the starter map, open the map, then return to Assets. The starter
  map renders and moves normally; the other row shows the note and Remove works.
