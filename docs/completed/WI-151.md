# WI-151 — Planning model routing

SPEC-035 §4 previously bound "planning turns" to `opus` as a blanket case. Scoped per
DEC-103 (answered (b)): `opus` for a Shape A request, for any gate touching a `RULE-`,
and for a decision the user will answer; `sonnet` for Shape B triage and for scheduling
an already-classified item into `PLAN.md`.

**Changes made.**

- `docs/spec/SPEC-035.md` §4 — amended in place with a dated annotation (the section is
  Completed, so it is never overwritten): the scoped routing rule, execution-turn routing
  restated unchanged.
- `CLAUDE.md` — Model paragraph split: the existing sentence keeps execution routing
  (dropping "and for planning"), a new sentence gives planning-turn routing by what the
  turn is doing, citing SPEC-035 §4.
- `.claude/commands/work-item.md` — step 4's model paragraph gains a note that this
  planning session's own turns route separately from the `model` cell it records for
  execution, with the same three cases.

**Visible behavior changes.** None — this governs which model an agent should run
planning turns on; it does not change any runtime behaviour.

files.
