# WI-117 — The letter input in the character sheet, capped at 3

**Spec:** SPEC-048 §5 · **From:** IN-111 · **Agent:** `claude-code` · **Model:** `sonnet` ·
**Effort:** S · **Closed:** 2026-09-09

## Changes made

- **`apps/web/src/lib/components/CharacterDock.svelte`** — added a letter input beside
  `token-color-control`, gated the same way (`canSetOwnToken`): a new `label.inline`
  (`data-testid="token-letter-control"`) wrapping a text input
  (`data-testid="token-letter-input"`, `maxlength="6"`), pre-filled from `genLetter` (the
  same precedence `previewSrc` already reads: `profile?.letter ?? actorToken?.letter ??
  seatLetterFor(...)`). `onchange` calls a new `setMyLetter`, which caps the typed value
  with `letterGlyphs` (the same `GEN_TOKEN_LABEL_CAP`-slicing helper the render pass uses)
  and calls `store.setTokenLetter(roomId, mine.id, letter || undefined)` on the player's
  own token — mirroring `setMyColor`'s shape. Disabled while a write is in flight or the
  actor has no token yet (`!actorToken`). Imports `letterGlyphs` from
  `../tokens/letter-style`.
- **`README.md`** — quick-sheets table row for `character` now lists the letter input
  alongside the colour picker; §II.7's "letter and colour are stored fields" bullet gets a
  sentence naming the new `token-letter-control`/`token-letter-input` surface and
  reiterating the own-token-only scope.

No store, schema, or Security Rules changes — `setTokenLetter` already existed
(WI-113) and is called exactly as documented, touching nothing but `Token.letter`.

## Visible behavior changes

A player (or the GM, for their own seat) can now retype their character's token letter
directly from the Character quick sheet, beside the colour swatches — previously this was
only settable via "My token"'s Generate-default tab. Capped at 3 Unicode code points
(`GEN_TOKEN_LABEL_CAP`, unchanged). Does not apply to referee creatures — that surface is
still the Generate-default tab and the encounter board, as SPEC-048 §5 scopes it.

## How to verify

- `pnpm verify` (lint + typecheck + unit) — green.
- Manually: open a character's quick sheet as its owning player, type a letter (up to 3
  glyphs) into the new field beside the colour swatches, confirm the token on the map
  updates to show the new letter, and confirm clearing the field removes the letter
  (falls back to no drawn glyph, per SPEC-048 §1's "absence is a legitimate state").

## Deviations

None — implemented exactly as scoped by IN-111/SPEC-048 §5: a new `data-testid`, no store
surface, reaching only the player's own token.
