# WI-165 — Text tool in the Overlay group

SPEC-054 §13. Part of Batch 2b (WI-159, WI-161, WI-164, WI-165) — one pull request, one
combined summary.

**Changes made**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `MapToolId` gains `'text'`.
- `apps/web/src/lib/map/tool-groups.ts` — the Overlay group gains a `text` entry
  (`key: 'T'`, WI-161).
- `apps/web/src/lib/shell/types.ts` and `apps/web/src/lib/components/shell/Icon.svelte` —
  `IconId` gains `text`, a capital-T glyph.
- `apps/web/src/lib/components/MapToolbar.svelte` — `TOOL_META.text` (label, testid
  `vector-tool-text`, icon).
- `apps/web/src/lib/components/VectorMapView.svelte` — a click while `text` is active
  (`placeTextAt`) prompts for a string via the shell's `dialogs.promptText` (the modal-stack
  dialog service, not `window.prompt`) and, if non-empty, writes one `Drawing` — `kind:
  'text'`, a single-point `points`, `style: { text }` — through the existing
  `store.writeDrawing` path (RULE-003: one settled write, RULE-001: no new store method).
  `DrawingKindSchema` already admitted `'text'` and `renderAnnotations` already drew it
  (`drawing.style['text']`), so nothing on the schema or render side changed. A `HINTS.text`
  entry describes the tool the way every other tool's hint does.

**Visible behavior changes** — a new Text tool in the map palette's Overlay group (hotkey
`T`): click to place, type a string in the prompt, and it renders on the map as a text
annotation. Cancelling or leaving the prompt empty places nothing.

**How to verify** — `pnpm verify` green. Manually: pick Text, click the map, type a string
and confirm — the text appears at the click point; cancel the prompt on a second click and
confirm nothing is added.

**Deviations** — none.
