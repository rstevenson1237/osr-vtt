## Changes made

- `apps/web/src/lib/map/map-seam.ts` (new) — `MapSeamDeps` (`invalidate`, `store`, `roomId`,
  `mapId`) and `SquareSeamDeps` (adds `toLatticeRaw`): the part of a seam controller's
  constructor argument that is the same for every seam (SPEC-060 §2).
- `apps/web/src/lib/map/map-labels.svelte.ts` (new) — `MapLabels`, the room-label seam. It
  owns the `$state` that was free variables in the component: the editor (`editingId`,
  `editingText`, `editingPos`, `inputEl`), the tooltips (`hover`, `pinned`) and the deriveds
  `fontPx`, `active`, `activeText`, `showTooltip`, `tooltip`, `noteDotRooms`,
  `noteDotRoomIds`. Methods: `pointerDown` (the note-dot tap, formerly
  `handleNoteDotPointerDown`), `pointerMove` (formerly `updateHoverLabel`; never consumes),

  `open`, `commit`, `cancel`, `keydown`, `tooltipAnchor`, `destroy`. Pointer methods take
  raw world pixels and convert with the `toLatticeRaw` they were handed (SPEC-060 §4).
  Component state it needs (map rooms, notes, coarse pointer, cell size, pick radius,
  "pointer is busy", snap, `toScreen`) arrives as getters, so its deriveds track them.
- `apps/web/src/lib/components/VectorMapView.svelte` — about 230 lines of label code removed

  `labels.pointerDown`, `labels.toolClick`, `labels.pointerMove` and `labels.pointerOut`
  at the same positions in the ladder. `overlayInputs()` reads `labels.editingId` /
  `labels.noteDotRoomIds`; the template reads `labels.*`; `activeTooltip` reads
  `labels.tooltip`. The hex-note tooltip stays in the component.
- `apps/web/src/lib/map/map-labels.test.ts` (new) — 18 tests constructing `MapLabels` with a
  fake `invalidate` and no browser: hover shown/hidden (no notes, busy, coarse, renaming),

- `README.md` — the note-dot paragraph names `MapLabels.pointerDown` / `pinned` / `hover`;

- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — WI-218 row and block removed from PLAN, row

## Deviations

- `MapLabels` never calls `invalidate`. The overlay layer's tracking `$effect` already
  reads `labels.editingId` / `labels.noteDotRoomIds`, so redraws follow the `$state` with no
  wiring (SPEC-060 §3). `invalidate` is still in the deps, as the protocol hands it to
  every seam, and a test asserts it stays uncalled. No change to SPEC-060 was needed.
- `roomId`/`mapId` reach the controller through getters on the deps object, because they
  are component props that may change (the `state_referenced_locally` lint rule requires
  it). `MapSeamDeps` keeps the plain `string` types.
- One micro-difference: the old hover path returned before setting `hoverLabel` when the
  engine did not exist yet; `MapLabels` falls back to a `{0, 0}` anchor there. A pointer
  event cannot arrive before the engine exists (the handlers are wired from it), so this is
  unreachable in practice.
- No RULE-015 exception used: no unblocking change, no Deviations-budget fix.
- Not run: the full `pnpm verify:all` battery. Only the four specs above were run locally,
  against the emulators; CI runs the whole suite.
