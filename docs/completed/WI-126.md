# WI-126 — Road and River are previewed while they are drawn

**Spec:** SPEC-047 §12 · **From:** IN-127 · **Agent:** `claude-code` · **Model:** `opus` ·
**Effort:** S · **Gate cleared:** user, 2026-09-11 · **Landed:** 2026-09-13

Closes WI-105's own recorded Deviation: a road or river under construction is now drawn
as it is clicked, in the shade, width and join the commit will take.

## Changes made

- **`apps/web/src/lib/map/vector-tools.ts`** — new `buildHexLinePreviewPoints(collecting,
  pointer)`, the `HexPoint`-space counterpart of `buildWallPreviewSegs` directly above it:
  the collected run plus, when the pointer is over the map, a last point at the pointer.
  Returns an empty run below two points — the same `>= 2` test `finishMultiClick` applies
  before committing (DEC-085) — so the preview can never show a gesture the commit would
  discard. Copies rather than mutating the collector it is handed. `hexMap` added to the
  module's `@osr-vtt/shared` import.
- **`apps/web/src/lib/map/vector-engine.ts`** — the render pass.
  - New exported `HexLinePreview` interface: a `HexLine` minus the `id` it has not been
    given yet (`kind`, `points`, `shade`, `width`, `join`).
  - `renderHexLines`' drawing body factored out into `strokeHexLine(g, line, size)`, shared
    by the committed pass and the preview so "the shade, width and join the committed line
    will take" is the same code rather than two sites agreeing. Behaviour of the committed
    pass is unchanged.
  - New `renderHexLinePreview(preview, size)` on the `VectorMapEngine` interface, drawing
    into its own `hexLinePreviewGraphics` on the **`tools`** layer (above
    `hexSelectGraphics`). `null`, a run under two points, or `size <= 0` clears it. Holds no
    state of its own: it is handed the run every frame.
- **`apps/web/src/lib/components/VectorMapView.svelte`** — the wiring.
  - New non-reactive `hexHoverPx` (raw world pixel), recorded in the stage `pointermove`
    handler beside `updateHoverHexNote`, for the same reason: a hex map has no lattice, so
    `hoverRaw`/`dragCurRaw` are not reachable from one (RULE-006).
  - `addHexLineVertex`'s point resolution factored into `hexLinePointFor(worldPx)`, which
    the preview now calls too — the ghost's last vertex lands exactly where the next click
    would put it, by construction.
  - New `hexLinePreview()` assembles the per-frame payload from `hexCollecting`, the
    resolved pointer, and the same `mapCtrl.selectedHexLineShade`/`selectedHexLineWidth`/
    `hexLineEntry(tool).join` that `finishMultiClick` hands `addHexLine`. `null` for any
    other tool and every square map.
  - `renderAll` calls `engine.renderHexLinePreview(hexLinePreview(), hexGrid?.size ?? 0)`
    beside `renderHexLines`. No new clear path was needed: commit (`finishMultiClick`),
    cancel and tool change (`cancelStroke`, via the tool `$effect`) already empty
    `hexCollecting` and call straight through to `renderAll`.
  - `type HexLinePreview` added to the `vector-engine` import.
- **`apps/web/src/lib/map/vector-tools.test.ts`** — three unit cases: the pointer is
  appended to the run; nothing previews below two points (and one collected vertex *plus* a
  pointer does); the collector is not mutated.
- **`README.md`** — "Hex overlays — symbols, roads and rivers" gains a bullet for the
  preview: what it draws, that it shares `strokeHexLine` and `hexLinePointFor` with the
  commit, that it rides `tools` and so is absent from an export, and that it writes nothing.
- **`docs/spec/SPEC-047.md`** — §12's work-item note records what was built and the
  layer deviation below; §4's "no live line preview" Deviation is marked closed by this item.
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — WI-126 removed from §2, row added to
  `PLAN-COMPLETED.md` §3, IN-127 moved from §1.1 to §1.2.

## Visible behavior changes

One, and it is the point of the item: on a hex map, with the **Road** or **River** tool
active and at least one vertex clicked, the line under construction is drawn live — the run
so far plus a segment to the pointer — in the exact shade, width and join the double-click
will commit. It tracks the snap mode (corner-to-corner under Hex snap, raw under Free),
disappears on commit, on Escape, and on a tool change, and never appears for a run too short
to commit. Nothing else moves: no control, no `data-testid`, no stored field, and no write
of any kind (RULE-003 untouched — the preview never leaves the drawing client). A PNG export
and a battle-map capture are byte-identical to before, since the ghost is on the hidden
`tools` layer.

## Deviations

- **The preview rides the `tools` layer, not `overlay`.** §12 describes the new pass as
  "on the same layer" as `renderHexLines`, which is `overlay` — a layer that **is** captured
  (`layers.tools` is in the hidden list at capture; `overlay` is not). A half-drawn ghost
  baked into a PNG export or a battle-map capture would be a defect, so the preview sits on
  `tools` with the picked-hex outline (`renderHexSelection`), which is there for exactly this
  reason. Nothing changes in what the referee sees while drawing — only what a capture sees.
  Recorded in SPEC-047 §12 as well.
- **`pnpm verify:all` was not run whole.** The full battery hit sandbox infrastructure
  trouble on WI-125 the same week; the targeted emulator run above covers the two e2e specs
  that actually exercise this change, and `pnpm verify` covers everything else.
