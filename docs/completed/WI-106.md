#### WI-106 — The hex Label gesture

**Spec:** SPEC-047 §5 (annotated). **From:** IN-093. **Model:** `sonnet`.

**Changes made.**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `MapToolId` grows one member,
  `hexLabel`. No new controller state: the gesture reuses `selectedHex`/`selectedHexTile`,
  which already exist for Select.
- `apps/web/src/lib/map/tool-groups.ts` — `HEX_TOOL_IDS` grows to
  `['select', 'pan', 'eye', 'measure', 'ping', 'hexLabel', 'hexSymbol', 'road', 'river']`,
  not `TOOL_GROUPS`: `hexLabel` is not the square map's own `label` (which writes
  `MapRoom.labelAnchor` in lattice units — RULE-006). `PaletteToolId` now also excludes it.
  The "Label is doubly out" doc comment is annotated in place — it still holds, since
  `hexLabel` invents no name and places no anchor.
- `apps/web/src/lib/map/tool-groups.test.ts` — `ALL_TOOLS`/`HEX_ONLY_TOOLS` grow to include
  `hexLabel`; the `HEX_TOOL_IDS` pin and the "reachable through `HEX_TOOL_IDS`, not
  `TOOL_GROUPS`" assertions cover it alongside `hexSymbol`/`road`/`river`.
- `apps/web/src/lib/components/MapToolbar.svelte` — `hexLabel` joins `HEX_TOOL_META` and
  the hex-only tool row (testid `hex-tool-label`, icon `label` — the same glyph the square
  map's own Label button uses), gated on `isHexMap` like its row-mates. Not added to
  `SNAP_TOOLS`: both snap modes resolve identically (§3), so the Snap selector stays hidden
  for this tool, the same as it is for Select.
- `apps/web/src/lib/components/VectorMapView.svelte` — the stage `pointerdown` handler
  short-circuits `hexLabel` (a hex map has no lattice to hand `onPointerDown`) into a new
  `handleHexLabelClick`: resolve the pointer to a hex through `hexAt` (the same
  `pixelToAxial` wrapper Select's own click already uses) and set `mapCtrl.selectedHex`
  unconditionally — unlike Select, this never toggles the selection off, since the gesture's
  point is to land on the hex whose note the sheet should show. `HexTilePanel` renders that
  hex's note unchanged; no new store method, no new prop threaded through `MapToolbar`.
  `HINTS` (`Record<MapToolId, string>`) gains a `hexLabel` entry.
- `apps/web/tests/e2e/hex-map.spec.ts` — one new test: the hex Label tool picks a hex,
  opens its note in the Map tools sheet, and the note shows on hover through the existing
  tooltip path.
- `docs/spec/SPEC-047.md` §5 — a "Built by WI-106" annotation covering the mechanism above.
- `docs/spec/SPEC-030.md` §5 — a new annotation recording that "Label is doubly out" still
  holds after `hexLabel` exists, per SPEC-047 §5's own instruction to qualify it in place.
- `README.md` — "Per-hex notes and the hex-tile sheet" gains a bullet on the `hexLabel`
  tool, and the "authored, not derived" bullet is updated to note it grew to include Label
  as well as Symbol/Road/River.
- `INTAKE.md` — IN-093's row moves from §1.1 to §1.2, closed via this item.
- `PLAN.md` / `PLAN-COMPLETED.md` — WI-106 moves from the upcoming table to the completed
  ledger.

**Visible behavior changes.**

A hex-crawl map's Map tools palette gets a fourth button in the hex-only row — Label —
alongside Symbol, Road and River. Clicking it and then clicking a hex on the map picks that
hex (the same `map-selected-hex` readout Select's own click sets) and the Map tools sheet's
hex-tile body shows its terrain, contents and note, ready to edit — the same sheet Select
already opens, reached one click sooner. Nothing new is stored: the note is the same
`HexTile.note` field, shown on hover through the same tooltip.
