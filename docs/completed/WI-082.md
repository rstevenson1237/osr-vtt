# WI-082 — Group card "Tidy"

**Spec:** — · **From:** IN-027 · **Decision:** DEC-067 · **Agent:** `claude-code`
(`sonnet`) · **Effort:** medium · **Closed:** 2026-08-13

DEC-067 turned IN-027's request — grid-arrange a cluttered group's members — into a
separate, explicit **Tidy** action on the group card, rather than a change to what
expanding a collapsed group does. Collapse/expand and `Group.memberOffsets` keep their
existing meaning untouched.

## Changes made

- `packages/shared/src/encounter/collapse.ts` — new `tidyGroupUpdates(group, tokens)`,
  a pure helper alongside the existing collapse/expand math. Lays out members in
  row-major order (`memberTokenIds` order, skipping ids with no matching token) in
  rows of `TIDY_GRID_COLUMNS = 3` (DEC-067: "4 or more wrap to a new row"),
  `TIDY_GRID_SPACING = 1` lattice unit apart (RULE-006 — positions stay in cell units;
  `cellSize` never enters this file). The grid originates on the first member's
  current position, which does not move. Returns `[]` for a group with no positioned
  member; feeds straight into `CampaignStore.moveTokens` as one batched write, the
  same pattern the collapsed-drag path already uses. It never touches
  `memberOffsets`, `anchorTokenId`, or `collapsed`.
- `packages/shared/src/encounter/collapse.test.ts` — 5 new cases: the 3-per-row wrap,
  the grid originating on (and leaving in place) the first member, skipping members
  with no token, non-interference with `memberOffsets`/`collapsed`, and the empty-group
  case.
- `apps/web/src/lib/components/EncounterBoard.svelte` — imports `tidyGroupUpdates`; a
  `tidyGroup(group)` handler that calls it and, if there's anything to move, batches it
  through `store.moveTokens`; a new **Tidy** button
  (`group-toggle-tidy-{groupId}`) in the group card's toggle row, next to
  Collapse/Expand. Disabled when the group is collapsed (its members aren't the
  individually-addressable thing on screen at that point, and moving them without
  updating `memberOffsets` would make the next Expand restore a stale formation) or has
  no members.
- `README.md` — the group-card control list now mentions Tidy, and a new paragraph
  next to the existing Collapse-to-one-token one documents the grid layout, its origin,
  and that it's a plain `moveTokens` write independent of `memberOffsets`.

## Visible behavior changes

- The group card gains a **Tidy** button. Clicking it snaps that group's member tokens
  on the map into a grid — up to 3 per row, wrapping to additional rows — anchored on
  wherever the first member currently sits. It's a one-shot rearrange, not a toggle.
- Tidy is disabled while the group is collapsed, or if the group has no members
  (same disabled styling as Collapse in that state).
- No change to collapse/expand behavior or to what gets stored when a group collapses.

## How to verify

- `pnpm verify` — lint, typecheck, and unit, including the 5 new `tidyGroupUpdates`
  cases in `collapse.test.ts` (confirmed passing in isolation:
  `npx vitest run src/encounter/collapse.test.ts` → 15/15). The suite's
  `account-recovery.emulator.test.ts` failure (`auth/network-request-failed`) is
  pre-existing and environmental — reproduced identically on this branch before this
  change, with no network path to the Auth emulator in this sandbox — not caused by
  this work item.
- By hand: as GM on the Encounter board, drag three or more cards into a named group so
  their tokens land at different map positions, then click **Tidy** on that group's
  card. The tokens snap into a 3-wide grid on the map. Collapse the group — Tidy
  disables; Expand — the pre-collapse formation (not the tidy layout, unless it was
  tidied before collapsing) restores as before.

## Deviations

None. IN-027's disposition note left three things to execution-time decision under
DEC-067: the grid's origin, its spacing, and whether it also reorders the group's
board cards. Decided here: origin is the first member's current position (matching
the anchor `collapseGroupPatch` already uses), spacing is 1 lattice unit with 3
columns, and Tidy does **not** touch `memberTokenIds` order — it only moves tokens on
the map. Reordering the board cards would change what drag-and-drop membership order
means (the thing `Group.memberTokenIds` is for elsewhere — initiative slots, drag
reorder) for a control whose only requested effect was the map layout; leaving it
alone keeps Tidy a pure position write, consistent with `collapsedDragUpdates`'s
existing `moveTokens`-only pattern.
