# WI-219 — Store updates to a missing document

SPEC-061, DEC-127. IN-226. Model `sonnet`, effort high. Changes the `CampaignStore` contract
(RULE-001). No schema, rules or testid change.

## Changes made

- `packages/shared/src/store/firebase-store.ts` — new private `updateExisting(ref, patch)`: runs
  `updateDoc`, treats `not-found` as success, and treats `permission-denied` as success only
  when one `getDoc` shows the document is absent (`isAbsent`; an unreadable document counts as
  "not known absent", so the original error propagates). All 32 bare `updateDoc` sites for
  single-document partial updates (room-doc setters, `renameMap`/`setMap*`, `setActiveMap`,
  `renamePlayer`/`setPlayerRole`/`setCurrentCharacter`, `moveToken`/`resizeToken`/`setToken*`,
  `updateGroup`, `updateProfileTemplate`/`updateEncounterTemplate`, the shared-roll status
  flips, `revealBlindDraw`, `revealHandout`, `hideHandout`) now call it. `patchBackground`
  (WI-215) is now a one-line caller of it. `moveTokens` keeps its one batched commit and falls
  back to one `updateExisting` per token only when that commit rejects `not-found`. Left
  alone on purpose: the migration helpers, `migrateRoomCollections`, `createBattleMap`,
  `exitBattleMap`, `touchRoomActivity`, `dismissRoomDormancy` and seat presence (SPEC-061 §4,
  or already catching their own errors).
- `packages/shared/src/store/memory-store.ts` — `transferGM` checks the room and both seats
  before changing anything and throws if any is missing. `LocalStore` inherits it. Every other
  `MemoryStore` update method already skipped a missing document.
- `packages/shared/src/store/campaign-store.ts` — the guarantee is on the doc comment of each of
  the 32 update methods, plus `moveTokens` (§2) and `transferGM` (§3).
- `packages/shared/src/store/contract/missing-doc.contract.ts` (new), registered in
  `campaign-store.contract.ts` — 11 tests run against `MemoryStore`, `LocalStore` and
  `FirebaseStore`: create the document, remove it, call every method of the group, check it
  resolves and the document stays absent. Covers tokens, `moveTokens` (two survivors, one
  missing), maps, backgrounds, player seats, groups, handouts, blind draws, the room doc after
  `deleteRoom`, and `transferGM` rejecting for a missing seat and a missing room (room and
  seats unchanged).
- `README.md` — new "Store errors: a missing document" subsection in Room lifecycle & dead data;
  the removed-background bullet points at it (RULE-018).
- `docs/spec/SPEC-061.md` §1 — states the `permission-denied` re-check (see Deviations).
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — WI-219 row and block removed from PLAN, row added
  to PLAN-COMPLETED, IN-226 moved to §1.2.

## Visible behavior changes

None for a single referee. When two referees race, the one whose action targets a document the
other just deleted (a token, map, group, seat or background) sees the action do nothing, with no
console error where `FirebaseStore` used to reject. A `transferGM` to a missing seat now rejects in
`MemoryStore` and `LocalStore` (it already did in Firestore).

## How to verify

- `pnpm verify` — docs:check, lint, typecheck and unit are green; the new contract file runs
  against `MemoryStore` and `LocalStore` as part of unit.
- `pnpm test:emulators:core` (or, for just this change: start the emulators and run
  `vitest run --config vitest.store.config.ts src/store/firebase-store.contract.test.ts -t SPEC-061`
  in `packages/shared`) — 11 of 11 pass against `FirebaseStore`.

## Deviations

- **Unblock — SPEC-061 §1 wording.** The spec said `FirebaseStore` swallows `not-found` only. The
  emulator showed that an update to a deleted _room_ doc is rejected `permission-denied`
  (`isGM` reads the stored document, `firestore.rules` L62), so the contract test for the
  room-doc setters failed with `not-found` alone. `updateExisting` therefore re-checks a
  `permission-denied` with one read and treats an absent document as a no-op; a denial on an
  existing or unreadable document still propagates. SPEC-061 §1 and the README say so. No rules
  change.
- **Branch.** Pushed to `claude/project-thread-sj03l1`, the branch this session was assigned,
  rather than `claude/wi-219`.
