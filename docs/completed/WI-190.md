# WI-190 — Referee exempt during a call; Resolve now

Amends SPEC-050 §3. SPEC-057 §2, DEC-115 (supersedes DEC-097 in part). Single unit (Shape
A). IN-162.

## Changes made

- `apps/web/src/lib/components/shell/sheets/RollSheet.svelte` — `callBlocking` is now
  `!isGM && initiativeCallOpen(sharedRoll)`: a staging Call for Initiative still disables
  and explains itself for a player, but the referee's dice row, staged-roll Roll/Hidden
  buttons, `TrayControls` and `MacroList` all stay live and publish ordinary `Roll`s.
- `apps/web/src/lib/components/DiceTray.svelte` — same exemption (`!isGM &&
  initiativeCallOpen(sharedRoll)`) for the expanded tray's add-die buttons, custom-die
  input and its own `TrayControls`/`MacroList`.
- `apps/web/src/lib/components/CombatTracker.svelte`:
  - New referee-only `resolveCallNow()` / `combat-resolve-now` button, next to **Roll for
    Initiative** and **Cancel call**. It resolves the shared roll exactly like the
    ordinary resolve (`resolveSharedRoll` only ever expands `ready` slots), then drops
    every row `applySharedRollToInitiative` left uninitiated — the seats that never
    staged — instead of leaving them in the order uninitiated. Enabled once at least one
    seat has staged (`readyCount > 0`), same as **Roll for Initiative**.
  - New `excludedFromReconcile` set (Deviation, unblock): the existing `[Active]`-group
    reconciliation effect re-adds any group/token member still marked Active but missing
    from `order` — exactly the row `resolveCallNow` just dropped — which undid the drop on
    the very next tick. Dropped refIds are recorded there, filtered out of the
    reconciliation's `wanted` set, cleared at the start of the next `callForInitiative`,
    and overridden by a deliberate re-add (the Encounter board's "add to initiative",
    which pins the ref) — "can be added by hand as today" (DEC-115).
- `README.md` — the Call-for-Initiative paragraph now states the referee's exemption
  (`roll-button`/`roll-hidden-button` and the rest of the Roll sheet/dice tray stay live)
  in place of DEC-097's "the referee is not exempt", and documents **Resolve now**
  alongside **Roll for Initiative**/**Cancel call**.
- `apps/web/tests/e2e/shared-roll.spec.ts` — the DEC-097 blocking test now covers two
  browser contexts (a player and the referee): the player's die controls still disable and
  say why, the referee's stay live and their roll doesn't touch the call, and Cancel still
  works. A new test drives an Individual-mode call with one auto-staged (unowned) actor and
  one player-owned actor that never stages, presses **Resolve now**, and asserts the staged
  actor gets an initiative value while the unstaged one's row is gone.

## Visible behavior changes

- While a Call for Initiative is staging, the referee can still roll normally (Roll sheet,
  dice tray, macros) — their rolls publish as ordinary `Roll`s, exactly as if no call were
  open. Players are unaffected: their controls still disable with the same explanation.
- The Combat tracker gains a **Resolve now** button (referee-only, visible whenever **Roll
  for Initiative** is), which resolves whoever has staged and removes anyone who hasn't
  from the initiative order, instead of leaving their row blank.

## How to verify

- `pnpm verify:all` — lint, typecheck, unit, rules, store, and the full Playwright suite
  (including `shared-roll.spec.ts`) against the Firebase Emulator Suite.
- By hand: as referee, call for initiative with a player-owned actor in the mix; open the
  Dice activity and roll normally while the call is staging (works); as the player, confirm
  their own dice are disabled with the explanatory note. Back in the Encounter tab, press
  **Resolve now** before the player stages — their row disappears from the order and stays
  gone (doesn't reappear on its own); adding them back via the Encounter board's "add to
  initiative" puts them back in.

## Deviations

Both under the RULE-015 **unblock** exception, in `CombatTracker.svelte`, a file this work
item already changes:

1. **Test fix.** The referee-exemption e2e test initially asserted `roll-hidden-button` was
   enabled before any die was staged; that button (like `roll-button`) is gated on the tray
   having a staged die regardless of any call, unrelated to the exemption under test. Fixed
   by staging a die first. No behavior change, test-only.
2. **Reconciliation conflict.** `resolveCallNow`'s row-drop was silently undone by the
   pre-existing `[Active]`-group reconciliation `$effect`, which is unconditional on any
   `encounter` write and re-adds any still-Active member missing from `order` — exactly the
   row just dropped. Without a fix, "Resolve now" would never visibly leave anyone out for
   any grouped actor, which is the common case DEC-115 targets (a player away from the
   keyboard while their character/side stays Active). Added the local
   `excludedFromReconcile` set described above; no schema change, matching DEC-115's stated
   Impact. Covered by the `shared-roll.spec.ts` "Resolve now" test, which fails without it
   (the dropped row reappears within the reconciliation effect's next tick).
