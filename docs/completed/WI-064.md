# WI-064 — Full-screen and standalone: one presentation model

**Spec:** SPEC-033 §5 · **From:** IN-035
**Agent:** `claude-code`, model `opus`, effort `high` · **Closed:** 2026-08-08

Full-screen (the Fullscreen API) and standalone (an installed PWA launched from the home
screen) are **two routes to the same state** — the app frame owning the whole display —
so they ship as one model, one control, and one layout. Neither is an authority boundary.

## Changes made

**The model.**

- `apps/web/src/lib/shell/presentation.svelte.ts` (new) — `createPresentation()`, a sibling
  of `layout.svelte.ts` in shape: reactive getters plus `dispose()`. Exposes
  `canFullscreen` (the API is usable here), `isFullscreen` (tracked from the document's
  `fullscreenchange`, not from the click, so Escape is never missed), `isStandalone`
  (`(display-mode: standalone)` plus iOS's `navigator.standalone`), `ownsDisplay` (either
  route), and `toggleFullscreen()`. Reads Safari's `webkit`-prefixed spellings alongside
  the standard ones. A refused request is swallowed, because the flag then simply stays
  truthful. Exports `STANDALONE_QUERY`.
- `apps/web/src/lib/shell/presentation.svelte.test.ts` (new) — nine cases over a fake
  document/`matchMedia`, covering what no CI browser can produce: a prefixed Safari API, a
  refused request, an installed standalone launch, iOS's legacy flag, an iPhone browser
  with no element full-screen, and listener detachment. Also pins the invariant that the
  request goes to `document.documentElement` — the frame — and not to the canvas.

**The control.**

- `apps/web/src/lib/components/shell/PresentationToggle.svelte` (new) — the
  `fullscreen-toggle` button. Owns its own `createPresentation()` (the two top bars are
  mutually exclusive, so at most one instance exists and nothing else reads the state).
  Renders **nothing** where it would be a lie: no Fullscreen API (an iPhone browser), or
  the app already owns the display (a standalone launch). Sized like the gear beside it,
  with SPEC-033 §7's `--hit-inline` as a floor so only a coarse pointer grows it.
- `apps/web/src/lib/components/shell/SessionTab.svelte`,
  `apps/web/src/lib/components/shell/MobileTopBar.svelte` — each mounts the control, so it
  is available in both layouts and to every seat, not just the referee.
- `apps/web/src/lib/shell/types.ts`, `apps/web/src/lib/components/shell/Icon.svelte` —
  two new `IconId`s, `fullscreen` and `fullscreen-exit`.
- `apps/web/src/App.svelte` — paints `:root:fullscreen` and its `::backdrop` in
  `--bg-root`, so a display whose aspect ratio differs from the window's does not
  letterbox in the UA's black. No layout CSS: the frame already sizes against `100dvh`
  (§1) and pads by the safe-area insets (§3), which is what makes both routes one layout.

**Standalone.**

- `apps/web/public/manifest.webmanifest` (new) — `display: standalone`, theme/background
  `#1b1712`, and **relative** `start_url`/`scope`/`id`/icon paths, so a GitHub Pages deploy
  under `/<repo>/` resolves them without a second source of truth.
- `scripts/make-app-icons.mjs` (new) + `apps/web/public/icons/{icon-192,icon-512,apple-touch-icon}.png`
  (new) — a dependency-free procedural drawing (a room, lattice lines, one token) in the
  theme's own tokens, rendered 4× supersampled and encoded as PNG with `node:zlib`. The
  art sits inside the central 60%, so one image serves `any maskable`.
- `apps/web/index.html` — links the manifest and icons through Vite's `%BASE_URL%`, and
  carries the iOS tags iOS reads *instead of* the manifest. Status-bar style is `black`,
  not `black-translucent`: translucent puts the app under the status bar, which would need
  a top safe-area inset the frame does not carry (§3 pads bottom and sides only) — and §5
  requires both routes to produce the same layout.

**Tests.**

- `apps/web/tests/e2e/presentation.spec.ts` (new, desktop project) — two cases. The control
  full-screens `document.documentElement` (rail and bottom bar still visible, so the
  toolbars came along), flips `aria-pressed`, and gives the display back. And the gate's
  named invariant: the Pixi stage survives a frame resize **with its camera intact**,
  asserted through `snap-cell-readout` — which lattice cell a fixed canvas-relative point
  lands in is a pure function of the world container's pan and zoom. Driven by
  `setViewportSize` rather than by entering full-screen, because a headless browser is
  already the size of its display and entering full-screen there resizes nothing.
- `apps/web/tests/e2e/mobile.spec.ts` — one added assertion: the control is present in the
  mobile top bar too.

- `README.md` — new "Full-screen and standalone are one presentation model (SPEC-033 §5)"

- `docs/spec/SPEC-033.md`, `SPEC.md` — SPEC-033 moves to **Completed**; the

## Visible behavior changes

- A **full-screen button** appears in the top bar in both layouts (desktop `SessionTab`,
  mobile `MobileTopBar`), for every seat. It toggles the whole app frame; the icon and
  `aria-pressed` follow the browser, so leaving full-screen with Escape updates it too.
  It is absent where the Fullscreen API is unavailable (an iPhone browser) or where the
  app was launched standalone.
- The app is **installable**. Android/desktop Chrome offers "Install"; iOS "Add to Home
  Screen" gets the app icon, the app name, and a standalone launch with no browser chrome.
  A browser tab that never installs and never goes full-screen is unchanged.
- Nothing about authority, tools, or visibility changes.

## How to verify

- `pnpm verify:all` — lint, typecheck, the unit suites (including the nine new
  `createPresentation` cases), and the emulator-backed rules/store/e2e battery, which now
  includes `presentation.spec.ts`.
- By hand, desktop: open a room, click the full-screen button in the top bar. The whole
  frame — rail, sheets, bottom bar — goes full-screen, and the map keeps its pan and zoom
  across the transition. Press Escape; the button un-presses on its own.
- By hand, mobile: same button in the compact top bar.
- `[HUMAN]`, and not covered by CI: install the app (Chrome "Install", or iOS Share → Add
  to Home Screen) and launch it from the home screen. The window has no browser chrome,
  the layout matches the full-screen one, and the full-screen button is absent.
- Regenerating the icons: `node scripts/make-app-icons.mjs`.

## Deviations

- **The gate was cleared by the user in the execution instruction** ("64 - user has
  approved", 2026-08-08) rather than by a four-section gate block written into `PLAN.md`
  during a planning session. The row in `PLAN.md` §2 carried "Four-section gate" as a
  requirement, not a clearance. Recorded here rather than inferred silently, which is the
  thing WI-063's summary flagged.
- **A camera-survival e2e was added, and it is driven by `setViewportSize`, not by
  full-screen.** The gate names camera survival as the thing to protect, and a headless
  browser cannot exercise it through the Fullscreen API — it is already the size of its
  display. The viewport change puts the Pixi host through the identical resize path
  (`resizeTo: hostEl` plus the grid/fog `ResizeObserver`), so the assertion is the real
  one; only the trigger differs.
- **The app icons are generated by a committed script rather than authored as art.** The
  repo has no image toolchain and RULE-010's thin-stack posture argues against adding a
  dependency for four PNGs. The generator keeps the sizes reproducible and the colours one
  edit from `theme/tokens.css`.
- **No new `data-testid` was removed, moved or renamed** (RULE-005); `fullscreen-toggle` is
  additive.
