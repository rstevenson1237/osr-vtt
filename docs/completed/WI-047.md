## WI-047 — Encounter board: a group's own "+" card adds a creature straight into that group

**Changes made.**

- `apps/web/src/lib/components/EncounterBoard.svelte`:
  - Added `addCreatureToGroup(group)`: opens the existing `dialogs.pickToken({mode:
    'creature', ... })` picker, builds the picked ref(s) via
    `nextCreatureTypeLetter`/`defaultCreatureRefs`, creates each token through
    `store.createToken` at the `STARTER_DROP_POS = { x: 160, y: 160 }` staircase (the same
    fallback `CharacterDock`'s "My token" flow uses since the board has no map camera —
    DEC-031), then adds every new token id into _that_ group's `memberTokenIds` via
    `store.updateGroup`. Unlike the map toolbar's `add-creature`, it never calls
    `createGroup`.
  - Rendered a new "+" card (`.add-creature-card`) at the end of each **named** group's
    card row — GM-only, expanded state only; the synthetic Unassigned bin does not get one.
  - New testid: `board-add-creature-{groupId}`. No existing testid moved (RULE-005).
- `apps/web/tests/e2e/encounter-board-v2.spec.ts` — new e2e case: promotes
  the Unassigned bin into a named group, clicks its "+" card, confirms the
  picker, and asserts the new creature landed in that group (not
  Unassigned, and no second group was created), surviving a page reload.
- `README.md` — one-line note on the Encounter Board's per-group
  add-creature card.
- `PLAN.md` — this entry; §2's WI-047 row removed and the execution order
  line updated.

**Visible behavior changes.** Each named group box on the Encounter Board now shows a
dashed "+" card after its last member card (referee view only). Clicking it opens the same
creature picker "Add creature" uses; confirming adds the picked creature(s) into that
group, positioned off-camera. The Unassigned bin does not get this card.

**How to verify.** As the referee: Encounter tab → promote the Unassigned bin into a named
group → click the new "+" card at the end of that group's row → confirm the picker → the
new creature's card appears inside that group, Unassigned count unaffected. Automated:
`pnpm test:all:emulators` — full suite green, including the new
`encounter-board-v2.spec.ts` case.

**Deviations.** None. The gate anticipated threading a `map` prop through `RoomShell` for
the real map `cellSize`; implementation instead reused `DEFAULT_GRID_CONFIG.cellSize`
directly, matching `CharacterDock`'s precedent — called out as alternative (b) in the gate.
