# WI-109 — `switchToEditMode` asserts the mode it establishes

**Spec:** — (test helper) · **From:** IN-107 · **Agent:** `claude-code` · **Model:** `haiku` ·
**Effort:** XS · **Closed:** 2026-09-08

## Changes made

- `apps/web/tests/e2e/helpers.ts` — `switchToEditMode` now asserts
  `expect(toggle).toHaveAttribute('aria-pressed', 'true')` on the `map-mode-toggle` testid
  immediately after the conditional click, before `closeQuickSheet` runs. The helper
  previously clicked the toggle when it wasn't already pressed but never checked that the
  click actually landed.

## Visible behavior changes

None. This is a test-only change; no app code, schema, or UI is touched.

## How to verify

- `pnpm verify` (lint + typecheck + unit) — green.
- Every e2e spec that calls `switchToEditMode` (`backgrounds.spec.ts`,
  `battle-map-capture.spec.ts`, `battle-map-lifecycle.spec.ts`, `fog.spec.ts`,
  `hex-map.spec.ts`, `map-draw-feedback.spec.ts`, `mobile.spec.ts`, `presentation.spec.ts`,
  `rooms-manager.spec.ts`) now fails at the helper call, not later at whatever edit-mode
  action the spec attempts next, if the toggle ever fails to reach the pressed state.
