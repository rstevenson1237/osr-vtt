# WI-183 — Pin listener guarantees in the contract suite, all three stores

SPEC-056 §5.1. Single unit (Deceptive). IN-173.

**Changes made**

- `packages/shared/src/store/campaign-store.contract.ts` — three new helpers
  (`subscribeAndWaitForFirst`, `pinArrayListener`, `pinSingleListener`) plus a new
  `describe('WI-183 — listener guarantees pinned across every subscribeX (SPEC-056 §5.1)', …)`
  block, added to `defineCampaignStoreContract` so it runs unmodified against `MemoryStore`,
  `LocalStore`, and `FirebaseStore` (RULE-001). For every `subscribeX` on `CampaignStore` it
  pins: the first callback fires once with the current contents (empty included, not an
  empty snapshot corrected by a second call), and no callback survives `unsubscribe()`. A
  separate `describe('ordering pinned where the interface documents one', …)` covers
  `subscribeMyRooms`'s newest-visited-first order (`subscribeLog`'s oldest-first/
  `LIVE_LOG_LIMIT`-capped order was already pinned by an existing test, noted inline rather
  than duplicated). No production code changed — this item only adds tests, per SPEC-056 §5.1
  item 1.
- The permission-error guarantee (item 4) applies to exactly two `subscribeX` methods —
  `subscribeBlindDraws`/`subscribeHandoutLibrary`, the only reads any store can ever deny
  (RULE-004/RULE-012) — and only `FirebaseStore` has an access-control concept to deny with;
  `MemoryStore`/`LocalStore` implement none (this file's own header comment already disclaims
  testing that here). Those two tests are `it.skip`'d for the other two labels and run only
  against `FirebaseStore (emulators)`.

**Visible behavior changes** — none (test-only change; no app code, schema, or interface
touched).

**How to verify** — `pnpm verify` (lint/typecheck/unit — exercises `MemoryStore`/`LocalStore`)
and `pnpm test:store` under `firebase emulators:exec` (exercises `FirebaseStore`) both green;
150 tests in the new `WI-183` block pass across all three labels (2 of them `it.skip`'d for
`MemoryStore`/`LocalStore`).

**Deviations** — none under RULE-015's two exceptions (no unblock write, no Deviations-budget
fix; this item touches only its own new test code). Two findings surfaced while writing the
tests, both handled as the spec's own §5.1 item 1 anticipates ("where the three stores
disagree today, … the test pins today's documented behavior") rather than by widening scope:

- `subscribeHexTiles`: `setHexTerrain` writes through a transaction (`patchHexTile`), which —
  unlike the plain `setDoc`/`updateDoc` every other pinned collection uses — does not apply
  optimistically to `FirebaseStore`'s local cache. A freshly-attached listener on the *same*
  client can take a second callback to catch up with a transaction's result. Its test is
  written to tolerate and document that specifically (comment in place at the test); every
  other `subscribeX` holds the stricter single-call shape.
- `subscribeBlindDraws`/`subscribeHandoutLibrary`: for a denied (non-GM) caller, `FirebaseStore`
  today neither errors nor resolves to an empty array — its `onSnapshot` calls carry no error
  callback, so a permission-denied listener simply never fires. That falls short of "reaches
  the error path" (item 4's stated guarantee); the tests pin the actual behavior (callback
  never fires) rather than the aspirational one. Wiring a real error channel through these two
  `subscribeX` methods is an interface-level change RULE-015 does not license from this item —
  **flagging it here for a `/work-item` triage pass to log as a new intake item**, rather than
  logging one directly, since `/execute-wi` keeps intake triage out of its reading/writing
  scope.
