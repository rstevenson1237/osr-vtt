# WI-221 — One container per token

SPEC-063, DEC-130 (a). IN-113. Model `opus`, effort high. Changes what the `tokens` layer
contains (RULE-006 trigger); the layer's place in the engine's order is unchanged. No store
method, schema, rules, coordinate meaning or `data-testid` change.

## Changes made

- `apps/web/src/lib/components/VectorMapView.svelte`
  - The six per-token maps (`spritesByToken`, `backgroundsByToken`, `ringsByToken`,
    `lettersByToken`, `awayBadgesByToken`, `brokenImageBadgesByToken`) become one
    `viewsByToken` map of `TokenView` records: a `PIXI.Container` with children, back to
    front, disc, sprite, letter, away badge, broken-image badge, ring (SPEC-063 §1).
  - New `createTokenView` (container `eventMode = 'passive'`, sprite `'static'` with the drag
    handlers and cursor, every other child `'none'`; §3), `addTokenChild` (inserts a lazily
    created letter or badge at its slot in that order) and `destroyTokenView`.
  - `syncSprites` places the container at `token.pos` (except while dragging) instead of the
    sprite; the disc no longer copies a position. `syncTokenRings`, `syncTokenLetters`,
    `syncAwayBadges` and `syncBrokenImageBadges` draw at fixed local offsets (`0,0`, or
    `(±0.72r, +0.72r)` for the corner badges) and no longer read the sprite's position.
    Alpha, tint and visibility stay on the same children as before.
  - New `ringLayer`, one `PIXI.RenderLayer` created with the first token and kept the last
    child of `layers.tokens` (new containers are inserted below it). Every ring is attached
    to it, and so is each collapsed-group count badge, which is now a child of its anchor
    token's container at `(+0.7r, −0.7r)` and is re-parented and re-attached when the anchor
    changes (§2).
  - `attachDragHandlers(sprite, container, tokenId)` reads and writes the container's position
    everywhere it used `sprite.position`, including the other members of a multi-select set
    drag. `resyncTokenDecorations` is deleted, and `syncCollapsedBadges` no longer runs on
    each pointer move.
- `README.md` — layer table row 5 and the token-letter bullet rewritten; new "Token container"
  bullet (RULE-018).
- `docs/spec/SPEC-063.md` → Active; `SPEC.md` index row → Active. `docs/spec/SPEC-048.md` §4
  "How the parts stay together" gains a superseded-in-part note pointing at SPEC-063.
  `docs/spec/SPEC-032.md` names `viewsByToken` beside the old `spritesByToken`.
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — WI-221 row and block removed from PLAN, row
  added to PLAN-COMPLETED, IN-113 moved to §1.2.

## Visible behavior changes

- A token's status ring and a collapsed group's count badge now always draw above every
  token's art. Before, a token created later could cover an earlier token's ring.
- Where two tokens overlap, the later token's art now covers the earlier token's letter and
  corner badges as well as its art, because each token's parts are drawn together. Before,
  letters and badges were drawn in separate passes and could show through a later token.
- Nothing else. Dragging, selection, cursors, alpha and tint behave as before.

## How to verify

- `pnpm verify` and `pnpm verify:all`. Both were green: lint, typecheck, unit, rules, store
  and the full Playwright suite, with no spec changed.
- PNG export check (SPEC-063 §4), run as a throwaway Playwright script against the emulator
  and not committed. Two goblins were added and the later one was dragged with free snap onto
  the earlier one's right half, then the earlier one was selected. On screen and in the
  exported PNG (`map-export-png`, whole stack), the earlier token's white selection ring is
  drawn across the later token's art, and the later token's group-colour ring is drawn across
  the earlier one's. So the render layer is included in the export. A screenshot taken
  mid-drag shows the disc, art, letter and ring moving together. The count badge uses the
  same render layer; it was not exported separately.
