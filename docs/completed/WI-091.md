# WI-091 — Redraw the icon set under SPEC-043's depiction rule

**Spec:** SPEC-043 · **From:** IN-074 · **Decision:** DEC-076 (Direction A · Implement) ·
**Agent:** `claude-code` (`sonnet`) · **Effort:** medium · **Closed:** 2026-08-30

**Changes made**

- `apps/web/src/lib/components/shell/Icon.svelte` — the wrapping `<svg>`'s
  `stroke-width` moves from `1.8` to `1.75` (SPEC-043 §1, the one technique change).
  Three `MARKUP` entries are redrawn per SPEC-043 §4, which named them as the glyphs
  that failed at palette size:
  - `dice` — a true d20: the same hexagon outline, but the three internal spokes now
    run from the centre to alternating outer vertices (top, lower-left, lower-right)
    instead of tracing a facet across the top, so the top vertex sits centred between
    two mirrored facets instead of reading as a crate's top face.
  - `tools` — a latched toolbox: a rounded rect body, an arched carry handle on top, a
    lid-seam line, and a small filled latch tab — replacing the diagonal chisel that
    merged head into shaft at 20px.
  - `ruler` — a straightedge lying flat: a horizontal rounded rect with four
    graduation ticks off its top edge — replacing the diagonal rhombus with tick
    pairs that read as a silhouette rather than a ruler.
  The module doc comment is updated to point at SPEC-043's precedence rule (implement →
  thing itself → resulting shape; group icons name the gesture) instead of claiming the
  markup is traced verbatim from the R1 mockup, which stopped being true for these three
  entries. The other 31 `MARKUP` entries are unchanged — SPEC-043 §4 names exactly these
  three as needing new geometry; the rest already depict an implement, a thing or a
  resulting shape under §2/§3, so redrawing them would be invention beyond what the
  gate approved (RULE-015).
- `README.md` — a new "Icon system (SPEC-043)" subsection under "Session shell — quick
  sheets (II.1)" states the technique (24×24 viewBox, `currentColor` stroke, 1.75 width,
  round cap/join) and the subject precedence rule in present-day-behaviour terms. The
  "Tools" section's `tool-groups.ts` paragraph gains one sentence cross-referencing the
  icon-system section and SPEC-043 §3 for why each group icon names a gesture rather than
  an implement.
- `PLAN.md` — WI-091 removed from §2; `docs/completed/WI-091.md` (this file) is the
  historical record.
- `PLAN-COMPLETED.md` — row added to §3.
- `INTAKE.md` — IN-074's row moved from §1.1 to §1.2.

**Visible behavior changes** — three glyphs in the shell's icon set render differently:
the dice/roll icon, the Tools nav icon, and the map Ruler tool icon. Every icon in the
app is very slightly thinner (1.75px vs 1.8px stroke at the same 24×24 viewBox). No
control's position, size, colour, `data-testid`, or accessible name changes — `Icon.svelte`
still renders `aria-hidden="true"` and the label lives on the wrapping control, untouched
by this change.

**How to verify** — `pnpm dev` and look at: the Roll quick sheet (dice icon in
`QuickSheetRail`/`MainViewTabs`), the shell's Tools-labelled control, and the map tools
palette's Ruler button under the View group. `pnpm verify` (lint + typecheck + unit) —
lint and typecheck pass clean; two pre-existing `*.emulator.test.ts` failures
(`account-recovery.emulator.test.ts`, `room-uploads.emulator.test.ts`) are unrelated to
this change — confirmed by running the same suite against the unmodified branch, where
they fail identically with `auth/network-request-failed` because no Firebase emulator is
reachable in this session's environment. `pnpm verify:all` (which starts the emulator
suite) is the suite that actually exercises those tests; CI runs it.

**Deviations** — none. The scope stayed inside SPEC-043's 34 glyphs and the two README
touch points constraint 1 in `PLAN.md` named; no other file was touched, and the 31
glyphs SPEC-043 §4 did not name for replacement were left as-is rather than redrawn from
scratch, per RULE-015 (the gate approved SPEC-043's stated scope, not open-ended
re-illustration).
