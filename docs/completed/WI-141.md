# WI-141 — Discoverability

**Spec:** SPEC-051 §§4, 5, 7 · **From:** IN-135, IN-139 · **Agent:** `claude-code` ·
**Model:** `sonnet` · **Effort:** M · **Closed:** 2026-09-19

## Changes made

- `apps/web/src/lib/components/shell/QuickSheetRail.svelte` — the `chips` variant (the
  mobile row above `MainViewTabs`) now renders each sheet's title under its glyph,
  matching `MainViewTabs`'s own mobile stacked layout (DEC-099, SPEC-051 §4). The icon
  drops its `size="sm"` override and falls to `Icon.svelte`'s default (`--icon`, 20px
  precise / 24px coarse) — the spec's "the glyph rises to `--icon`'s coarse value in the
  taller chip." No height change to `.mrail-chips`/`--mchips-h` was needed: the icon
  (24px) plus a 2px gap plus the 0.6rem label (matching `MainViewTabs`'s mobile label
  size) fit inside the existing `max(38px, var(--hit))` row at both pointer coarsenesses,
  so DEC-099's stated fallback (shrink the label to 9px, keep the glyph at `--icon-sm`)
  was not needed. The label truncates with an ellipsis rather than wrapping, since a
  two-word title ("Map tools", "Random tables") has no room to wrap onto a second line
  without growing the row.
- `apps/web/src/lib/components/MapToolbar.svelte` — six labelled, words-only actions gain
  a glyph beside their text, per SPEC-051 §7's named set: `map-undo` (`undo`), `map-redo`
  (`redo`), `fog-reveal-all` (`eye` — the existing Eye-tool glyph, reused for the same
  "look/see" meaning), `fog-reset` (`fog`), `map-rotate-selection` (`rotate` for a
  symbol, `flip` for a door — the button already switches its label the same way), and
  `map-export-png` (`download`). `add-creature` already carried `add-person` since
  WI-140. No button lost its label — every one keeps the same text it had, next to the
  new glyph (RULE-005 unaffected: no testid moved). The Edit/View toggle is unchanged —
  SPEC-051 §7 names only these six controls, not that one.
- `README.md` — the mobile-shell paragraph (previously just "Mobile has no rail; the
  bottom tab bar shows every main view at once") now also describes the labelled chip
  row; a new paragraph after the `MapToolbar` group description lists the six
  newly-glyphed actions and restates the "no button becomes icon-only" constraint.

## Visible behavior changes

On a narrow/mobile viewport, the quick-sheet chip row (Map tools, Character, Roll, Room,
Battle map/Random tables) now shows a short title under each icon instead of an icon
alone, and the icon itself renders slightly larger (matching the desktop rail's size
token). In the map tools sheet/palette, Undo, Redo, Reveal all, Reset fog, Rotate
90°/Flip 180° and Download PNG each now show a small icon beside their existing label.

## How to verify

`pnpm verify` (lint + typecheck + unit) — green. Visually: open the app on a narrow/touch
viewport and confirm the quick-sheet chip row shows a word under each glyph without
wrapping or overflow; open the map tools palette (desktop or the mobile sheet) and
confirm Undo/Redo/Reveal all/Reset fog/Rotate or Flip/Download PNG each show an icon
next to their label, and that Edit/View and the tool buttons are unaffected.

## Deviations

None. The blocking condition (WI-139's ids) was already satisfied; DEC-099's approved
default (label under glyph, glyph at `--icon`'s coarse stop) fit without invoking the
recorded fallback, so the fallback was not exercised.
