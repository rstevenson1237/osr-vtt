# WI-184 — `collectionOf<T>` in `FirebaseStore`, methods migrated in slices

SPEC-056 §5.2. Single unit (Deceptive). IN-173. After WI-183.

**Changes made**

- `packages/shared/src/store/firebase-store.ts` — new private `collectionOf<T>(path,
  converter)` (added just after `requireUid`), returning `{ subscribe, set, remove, batch }`
  over one Firestore collection: `subscribe(cb)` wraps `onSnapshot`+`docs.map(d => d.data())`;
  `set(item)` mints a doc ref (explicit `item.id`, or a fresh one) and `setDoc`s the full item
  with that id folded in, returning the id used; `remove(id)` is a `deleteDoc`; `batch(ops)`
  takes a list of `{ id, set }` / `{ id, remove: true }` entries and commits them as one
  `writeBatch`. The `CampaignStore` interface is unchanged (SPEC-056 §5.2's own condition) —
  this is purely internal to `FirebaseStore`.
- Every per-collection method whose shape is exactly subscribe/full-write/delete/batch now
  calls through a private `<name>Col(...)` accessor built on `collectionOf`, in place of its
  own `collection(...).withConverter(...)` + `onSnapshot`/`setDoc`/`deleteDoc`/`writeBatch`
  boilerplate: `players` (subscribe + `removePlayer`'s deletes), `tokens` (subscribe +
  `createToken`), `groups` (subscribe, wrapping `sortGroups` around the callback + `createGroup`
  + `deleteGroup`), `profiles` (subscribe only), `backgrounds` (subscribe + `addBackground` +
  `removeBackground`), `symbols` (subscribe + `placeSymbol` + `removeSymbol`), `mapRooms`
  (subscribe + `upsertMapRoom` + `removeMapRoom`), `floorRegions`/`fogRegions` (the shared
  `regionCollection` helper now returns a `collectionOf`, and `commitRegions` uses its
  `batch()` instead of building its own `writeBatch`), `walls` (subscribe + `setWall` +
  `removeWall` + `setWalls`/`removeWalls` via `batch()`), `doors` (subscribe + `setDoor` +
  `removeDoor`), `drawings` (subscribe + `writeDrawing` + `deleteDrawing`), `hexSymbols`
  (subscribe + `placeHexSymbol` + `removeHexSymbol`), `hexLines` (subscribe + `addHexLine` +
  `removeHexLine`), `macros` (subscribe + `saveMacro` + `deleteMacro`), `tables` (subscribe +
  `upsertTable` + `deleteTable`), `assetRefs` (subscribe + `saveAssetRef` + `deleteAssetRef`).
  Each migration is behavior-preserving: same Firestore calls, same converters, same doc-id
  and default-value logic (e.g. `addBackground`'s `{ locked: false, ...background }` default
  is resolved before the object reaches `set`, exactly as it was resolved before `setDoc`
  before).
- Left on direct Firestore calls, deliberately, because they don't fit the four-method shape
  without changing behavior: partial-field patches (`renamePlayer`, `setPlayerRole`,
  `moveToken`/`resizeToken`/`setTokenImage`/`setTokenColor`/`setTokenName`/`setTokenLetter`/
  `setTokenOwner`, `updateGroup`, `setBackgroundTransform`/`Order`/`Locked`, `setProfileValue`/
  `Portrait`/`Color`, and every map/room-doc field setter); `deleteToken` and `transferGM`
  (atomic batches that span two different collections, which one `collectionOf` instance can't
  address); `moveTokens` (a batch of partial `update`s, not full `set`s); `subscribeMyRooms`/
  `subscribeLog`/`subscribeRolls` (an `orderBy`+`limit` query plus, for the latter two, a
  `.reverse()` — outside `subscribe`'s plain-collection shape); `subscribeHexTiles`/
  `patchHexTile` (deliberately unconverted — see the existing comment on `hexTileCol` — and
  transaction-based); `subscribeBlindDraws`/`subscribeHandoutLibrary`/`writeBlindDraw`/
  `saveHandout` (schema-filtered raw reads over a shared `gmPrivate` collection, sorted and
  kind-filtered, not a plain per-item converter); `subscribeSharedRoll` (a composite emitter
  over a doc + a subcollection); `exportRoom`/`importRoom`/`deleteRoom`/`deleteMap`/
  `migrateMapBackgrounds`/`migrateTokenLetters` (generic loops over collection *names*, not
  one converter/type each).

**Visible behavior changes** — none. Internal refactor only; no `CampaignStore` method's
signature, return shape, or observable ordering/timing changed.

**How to verify** — `pnpm verify` (lint/typecheck/unit, green) and `pnpm verify:all` (adds the
Security Rules, store-contract, and Playwright e2e suites against the Firebase emulators,
green) — in particular the WI-183 listener-guarantee block in
`campaign-store.contract.ts` (`pinArrayListener`/`pinSingleListener` across every migrated
`subscribeX`) passing unmodified against `FirebaseStore (emulators)` is the direct proof this
migration didn't change any pinned behavior.

**Deviations** — none under RULE-015's two exceptions (no unblock write, no Deviations-budget
fix). All work is the single approved change: adding `collectionOf<T>` and moving the
per-collection methods that fit its shape onto it.
