# WI-220 — A `.vttcamp` from a newer build is refused

SPEC-062, DEC-128. IN-072. Model `sonnet`, effort high. A guarantee on the `.vttcamp` reader
(RULE-014); the manifest field is optional and additive, so no `VTTCAMP_FORMAT_VERSION` bump and
no migration (RULE-007). No store method, rules or testid change.

## Changes made

- `packages/shared/src/portability/vttcamp.ts` — `VttCampManifest` gains optional
  `exportedBy?: string`. `snapshotToArchive(input, exportedBy?)` writes it when given.
  New `assertNotFromNewerBuild`, called by `archiveToSnapshot` and `readManifest` right after
  `assertSupportedFormatVersion` and before `migrateRoom`: throws `VttCampFormatError` when
  `manifest.formatVersion` > `VTTCAMP_FORMAT_VERSION`, or the higher of the manifest's and the
  room doc's `schemaVersion` > `CURRENT_SCHEMA_VERSION`. Both readers take an optional
  `thisBuild` string; the message names the exporting build (`exportedBy`, else "a newer
  version") and, when passed, this build, and tells the referee to update the app.
- `packages/shared/src/store/local-store.ts` — optional fourth constructor argument `appVersion`
  (the shared package does not read the Vite env): passed to `snapshotToArchive` on every write
  and to `archiveToSnapshot` on `openCampaign`, so a newer file is refused before it is touched.
- `apps/web/src/lib/firebase/client.local.ts` — both `LocalStore` constructions pass
  `import.meta.env.VITE_APP_VERSION`.
- `apps/web/src/lib/components/Lobby.svelte` — both `snapshotToArchive` calls pass the version.
- `apps/web/src/lib/components/shell/SessionActivity.svelte` — the export passes `appVersion`;
  the import passes it to `archiveToSnapshot`, so the existing `importError` shows the message.
- `packages/shared/src/portability/vttcamp.test.ts` — new `.vttcamp from a newer build` block:
  current versions still import; newer `formatVersion`, manifest `schemaVersion` and room-doc
  `schemaVersion` each refused by both readers; message names both builds, falls back without
  `exportedBy`; `exportedBy` round-trips and is absent when not given.
- `packages/shared/src/store/local-store.test.ts` — `openCampaign` rejects a newer archive with
  the two-build message, writes nothing (`file.writes` is 0) and leaves the bytes unchanged.
- `README.md` — Local mode "Load" bullet states the newer-archive refusal and `exportedBy`
  (RULE-018). `docs/spec/SPEC-062.md` status line updated.
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — WI-220 row and block removed from PLAN, row added
  to PLAN-COMPLETED, IN-072 moved to §1.2.

## Visible behavior changes

Opening a `.vttcamp` made by a newer build (hosted Import, or opening a file in the local lobby)
now shows an error saying the file was made by a newer version of the app, naming both versions
when known, and asking the referee to update. Nothing is imported or written. Archives from this
or an older supported build open exactly as before. Exported archives carry one extra manifest
field, `exportedBy`.

## How to verify

- `pnpm verify` and the two test files: `pnpm --filter @osr-vtt/shared exec vitest run
  src/portability/vttcamp.test.ts src/store/local-store.test.ts`.
- By hand: export a campaign, edit `campaign.json` inside the zip to set
  `manifest.formatVersion` to 3, and import it — the error appears and no room is created.
