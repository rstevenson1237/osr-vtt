#### WI-105 — The Symbol, Road and River tools

**Spec:** SPEC-047 §4 (annotated). **From:** IN-092, IN-094. **Model:** `sonnet`.

**Changes made.**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `MapToolId` grows three
  members, `hexSymbol` | `road` | `river`, and the controller gains their per-viewer
  parameter state: `selectedHexSymbolKind` (default `'castle'`), `selectedHexLineShade`
  (default `1`), `selectedHexLineWidth` (default `0`) — the hex-space counterparts of
  `selectedSymbolKind`/`bandWidth`.
- `apps/web/src/lib/map/tool-groups.ts` — `HEX_TOOL_IDS` grows to
  `['select', 'pan', 'eye', 'measure', 'ping', 'hexSymbol', 'road', 'river']`, not
  `TOOL_GROUPS`: the three new tools are not square-map tools wearing a hex hat (they
  write `HexSymbol`/`HexLine` in `HexPoint` space, never `MapSymbol`/`Drawing` in lattice
  space — RULE-006). `PaletteToolId` now also excludes them, since they are never a
  `TOOL_GROUPS` member.
- `apps/web/src/lib/map/tool-groups.test.ts` — the "every `MapToolId` is reachable from
  exactly one place" guarantee is extended rather than weakened: split between
  `TOOL_GROUPS` (square tools) and `HEX_TOOL_IDS` (hex-only tools), plus new assertions
  pinning `HEX_TOOL_IDS`'s new tail and that the three hex-only tools are `isHexTool` but
  never `groupForTool`-reachable.
- `apps/web/src/lib/components/MapToolbar.svelte` — a new hex-only tool row (gated on
  `isHexMap`, parallel in spirit to a `TOOL_GROUPS` row but authored separately per that
  file's own doc comment), testids `hex-tool-symbol`/`hex-tool-road`/`hex-tool-river`; a
  symbol-kind picker (`hex-symbol-kind`, from `HEX_CONTENTS_CATALOG` — the same catalog
  `HexTilePanel` already draws from, not a second one); a shade swatch row
  (`hex-line-shade`, `hex-line-shade-0/1/2`, from the active line tool's `HEX_LINE_CATALOG`
  entry) and width select (`hex-line-width`, from `HEX_LINE_WIDTHS`) shown while Road or
  River is active. The Snap selector now also shows for the three new tools — the first
  hex tools that actually read `'hex'`/`'free'` (SPEC-047 §3, WI-104, previously dormant).
  New bindable props: `selectedHexSymbolKind`, `selectedHexLineShade`,
  `selectedHexLineWidth`.
- `apps/web/src/lib/components/shell/MapToolPalette.svelte` — threads the three new
  bindable props from `MapToolController` to `MapToolbar`.
- `apps/web/src/lib/components/VectorMapView.svelte` — `hexSymbols`/`hexLines` state,
  subscribed via `store.subscribeHexSymbols`/`subscribeHexLines` alongside `hexTiles`
  (empty on every square map, same sparseness). A new `hexCollecting: HexPoint[]`, kept
  apart from the lattice `collecting: Point[]` array so a `HexPoint` can never reach a
  square-lattice consumer at the wrong scale (RULE-006). The stage `pointerdown` handler
  short-circuits `hexSymbol` (single click, `placeHexSymbolAt`) and `road`/`river` (vertex
  collection, `addHexLineVertex`) before falling into the lattice-tool dispatch, the same
  way the square map's own `symbol`/`label` tools already do — a hex map has no lattice to
  convert the pointer into, so these need the raw world pixel for
  `hexMap.pixelToAxial`/`pixelToHexPoint`. `finishMultiClick` (the existing
  double-click/Enter handler Wall/Path/Polygon already use) gains a `road`/`river` branch
  committing via `store.addHexLine` when `hexCollecting.length >= 2`, discarding otherwise.
  `cancelStroke` resets `hexCollecting` too. `renderAll` calls two new render methods;
  `HINTS` (`Record<MapToolId, string>`) is extended for the three new ids. New
  introspection testids `map-hex-symbol-count`/`map-hex-line-count`.
- `apps/web/src/lib/map/vector-engine.ts` — `renderHexSymbols`/`renderHexLines`, both
  drawing to the `overlay` layer (a placed symbol the same layer the square map's own
  `symbol` uses; a line above the grid lines so it reads against the terrain under it).
  Symbols reuse the existing `syncHexArt` sprite-pool pattern keyed by `HexSymbol.id`;
  lines are drawn as one stroked polyline each, with colour/width resolved from
  `HEX_LINE_CATALOG`/`HEX_LINE_WIDTHS` at draw time only (never stored as values — §2) and
  `join` mapped from the document's own `HexLineJoin` (`'mitre'` → Pixi's `'miter'`,
  `'round'` → `'round'`).
- `apps/web/tests/e2e/hex-map.spec.ts` — two new tests: placing a hex symbol and drawing a
  road and a river (asserting the new count testids move), and a one-point Road/River
  commits-nothing guard (DEC-085).
- `docs/spec/SPEC-047.md` §4 — a "Built by WI-105" annotation covering the mechanism above,
  the resolution table read literally against §3, and the two deliberate omissions below.
- `README.md` — "Hex overlays — symbols, roads and rivers" gains a bullet on the tools
  themselves; the `HEX_TOOL_IDS`/`'hex'`-snap-mode bullets under "Per-hex notes and the
  hex-tile sheet" are updated to say they are now used rather than still dormant.

**Visible behavior changes.**

A hex-crawl map's Map tools palette now shows a third row — Symbol, Road, River — below
Select and the View tools, visible only on a hex map. Symbol drops the selected
`HEX_CONTENTS_CATALOG` icon: under Hex snap it lands on the hex the pointer is inside,
under Free snap exactly where the pointer is. Road and River draw a click-to-click,
double-click(or Enter)-to-finish line — three browns with mitred joins for a road, three
blues with round joins for a river, with a shade swatch row and a three-option width
select while either is active; under Hex snap each vertex snaps to the nearest hex corner
or centre, under Free snap the line is organic. Placed symbols and drawn lines render on
the map immediately and persist across a reload. Removing a placed symbol or line has no
UI yet — the store methods exist and are unused, deliberately (see Deviations).

**How to verify.**

- `pnpm verify` — lint, typecheck, unit.
- `pnpm verify:all` — adds rules/store/e2e against the Firebase emulators, including the
  two new `hex-map.spec.ts` cases.
- By hand: create a hex crawl, switch to Edit, open Map tools. Pick Symbol, choose a kind,
  click the map under Hex snap (lands centred on a hex) and again under Free snap (lands
  exactly at the click). Pick Road, click three points, press Enter or double-click to
  finish — confirm it draws in brown with mitred corners under Hex snap. Pick River and
  repeat — blue, round joins. Reload the map and confirm everything placed/drawn is still
  there.

**What the suite actually did.** `pnpm verify`: `lint`, `typecheck`, `unit` all green.
`pnpm verify:all`: `lint`, `typecheck`, and the emulator suites (rules, store, and
Playwright e2e — including the two new hex-tools cases) all green, no failures and no
flake retries needed.

**Deviations.**

- **No live line preview for Road/River.** SPEC-047 §4 specifies the gesture and the
  committed line, not a live ghost, and Wall's `buildWallPreviewSegs` has no
  `HexPoint`-space counterpart — building one would mean new preview plumbing in
  `vector-engine.ts` disproportionate to what the spec asks for. The gesture still
  accumulates and commits normally; it just isn't previewed mid-draw. Recorded in the
  SPEC-047 §4 annotation rather than left as a silent gap.
- **Hex-object selection/removal was not built.** `removeHexSymbol`/`removeHexLine`
  (WI-103) exist and stay unused. §4 describes placement only, and hex Select still picks
  hexes, not objects — giving it whole-object picking for `hexSymbols`/`hexLines` is a
  future item, not scope creep into this one (RULE-015).
