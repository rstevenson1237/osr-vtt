# WI-182 — One modal stack

SPEC-056 §7. Single unit (Deceptive). IN-183.

**Changes made**

- `apps/web/src/lib/shell/modal-stack.svelte.ts` — new `ModalStack` class: `open()`
  registers a new top entry and returns its id, `close(id)` unregisters it (from anywhere
  in the stack, though every current caller closes top-down), `isTop(id)` says whether an
  id is the current top, and `depth` is the entry count. Unit tests in
  `modal-stack.test.ts` (empty stack, single entry, nesting, closing the top restores the
  one below, closing out of order).
- `apps/web/src/lib/context.ts` — new `MODAL_STACK_KEY` context symbol.
- `apps/web/src/lib/components/RoomShell.svelte` — one `ModalStack` instance created per
  `RoomShell` and set on context, same lifetime as `DialogService`/`ShellState`.
  `onGlobalKey` rewritten: the expanded quick sheet (not a stack member) still collapses
  first on `Esc` regardless of what else is open; otherwise, while `modalStack.depth > 0`,
  every global shortcut (`?`, `L`, map tool hotkeys, `1`–`9`) is inert and `Esc` is left for
  the top entry's own listener to handle. This replaces the previous hand-rolled guard
  (`if (shell.dialog || dialogs.prompt || dialogs.confirmRequest || dialogs.tokenPicker)
  return;`), which never covered `shell.overlay` — global shortcuts still fired while the
  Log/Session overlay was open.
- `apps/web/src/lib/components/shell/Dialog.svelte` — the shared primitive behind
  `PromptDialog`/`ConfirmDialog`/`TokenPickerDialog`/`ShortcutSheet`: registers itself on
  the stack in `onMount`, unregisters and restores focus on unmount (moved off an `$effect`
  that re-ran when `panelEl` bound, onto `onMount`'s single mount/unmount pair), and its
  `Esc`/`Tab`-trap handler now no-ops unless `modalStack.isTop(stackId)`.
- `apps/web/src/lib/components/shell/ShellOverlay.svelte` — the Log/Session chrome, which
  previously had **no** focus trap and **no** focus restore at all, and depended entirely
  on `RoomShell`'s global handler to close on `Esc`. It now carries the same
  register/trap/restore machinery as `Dialog.svelte`, gated the same way on
  `modalStack.isTop`.
- `README.md` — "Keyboard" gains a paragraph naming the `ModalStack` and what it
  guarantees.

**Visible behavior changes** — Two real bugs are fixed, both only reachable by stacking
one modal over another (a confirm raised from inside Session settings — "Remove player" /
"Transfer referee" — is the one existing path into this): previously a single `Esc` press
could close both the confirm and the overlay beneath it at once (every open `Dialog`
listens on `window` and none checked whether it was topmost); now `Esc` closes only the
top one. The Log/Session overlay never trapped `Tab` or restored focus to its opener on
close; it now does both. Separately, global shortcuts (`?`, `L`, map tool hotkeys, digit
keys) previously still fired while the Log/Session overlay was open (only the four
`Dialog`-backed states were checked, not `shell.overlay`); they are now inert too. Every
`data-testid` is unchanged.

**How to verify** — `pnpm verify` (lint/typecheck/unit, includes the new
`modal-stack.test.ts`) and `pnpm verify:all` (adds rules/store contract suites and the full
Playwright e2e suite against the emulators, including `shell-navigation.spec.ts`'s existing
Log/Session/shortcut-sheet Escape cases) both green. Manually: as referee, open Session
settings, click "Remove player" on a seat to raise the confirm on top of it, press `Esc`
once — only the confirm closes, Session settings stays open and focus lands back on the
Remove button; press `Esc` again to close Session settings, and focus returns to the
`session-shortcut` button that opened it. With Session settings open, pressing `2` no
longer switches the main view underneath it.

**Deviations** — none.
