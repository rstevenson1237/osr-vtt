# WI-119 — Worldographer terrain reference sheet

**Closed 2026-09-09.** From IN-114, against SPEC-047 §8. **Findings and figures, no
production code** (the WI-100 precedent, RULE-015). Model target `sonnet`, run on `sonnet`.

§8 replaces WI-101's terrain art with the two supplied Inkwell Ideas/Worldographer icon
sets. The palette colours are the irreversible half of that work, so §8 splits into two
work items and puts the reference sheet first: this one traces every candidate, proposes a
`color`/`ink` pair for each, settles the two comparisons §8 left open, and renders the sheet
that WI-120 lands from. Nothing under `apps/` or `packages/` is touched.

**Deliverables**, all under `docs/completed/wi-119/`:

- `traced/*.svg` — 43 files: the 37 B&W silhouettes, the 4 confirmed single-tone colour
  additions, and the 2 held-back comparisons (`sandydesert`, `grassyhills`), each a single
  `<path class="ink" fill="#ffffff" fill-rule="evenodd">` in a `0 0 100 100` viewBox — the
  exact shape §8 asks for and the exact convention `catalog.ts`'s existing pack already uses.
- `reference-sheet.html` — every proposed kind at true render size (`hex.size` 48, today's
  default) and a 3× study size, ink at production's 55% alpha, over a stand-in black
  contents icon, exactly as `renderHexTiles`/`syncHexArt` composite them. Open it in a
  browser; it is plain static HTML with the SVGs inlined.
- `palette.json` — the machine-readable proposal: the 41-kind catalog (`color`/`ink`/`ref`),
  the `water` entry, the 6 alias resolutions, the 2 rejected comparisons, and a recommendation
  for the kinds this pack doesn't touch. WI-120's mechanical input.

## 1. Tracing: method and a coordinate-convention finding

Traced with `potracer` (pure Python, no system dependency — the tool named in the intake
README) at `threshold = peak_alpha // 2` rather than a fixed 128. One file needed that:
`sandydesert.png`'s whole glyph caps at alpha 87 (a deliberately faint texture in the source
art), which a fixed 128 threshold traces to **nothing**. Every other candidate peaks at 255,
where the adaptive threshold lands at 127 — indistinguishable from the fixed value the intake
README assumed. This is the kind of thing that only shows up by tracing all 43 and checking
for empty output, which is what surfaced it.

**A coordinate-convention finding worth recording**: `potracer`'s `Bitmap` treats `False`
(`0`) as the region to trace and `True` (`1`) as background — the opposite of the naive
reading of "pass a boolean mask." Verified with a synthetic 10×10 bitmap before touching any
real file (a centred `True` square traces as a hole in a full-canvas wrapper; inverting it
traces the square alone, correctly bounded). The pipeline is `bitmap_data = alpha < threshold`
— **not** `alpha >= threshold` — for exactly this reason.

Fidelity holds at every density tried, including the two glyphs the intake README flagged as
the ones most likely to fail (`forest-heavy`, `forest-mixed-mountains`): both traced with a
handful of subpaths and no visible artefacts against the source raster at 3× zoom. Output
sizes land inside the README's predicted 0.6–5.0 KB band for every file except three of the
busiest scatters (`reefs` 7.3 KB, `sandydesert` 6.8 KB, `forest-mixed-heavy` 7.4 KB) — still
smaller than their PNG sources.

Each source canvas (300×300 for B&W, 250×250 for the multicoloured set) is scaled uniformly
into the `0 0 100 100` viewBox with no per-icon re-centring: the icons are already centred in
their own canvases as authored, and a uniform scale is what preserves the relative visual
weight between, say, `forest` and `forest-heavy` — cropping each to its own content bbox
would have destroyed exactly that relationship.

## 3. Comparisons §8 left open

**Desert: `bw-desert.png` kept, `sandydesert.png` rejected.** Same colour/ink pair, side by
side on the sheet. `sandydesert`'s dot scatter reads as gravel or stipple, not dunes; `desert`'s
three nested arcs read immediately as dune ridges and cost twelve segments to `sandydesert`'s
195. Not close.

**Grassland: multicoloured `grassyhills.png` chosen, `bw-grassland.png` rejected.** This one
inverts the expected pack (B&W loses to multicolour-traced-to-white). `bw-grassland.png` is
two marks — a short dash and a dot — plainly meant to tile densely across a large painted
region in Worldographer's own renderer, which draws each icon at a fraction of its true size
and repeats it several times per hex. This pack draws one icon per hex at near-full size, and
two marks at that scale reads as almost nothing, especially under a contents icon. `grassyhills`'
cluster of six irregular blobs reads as texture at every size on the sheet. `grassland`'s
`ref` is `grassyhills.svg`; `bw-grassland.png` is traced (`traced/grassland.svg`) but unused.

**Badlands vs. brokenlands: not a blocker, filename-canon both ways, per the user's
2026-09-08 call.** Worldographer's own `black_white.properties` labels `bw-brokenlands.png`
"Badlands," while `bw-badlands.png` is one of the 15 unreferenced extras (§2). §8 already
settles this by naming from the filename rather than the label, so `badlands` ↔
`bw-badlands.png` (a jagged spike cluster) and `brokenlands` ↔ `bw-brokenlands.png` (a
star/asterisk cluster). The two shapes are visually distinct — this is not the "wrong
decision is invisible" case stated in the plan, that concern was about which *name* attaches
to which glyph, not whether they're worth two kinds — and both ship as ordinary catalog rows.

## 5. Water: three shades studied, one proposed

§8 asks for "three shades of blue, background only, no glyph." Studied on the sheet:

| shade | colour | bg/contents |
| --- | --- | --- |
| water-shallow | `#4fb0c6` | 5.70 |
| **water (proposed)** | **`#3a7098`** | **3.90** |
| water-deep | `#1c3f66` | 2.39 — rejected |

`water-deep` is the cautionary case for the whole palette: dark enough to look like open
ocean, dark enough to swallow the black contents icon. `water-shallow` and the proposed pick
both clear this sheet's bar; the mid shade is proposed because it sits furthest from either
neighbour and reads unambiguously as "water" rather than "shallows" or "trench" on its own,
which is the only judgement call left once legibility is satisfied.

**What WI-120 still has to decide, left open on purpose**: whether `HexTerrainEntry.water`
keeps a `ref` pointing at a valid-but-empty SVG (simplest — `syncHexArt` needs no new branch)
or the renderer learns to skip a null ref. This work item takes no position beyond naming the
choice; it is a two-line implementation detail, not a design one.

## 6. The colour model: mid-tone background, dark hued ink, verified two ways

DEC-089 (a): an authored `color`/`ink` pair per kind, guarded by a minimum contrast ratio.
Every pair here follows one rule — **background stays light-to-mid (never dark), ink is
always a dark, hue-tinted colour** (a warm brown-black for vegetation, a cool slate for
mountains and snow, a rust-black for badlands) rather than one of two greys. This is a
narrower rule than "authored, picked, not computed" strictly allows — DEC-089 does not
require every background to stay light — but it was chosen because the black contents icon
(SPEC-030 §3, unchanged) sits on **every** terrain regardless of kind, and this project's own
shipped precedent already treats a dark background as the risk to avoid (today's darkest
entry, `tree-evergreen` at `#2e5c38`, luminance 0.31, is also its lowest contents contrast at
3.10:1 — nothing in the existing catalog goes darker). Backgrounds here were generated
per-kind by hue/category and then walked lighter in 1%-lightness steps, by script, until both
checks below cleared **3.3:1** — comfortably above the 3:1 WCAG non-text floor this project's
own precedent already runs close to, with a bit of headroom held back deliberately.

**Two contrasts were checked, not one, and the second is the actual finding here.** The
obvious guard is `color` vs `ink` at full strength — call it the "raw pair." But
`HEX_TERRAIN_OVERLAY_ALPHA` (`vector-engine.ts`) renders the ink at **55% alpha**, and the
black contents icon is drawn on top of that blend, centred at the same point
(`renderHexTiles`) — so the pair that actually has to stay legible is the **55%-alpha blend
of ink over background, against the black contents tone**, and that number is uniformly
lower than the raw pair for a dark-ink-on-light-background scheme (blending a dark ink into a
light background can only darken the result the black icon has to stand out from). A raw
pair scored against DEC-089's literal ask can pass a unit test written against `color`/`ink`
alone while still under-serving contents legibility in the region where the two overlays
overlap. Every row on the sheet reports both numbers; every row clears both at ≥3.3.
**Recommendation for WI-120's guard test: check the blended figure, not just the raw pair.**
`docs/completed/wi-119/palette.json` carries both per kind.

## 7. What WI-120 should do with this

`palette.json`'s `catalog` array is the 41-row table (`kind`, `label`, `category`, `color`,
`ink`, `ref`, and whether it supersedes an existing kind's `ref` in place — 7 do:
`desert`, `hills`, `jungle`, `mountains`, `swamp`, `forest`, `grassland`). `water`, `aliases`
(the 6 in §4) and `rejectedComparisons` are separate keys. `untouchedKindsRecommendation`
lists the 9 kinds this pack does not touch at all (`plains`, `barren`, `mountain-major`,
`mountain-minor`, `reed`, `tree-deciduous`, `tree-evergreen`, `unknown`, plus `scrub` is
already covered above) with a baked-in `ink` per kind — today's `hexOverlayTone(color)`
result, computed once rather than re-derived, so `HexTerrainEntry.ink` can be a required
field with no behaviour change for anything this section doesn't touch.

`HEX_OVERLAY_DARK`/`HEX_OVERLAY_LIGHT` and `hexOverlayTone` retire once every entry carries
its own `ink` — SPEC-030 §2's amendment WI-120 owns.

## 8. Reproducing this

The tracing script, the palette generator and the sheet builder were written and run in the
session scratchpad and are **not committed** (RULE-015 — this work item changes no code; the
WI-100 precedent). Reproducing them:

- Trace: `potrace.Bitmap(alpha_array < peak_alpha // 2)`, walk `.trace()`'s curves, corner
  segments emit two `L`s (to the corner point, then the endpoint), Bezier segments emit one
  `C`; scale by `100 / max(source_w, source_h)`.
- Palette: per kind, an HSL background and a darker/hue-shifted HSL ink, then the background's
  lightness is walked up in 1% steps until `contrast(bg, ink) >= 3.3` **and**
  `contrast(blend(ink, bg, 0.55), '#111111') >= 3.3` both hold.
- Sheet: inline SVG per kind — a flat-top hexagon (`hexCorners`' own convention: first corner
  due east) filled with `color`, the traced path scaled into a `size * 1.1` box at `ink`
  opacity 0.55, a stand-in contents icon (`danger.svg`'s path, reused for its middling
  density) scaled into a `size * 0.9` box at full black — at `size` 48 and `size` 140.
