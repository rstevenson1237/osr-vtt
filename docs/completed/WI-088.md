# WI-088 — `RULE-AMENDMENT`: RULE-009 states the backend per build

**Spec:** — (rule) · **From:** IN-065 · **Agent:** `claude-code` · **Model:** `opus` ·
**Effort:** medium · **Closed:** 2026-08-18

RULE-009 stated the backend as a single fact — "Firebase serverless on the **Spark** tier
… Anonymous Auth (+ optional Google link) = identity" — so IN-065's local mode, a build
with no Firebase at all, contradicted the rule as written before it could be designed
(DEC-074). Per the `RULES.md` preamble and RULE-017 the amendment is its own change, its
own branch and its own `RULE-AMENDMENT:`-prefixed commit, landing before any of the
implementation: the same shape WI-037 (RULE-006, per grid kind) and WI-065 (RULE-010, per
tier) took. This is that amendment and nothing else — no `LocalStore`, no build mode, no
lobby; those are WI-089.

**Changes made.**

- `RULES.md` — RULE-009 is now **"Backend, per build"**. The hosted build's backend is
  restated **word for word** and unchanged. A **local** build is admitted beside it: no
  backend, no identity provider, no network; the campaign is a `.vttcamp` file on disk and
  the store is backed by that file (SPEC-041); no Firebase SDK and no project identifier in
  its output, as a build-output assertion rather than a comment; explicitly not an offline
  mode, a cache or a sync layer, so admitting one is a further amendment rather than a
  reading of this one. Two paragraphs then state the consequences the rule owns: **what the
  split scopes** — RULE-003, RULE-004, RULE-011 and RULE-012 describe Firebase services or
  a join path a local build does not have and are scoped to the hosted build, none weakened
  and none relaxable in a hosted build on the grounds that another build does not reach it —
  and **what it strengthens**: RULE-001 (the local store passes the same contract suite or
  local mode is a fork this rule does not admit) and RULE-014 (locally the `.vttcamp` is the
  database, so a lossy round-trip loses the campaign). RULE-010 is noted as unaffected: it
  constrains the hosted build, and a local build has no server to put a function on. The
  amendment is recorded in place in the house `> **Amended by WI-nnn (date).**` form.
- `docs/spec/SPEC-041.md` — the header's **Blocked on WI-088** note is replaced by
  **Unblocked 2026-08-18**, naming the amendment and stating that WI-089 may begin. No other
  line of the spec changes.
- `PLAN.md` — WI-088 removed from §2; the chain paragraph records the close and what the
  amended rule says; the "all eight gates cleared" paragraph reads in past tense with the

- `PLAN-COMPLETED.md` — the WI-088 row added to §3.
- `docs/completed/WI-088.md` — this file.
