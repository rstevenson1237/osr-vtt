# WI-158 — "Now on: <map>" notice

SPEC-054 §14. Part of Batch 1 (WI-152–158) — one pull request, one combined summary.

**Changes made**

- `map-tool-controller.svelte.ts` — new `locallySetMapId` field: set by whichever
  control switches the active map, just before calling `setActiveMap`.
- `MapsPanel.svelte`, `BattleSheet.svelte` (`start()`, starting a battle map) — set
  `mapCtrl.locallySetMapId` before their `setActiveMap` call.
- `RoomShell.svelte` — the existing map-resubscribe effect now also decides
  `isRemoteSwitch` (a real map change, not this seat's first map, and not this client's
  own switch) and, on the new map's first snapshot, shows a 4s "Now on: `<map name>`"
  notice if so.

**Visible behavior changes** — when the referee (or any client) switches the active
map, every *other* client shows a transient "Now on: `<map name>`" notice; the client
that made the switch does not. Not covered: exiting a battle map
(`exitBattleMap`, which doesn't report the map it returns to) shows the notice to the
switching client too — a minor gap, not tracked as a separate intake item given the
feature is a first-run cue, not load-bearing.

**How to verify** — `pnpm verify:all` green. Manually: two browser contexts in the same
room, referee switches the active map from the Maps panel — the other client shows the
notice, the referee's own client doesn't.

**Deviations** — none.
