# WI-156 — Room not found; Reconnecting…

SPEC-054 §10. Part of Batch 1 (WI-152–158) — one pull request, one combined summary.
**States half only** — see Deviations.

**Changes made**

- `RoomShell.svelte` — new `roomLoaded` flag, set the first time `subscribeRoom`'s
  callback fires (Firestore's `onSnapshot` always fires at least once, with `null`
  either way — this is what tells "not yet loaded" apart from "confirmed gone" without
  a new store method). Template gate: `!roomLoaded` → "Loading room…" (unchanged);
  `roomLoaded && room === null` → new **Room not found** panel with a link back to the
  lobby; otherwise the existing join-gate/shell flow.

**Visible behavior changes** — a room id whose document doesn't exist now shows "Room
not found" with a link back to the lobby, instead of "Loading room…" forever.

**How to verify** — `pnpm verify:all` green. Manually: navigate to `#/r/does-not-exist`
and confirm "Room not found" renders (not an infinite loading state).

**Deviations — scope reduced, re-triaged (RULE-015).** The Reconnecting… banner
(§10's second bullet) needs a connectivity signal — RTDB `.info/connected` or
equivalent — that no `CampaignStore` method exposes today; adding one is a new method
on the shared contract (RULE-001, Deceptive trigger), out of scope for this Simple
item. Stopped and logged as **IN-215** rather than widening the item or guessing at an
implementation. IN-168's own classification anticipated exactly this possibility
("if detecting 'not found' needs one, that half is re-triaged") — it turned out to be
the other half that did.
