## WI-129 — Road and River lose the shade selector; the shade is the width

**Status: Completed 2026-09-14**

The shade index a line commits is now derived from the width index it was drawn with —
thin is the kind's lightest shade, thick its darkest — instead of a second control.

### Changes made

- **`apps/web/src/lib/shell/map-tool-controller.svelte.ts`** — removed
  `selectedHexLineShade`; doc comment on `selectedHexLineWidth` notes it also indexes the
  shade (SPEC-047 §14). **`MapToolPalette.svelte`** — dropped the `bind:selectedHexLineShade` wire.
- **`apps/web/src/lib/components/MapToolbar.svelte`** — removed the `selectedHexLineShade`
  prop/type, `activeHexLineShades`, and the `Shade:` swatch-row markup
  (`data-testid="hex-line-shade"`/`hex-line-shade-{i}`) with its `.swatch-row`/`.swatch`
  CSS. The Road/River param group is Width only.
- **`apps/web/src/lib/components/VectorMapView.svelte`** — both `store.addHexLine`'s
  write and `hexLinePreview()`'s ghost now derive `shade` from `selectedHexLineWidth`.
- **`README.md`** — the hex-overlay preview note corrected: only the width is chosen; the
  shade follows (SPEC-047 §14).
- **`docs/spec/SPEC-047.md`** §14 already documented this behaviour; no change needed.

### Visible behavior changes

The Road/River toolbar panel no longer shows shade swatches — only Width remains. Drawing
a line now derives its colour tone from the chosen width (thin = lightest, thick =
darkest). Lines already drawn are unaffected: `HexLine.shade` is unchanged in meaning and
stored value.

### How to verify

1. `pnpm verify` — lint, typecheck, unit all green.
2. On a hex map, select Road or River: the parameter row shows only Width, no shade
   swatches.
3. Draw a thin line, then a thick line of the same kind: thin renders in the kind's
   lightest shade, thick its darkest — both preview and committed line.

### Deviations

None.
