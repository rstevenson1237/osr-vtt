# WI-169 — One `actorPresentation` resolver (identical outputs)

SPEC-055 §4. Part of **Batch 3** (WI-166, WI-167, WI-168, WI-169) — one pull request,
one combined summary.

## Changes made

- `apps/web/src/lib/tokens/actor-presentation.ts` (new) — `actorPresentation(actor,
  players, groups)` returns `{ name, letter, color, portrait }` for an `ActorRef`
  (`{ kind: 'token'; token: Token }` or `{ kind: 'side'; groupId: string }`). The `name`
  algorithm moved here from `tokenLabel` (`encounter/labels.ts`) verbatim; `letter` reads
  `Token.letter` directly (no seat-derived fallback — matches `letterStyleFor`'s existing
  contract); `color`/`portrait` read `Token.color`/`Token.imageRef` for a token, or
  `groupColor(groupId)` for a side.
- `apps/web/src/lib/tokens/actor-presentation.test.ts` (new) — asserts `actorPresentation`
  agrees with `tokenLabel`/`refLabel` for every case those already cover.
- `apps/web/src/lib/encounter/labels.ts` — `tokenLabel`/`refLabel` are now thin wrappers
  over `actorPresentation` (kept as the entry point for the "no token at all" case
  `actorPresentation` doesn't model, and for backward compatibility — `CombatTracker`/
  `TurnStrip` still call `refLabel`, unchanged). `encounter/labels.test.ts` passes
  unmodified.
- **Found and logged, not fixed (SPEC-055 §4):** `creatureLabel`/`creatureDisplayName`
  (`tokens/labels.ts`, used by `CharacterDock`'s creature header and `EncounterBoard`'s
  card name) run a second, disagreeing name algorithm — no `Token.letter` fallback, and
  an art-only fallback with no id suffix. Logged as **IN-218**; both call sites keep
  calling `creatureDisplayName` directly, per SPEC-055 §4's "today's per-surface answer
  is kept." `letterStyleFor` (`tokens/letter-style.ts`) is a render-detail function (font
  size, stroke, fill by mode), not an identity lookup, and stays a direct `Token.letter`
  reader — folding it in would require inventing a letter-absence policy this item does
  not have standing to decide. `resolveCharacterColor`/`assignedCharacterColor`
  (`character-color.ts`) are seat/profile-keyed, not token-keyed (used by `CharacterDock`
  and dice-roll colouring, neither of which always has a `Token` at hand), and are a
  different question from a token's presentation — left untouched.
- `INTAKE.md` — new row IN-218 (§1.1) plus its prose entry ("Batch 3 finding
  (2026-09-24)").
- `README.md` — "Creature names and symbols" section corrected: it previously claimed
  the initiative order "cannot disagree" with the Encounter Board / quick-sheet header,
  which was already untrue before this work item (the two algorithms always differed);
  now documents the real disagreement and points to IN-218.

## Visible behavior changes

None. `tokenLabel`/`refLabel` produce byte-identical output to before (verified by the
unmodified `encounter/labels.test.ts` passing unchanged); `creatureLabel`/
`creatureDisplayName`/`letterStyleFor`/`resolveCharacterColor` are untouched.
