# WI-073 — Seed defaults

**Status:** Completed 2026-08-11
## Changes made

- **`profile/starter-template.ts`** — `STARTER_PROFILE_TEMPLATE` changed from
  `[Name (text), Torches (counter), Combat (roll d6)]` to `[HP (number), To Hit (roll d20),
  Initiative (initiative d6)]`. HP has no default; To Hit/Initiative seed d20/d6.
- **`packages/shared/src/types.ts`** — `DEFAULT_BACKGROUND` changed from `{ ref:
  STARTER_MAP_REF }` to `null`. New maps show bare rock by default.
- **`campaign-store.contract.ts`**, **`migrations/index.test.ts`** (v17, v9→v10),
  **`portability/vttcamp.test.ts`** — updated to expect `null` background.
- **`PLAN.md`** — WI-073 moved from §2 to §3.
- **`session-config.spec.ts`** (Gate 19) — expects a fresh room's background to read
  "None (bare rock)" with Remove disabled.
- **`two-context.spec.ts`**, **`dice-profiles.spec.ts`** — field-id refs updated to
  `hp`/`toHit`/`initiative`; `two-context` rolls `initiative` (matches the default
  `osr-d6` convention); `dice-profiles` asserts the GM's HP field as `'0'`, not `''`.
- **`encounter-board-v2.spec.ts`** — pinned-field test switched from `torches` to `hp`.

## Visible behavior changes

A GM's new room shows no background (bare rock, addable via Assets) instead of the bundled
starter map. New rooms seed HP/To Hit (d20)/Initiative (d6) instead of Name/Torches/Combat
— still editable in session settings. Migrated pre-multi-map rooms also no longer default
to the starter map background.

## How to verify

1. Create a new room — map shows bare rock, not the starter map.
2. Session settings — template fields are HP/To Hit/Initiative.
3. `pnpm test:unit --exclude "**/account-recovery*.test.ts"` — 599 tests pass.
4. `pnpm test:all:emulators` — affected e2e specs pass (Changes made lists them).

## Deviations

The seed-default change (RULE-015's unblock exception) rippled into e2e tests hard-coding
the retired field ids or the starter-map assumption; fixed here since the suite could not
stay green otherwise (see Changes made). One unrelated pre-existing flake was also fixed:
`group-ownership.spec.ts`'s `tryDrag` raced the drag-end write; changed to `expect.poll`.
