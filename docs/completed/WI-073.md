# WI-073 — Seed defaults

**Status:** Completed 2026-08-11

## Changes made

- **`apps/web/src/lib/profile/starter-template.ts`** — Updated `STARTER_PROFILE_TEMPLATE` from `[Name (text), Torches (counter), Combat (roll d6)]` to `[HP (number), To Hit (roll d20), Initiative (initiative d6)]`. The HP field has no default; To Hit and Initiative seed d20 and d6 respectively.

- **`packages/shared/src/types.ts`** — Changed `DEFAULT_BACKGROUND` from `{ ref: STARTER_MAP_REF }` to `null`. New maps now show bare rock by default instead of the bundled starter map. Updated the comment to reflect WI-073 superseding the R15/WI-19 assumption.

- **`packages/shared/src/store/campaign-store.contract.ts`** — Updated the test `"a freshly created room has an activeMapId whose map seeds the starter map as its background (R15/WI-19, R17.3)"` to expect null background instead of the starter map, and renamed it to reflect the new behavior.

- **`packages/shared/src/migrations/index.test.ts`** — Updated two migration tests to expect `null` for the background instead of `{ ref: STARTER_MAP_REF }`:
  - The v17 room migration test (line 505)
  - The v9→v10 migration test (line 271)

- **`packages/shared/src/portability/vttcamp.test.ts`** — Updated two vttcamp round-trip tests to expect `null` for background (lines 407 and 446), since old exports being migrated up now backfill with `null` instead of the starter map.

- **`PLAN.md`** — Marked WI-073 as completed; moved it from §2 (upcoming) to the completion entry in §3.

## Visible behavior changes

**New maps:** When a GM creates a new room, its first map now has no background (bare rock) instead of the bundled starter map. The GM can add a background later via the Assets activity.

**Character template:** New rooms now seed three core fields — HP (Number), To Hit (Roll d20), Initiative (Initiative d6) — instead of Name (text), Torches (counter), Combat (roll d6). The Profile Template is still editable in session settings.

**Migrations:** Rooms migrated from pre-multi-map versions no longer receive the starter map as a default background; they also show bare rock until a GM configures one.

## How to verify

1. **Create a new room** — verify that the map shows bare rock background, not the starter map.
2. **Check character template in session settings** — verify that the three template fields are HP (Number), To Hit (Roll d20), and Initiative (Initiative d6).
3. **Run the test suite** — `pnpm test:unit --exclude "**/account-recovery*.test.ts"` passes with 599 tests (the account-recovery test has a pre-existing Firebase network issue unrelated to these changes).

## Deviations

None. All changes match the approved plan.
