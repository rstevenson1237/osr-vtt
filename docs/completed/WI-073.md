# WI-073 — Seed defaults

**Status:** Completed 2026-08-11

## Changes made

- **`apps/web/src/lib/profile/starter-template.ts`** — Updated `STARTER_PROFILE_TEMPLATE` from `[Name (text), Torches (counter), Combat (roll d6)]` to `[HP (number), To Hit (roll d20), Initiative (initiative d6)]`. The HP field has no default; To Hit and Initiative seed d20 and d6 respectively.

- **`packages/shared/src/types.ts`** — Changed `DEFAULT_BACKGROUND` from `{ ref: STARTER_MAP_REF }` to `null`. New maps now show bare rock by default instead of the bundled starter map. Updated the comment to reflect WI-073 superseding the R15/WI-19 assumption.

- **`packages/shared/src/store/campaign-store.contract.ts`** — Updated the test `"a freshly created room has an activeMapId whose map seeds the starter map as its background (R15/WI-19, R17.3)"` to expect null background instead of the starter map, and renamed it to reflect the new behavior.

- **`packages/shared/src/migrations/index.test.ts`** — Updated two migration tests to expect `null` for the background instead of `{ ref: STARTER_MAP_REF }`:
  - The v17 room migration test (line 505)
  - The v9→v10 migration test (line 271)

- **`packages/shared/src/portability/vttcamp.test.ts`** — Updated two vttcamp round-trip tests to expect `null` for background (lines 407 and 446), since old exports being migrated up now backfill with `null` instead of the starter map.

- **`PLAN.md`** — Marked WI-073 as completed; moved it from §2 (upcoming) to the completion entry in §3.

- **`apps/web/tests/e2e/session-config.spec.ts`** (Gate 19) — Updated to expect a fresh room's background to read "None (bare rock)" with Remove disabled, then exercises Change → Remove from that starting point, instead of assuming the starter map was already set.

- **`apps/web/tests/e2e/two-context.spec.ts`** — Updated all references to the retired `name`/`torches`/`combat` fields to the new `hp`/`toHit`/`initiative` fields. The roll-and-classify assertion now rolls the `initiative` field (default d6, matched by the room's default `osr-d6` roll convention) rather than `toHit` (default d20, which has no matching convention and would always render an empty `resultClass`).

- **`apps/web/tests/e2e/dice-profiles.spec.ts`** — Same field-id migration (`name` → `hp`, `combat` → `toHit`). The GM's own untouched HP field asserts value `'0'`, not `''`: a `number`-type field with no `default` falls back to `defaultForType('number') = 0` (`profile-view.ts`), unlike the old `text`-type `name` field which fell back to `''`.

- **`apps/web/tests/e2e/encounter-board-v2.spec.ts`** — The pinned-field test used the retired `torches` counter (seeded default `3`) as its example; switched to pinning `hp`, with the player explicitly setting a value (`5`) first since `hp` has no seeded default to assert against.

## Visible behavior changes

**New maps:** When a GM creates a new room, its first map now has no background (bare rock) instead of the bundled starter map. The GM can add a background later via the Assets activity.

**Character template:** New rooms now seed three core fields — HP (Number), To Hit (Roll d20), Initiative (Initiative d6) — instead of Name (text), Torches (counter), Combat (roll d6). The Profile Template is still editable in session settings.

**Migrations:** Rooms migrated from pre-multi-map versions no longer receive the starter map as a default background; they also show bare rock until a GM configures one.

## How to verify

1. **Create a new room** — verify that the map shows bare rock background, not the starter map.
2. **Check character template in session settings** — verify that the three template fields are HP (Number), To Hit (Roll d20), and Initiative (Initiative d6).
3. **Run the unit suite** — `pnpm test:unit --exclude "**/account-recovery*.test.ts"` passes with 599 tests (the account-recovery test has a pre-existing Firebase network issue unrelated to these changes).
4. **Run the affected e2e specs against the emulator** — `two-context.spec.ts`, `group-ownership.spec.ts`, `dice-profiles.spec.ts`, `encounter-board-v2.spec.ts`, and `session-config.spec.ts` all pass under `pnpm test:all:emulators` (or `firebase emulators:exec` + `playwright test <files>` directly).

## Deviations

The seed-default change (RULE-015's "genuinely required to unblock" exception) rippled into e2e tests that hard-coded the retired starter template's field ids (`name`, `torches`, `combat`) or assumed a fresh room's background was the starter map. These were fixed as part of this work item rather than logged as separate intake items, since the suite could not stay green otherwise:

- `session-config.spec.ts` Gate 19 — background assumption updated (see Changes made).
- `two-context.spec.ts`, `dice-profiles.spec.ts`, `encounter-board-v2.spec.ts` — field-id references updated to `hp`/`toHit`/`initiative` (see Changes made).

One unrelated, pre-existing flake surfaced while stabilizing the above and was also fixed here, since it was blocking a green CI run on this PR: `group-ownership.spec.ts`'s `tryDrag` helper read the token's position readout immediately after `mouse.up()`, racing the drag-end write's Firestore round-trip. Changed to a bounded `expect.poll` that tolerates "no change" (a denied drag legitimately never changes) while giving an allowed drag time to settle. This file is otherwise untouched by WI-073 and the fix is not itself a WI-073 change — it's the one-exception unblock, called out here for visibility.
