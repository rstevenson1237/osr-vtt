## Changes made

- `apps/web/src/lib/map/map-hex.svelte.ts` (new): the `HexAuthoringController` seam. It owns
  the three hex documents (`tiles`, `symbols`, `lines` — `$state`) and `revealed`,
  `selectedTile`, `hoverNote`, `hoverNoteText` (`$derived`/`$state`), and the per-gesture
  fields (the Road/River run, the pointer's last world pixel, the fog stroke and the pending
  fog stroke) as plain fields, as they were. It carries `hexAt`, `hexSymbolPointFor` and
  `hexLinePointFor` — the only place a pointer becomes an axial coordinate — plus Select's hex
  pick, the Symbol, Road/River, Label, Terrain and Reveal/Hide click tools, `pointerDown`/
  `pointerMove`/`pointerUp`/`pointerOut`/`cancel`/`finishLine`, `subscribe()` (the three hex
  listeners), the hex-tile sheet's `setTerrain`/`setContents`/`setNote`, `revealAll`/
  `resetFog`, `dropFoggedSelection`, `linePreview()` and `fogView()` for the composers. It is
  handed `hexSize` and never a lattice conversion or `cellSize`.
- `apps/web/src/lib/components/VectorMapView.svelte`: holds `hex` (`null` on a square map),
  constructed in `onMount` only when `hexGrid` is set, and deletes `hexTiles`, `hexSymbols`,
  `hexLines`, `hexCollecting`, `hexHoverPx`, `hexFogStroke`, `hexFogPending`, `hexFogOn`,
  `hexRevealed`, `hexFogAllowed`, `hexHiddenFromMe`, `selectedHexTile`, `hoverHexNote`,
  `hoverHexNoteText`, `hexAt`, `hexSymbolPointFor`, `hexLinePointFor`, `hexLinePreview`,
  `handleHexPointerDown`, `placeHexSymbolAt`, `addHexLineVertex`, `handleHexLabelClick`,
  `placeHexTerrainAt`, the hex fog functions, `updateHoverHexNote`, the hex halves of
  `revealAll`/`resetFog`/`finishMultiClick`/`cancelStroke`, the three hex subscriptions and
  the three sheet-handler assignments. `wireStagePointerEvents` calls `hex?.pointerDown`
  where `handleHexPointerDown` sat (it also takes the five hex-only tool branches, which the
  ladder tested later), `hex?.pointerMove` and `hex?.pointerUp` where the hex fog branches
  were, and `hex?.pointerOut`. The composers and the `map-hex-*` readouts read `hex?.tiles`,
  `hex?.symbols`, `hex?.lines`, `hex?.revealed`, `hex?.fogView()` and `hex?.linePreview()`;
  Measure is handed `hex?.hexAt`. Unused imports removed.
- `apps/web/src/lib/map/map-draw.svelte.ts`: the `hexAt` dep's comment no longer says WI-228
  will repoint it; no code change.

## Visible behavior changes

None. Hex picking, the click tools, the note hover, hex fog and the three hex layers behave as
before; a square map never builds the controller.

## Deviations

- SPEC-066 §3 lists `mapCtrl` as handed; the controller is handed the four fields it uses as
  `tools: HexToolState` (the shared controller satisfies it), so the seam names what it reads.
- The effect that drops a player's fogged selection and the sheet's `selectedHexTile` mirror
  stay as `$effect`s in the component, calling `hex?.dropFoggedSelection()` and reading
  `hex?.selectedTile`: a class built in `onMount` cannot own effects. The logic is the
  controller's; only the trigger stayed. The three `mapCtrl.onSetHex*` handlers moved from an
  `$effect` to `onMount`, where `hex` is built — they had no reactive input but `mapId`,
  which is constant for the component's life.
- Measure is handed `(worldPx) => hex?.hexAt(worldPx) ?? null` rather than `hex?.hexAt ?? null`:
  `MapDraw` is constructed before `onMount` builds the controller, so a captured value would
  be `null`. The lambda resolves the controller at call time.
- Select's background pick and its "drop the background pick" step are handed to the
  controller as two callbacks (`pickBackground`, `dropBackgroundPick`), because the selection
  model stays in the component until WI-229.
- `pointerUp` adds one microtask `await` on the stage's release path when no fog stroke is
  open; the path was already inside an async function.
- No RULE-015 unblock or Deviations-budget fix.
