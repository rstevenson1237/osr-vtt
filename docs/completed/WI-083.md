## Deviations

- **Lead 1 (`applyBackgrounds`'s all-or-nothing texture load) was confirmed by code
  reading, not forced live**, as the plan anticipated might be necessary. The Assets
  activity's "By URL" flow already validates an image loads (`<img>` `onload`/`onerror`)
  before letting the referee save it, so a persistently-broken ref cannot be placed
  through the current UI — the naive repro (save a 404 URL, place it, drag another
  background) never got past the picker's own guard. The hazard itself is still real
  (a saved ref that validates at add time can go dead later — host outage, revoked link
  — and the `Promise.all` in `applyBackgrounds` has no try/catch), so it is recorded as
  IN-068 rather than being discarded; forcing a live repro would need either intercepting
  the network layer for a second load of the same URL or writing directly to the store,
  either of which is investigation scaffolding beyond a medium-effort budget.
- **Lead 3 (`nativeAspect` reading a `Texture.EMPTY` 1×1 fallback) was discarded**, not
  confirmed or logged as an intake item: background sprites are only created after
  `applyBackgrounds` has awaited the real texture (no placeholder-texture phase like door
  sprites have), so the fallback path only ever computes the same aspect
  `fitBackgroundToGrid` already placed the image at.
- **Lead 4 was extended beyond its original wording.** IN-060 asked whether the alignment
  overlay reaches a hex map; reading the code showed the *entire* background feature
  (add, select, move, resize, and the overlay) is reachable on a hex map, not only the
  overlay — logged as IN-069 accordingly.
- **Lead 2 (a Fit-to-grid background swallowing the whole canvas for every map tool) was
  not re-investigated in depth.** IN-060's own text already names this as the exact
  defect IN-061 – IN-063/WI-084 – WI-086 exist to fix, so confirming its mechanism
  further here would not change what happens next.
- **The reproduction spec (`apps/web/tests/e2e/_wi083-repro.spec.ts`) was written,
  used, and then deleted before this summary was finalised.** It was scratch scaffolding
  for this investigation, not a lasting acceptance test — it duplicated
  `backgrounds.spec.ts`'s setup with console/page-error capture bolted on, and neither of
  the two findings it surfaced needs a standing regression test in this work item (they
  are unfixed and awaiting triage, per RULE-015).
