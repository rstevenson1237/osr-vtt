## WI-036 — Battle map: the referee quick sheet, Start and Exit

**Spec:** SPEC-029 §5 · **From:** IN-010 · **Closed:** 2026-08-10 · `claude-code`, `sonnet`,
effort `medium`

### Changes made

- **`packages/shared/src/store/campaign-store.ts`** — `BATTLE_MAP_SOURCE_COLLECTIONS`
  (`EXPORTED_MAP_COLLECTIONS` minus `fogRegions` — SPEC-029 §2's "background, floor and
  overlay", not fog), and two new `CampaignStore` methods: `createBattleMap(roomId,
  sourceMapId, rect)` (cuts a new `GameMap` carrying the source's
  `grid`/`background`/`measure`/`gridSettings` plus `battle: { sourceMapId, rect }`, copies
  every `BATTLE_MAP_SOURCE_COLLECTIONS` doc over, and does not touch `Room.activeMapId` —
  mirrors `createMap`) and `exitBattleMap(roomId, mapId)` (reads `battle.sourceMapId`,
  switches `Room.activeMapId` back to it, and deletes the temporary map in one call, so a
  caller can never do one half without the other; throws if `mapId` carries no `battle`
  marker).
- **`packages/shared/src/store/memory-store.ts`** / **`firebase-store.ts`** — both
  implement `createBattleMap`/`exitBattleMap` (RULE-001). `FirebaseStore`'s reads the
  source map and its subcollections with one-shot `getDoc`/`getDocs` calls and writes the
  copy in `FIRESTORE_BATCH_LIMIT`-sized batches, the same discipline `importRoom` already
  uses for a whole-room copy; `MemoryStore`'s is a direct bucket-to-bucket `entries()` copy.
- **`packages/shared/src/store/campaign-store.contract.ts`** — three new tests under "maps
  manager": `createBattleMap` carries the `battle` marker, copies floor/wall geometry,
  excludes fog, and never touches `activeMapId`; `exitBattleMap` switches active back and
  deletes the temporary map; `exitBattleMap` rejects a map with no `battle` marker. All run
  against both `MemoryStore` and `FirebaseStore`.
- **`apps/web/src/lib/map/vector-engine.ts`** — `exportPng` gained three optional inputs:
  an explicit `frame` (world pixels, overriding the default "union of `regions`' bboxes"
  frame), `hideGrid` (skips the one-shot export grid regardless of `maxLayer`), and
  `backgroundColor` (composited behind the extracted canvas by a new pure
  `compositeBackgroundColor` helper). This is SPEC-029 §2's noted `exportPng` gotcha: a
  solid `GameMap.background: { color }` lives on the renderer's clear colour, never a
  `layers.background` sprite, so a plain extract would miss it. The existing "Download map
  as PNG" call site is unchanged (all three are optional, defaulting to old behaviour).
- **`apps/web/src/lib/shell/map-tool-controller.svelte.ts`** — `onExportBattlePreview(rect):
  Promise<Blob>`, wired by `VectorMapView` the way `onExportPng` is; reset to a rejecting

- **`apps/web/src/lib/components/VectorMapView.svelte`** — `exportBattlePreview(rect)`:
  calls `engine.exportPng` with the candidate rect as an explicit `frame`, `maxLayer:
  'overlay'`, `hideGrid: true`, and the map's solid background colour if it has one; wired

- **`apps/web/src/lib/components/shell/sheets/BattleSheet.svelte`** (new) — the quick

### Visible behavior changes

A referee can now cut a battle map end to end: draw a capture rect with the Capture tool,
open the new **Battle map** quick sheet (referee-only, next to Room in the rail), see a
live preview of the captured area, and click **Start**. Every player's client switches to
the new, smaller-scale map immediately — same tokens, encounter, dice and log, a doubled
grid, a camera that cannot leave the captured rect, and only the View tools available.
Clicking **Exit** switches everyone back to the source map and deletes the temporary one;
nothing about it survives a `.vttcamp` export (already true since WI-033).

### Deviations

- **`SPEC-029 §2` is not cited by WI-036's own gate** (only §5 is), and `INTAKE.md`'s
  IN-048 — still open, unscheduled — flags exactly this: the background/floor/overlay copy
  semantics, the `exportPng`-reuse preview, and the background-colour compositing gotcha
  are all §2 content with no work item formally attached. They were built anyway: §5's
  "Start... performs the map change" cannot mean anything without them, and WI-034/WI-035
  already built render-time behaviour (the capture tool, the bounded camera, the
  view-tools-only palette) on the same unstated assumption. This mirrors the precedent
  those two work items already set rather than introducing new scope; IN-048's own
  citation/gate bookkeeping is left untouched, since resolving it isn't this work item's
  call to make.
- **`fogRegions` is deliberately not copied.** SPEC-029 §2 lists only "background, floor
  and overlay layers"; a battle map is left with no `fog` config at all (same as any map
  created before fog existed), so it renders unfogged regardless of the source's fog state.
  Not spelled out in the spec text, but the narrowest reading consistent with what is.
- **The new map's name is `${source.name} — Battle`.** SPEC-029 doesn't name a convention;
  this is legible in the Maps manager list without hiding the temporary map from it (no
  work item asked for that, and doing so would need its own gate — deleting or renaming it
  through the Maps manager instead of Exit is a pre-existing GM footgun this item didn't
  introduce or worsen).
- **One `pnpm verify:all` run, plus a second targeted emulator pass.** The full run was
  kicked off before `battle-map-lifecycle.spec.ts` existed (writing it, and the doc
  updates, took long enough that starting the full suite first was the cheaper order), so
  it does not include the new spec. Both runs are quoted under How to verify.
