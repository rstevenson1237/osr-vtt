# WI-229 — The selection becomes one `MapSelection`; the Select gesture leaves `VectorMapView` for `SelectionController`

**Closed 2026-10-20.** From IN-205. SPEC-067, SPEC-060 §2–§5, DEC-134 (a). Model target
`sonnet`, run on `sonnet`; effort `high`.

---

## Changes made

- `apps/web/src/lib/map/map-selection.svelte.ts` (new): `MapSelection`, the four mutually
  exclusive slots — `handles` and `objects` (`$state.raw`), `tokenIds` and `backgroundId`
  (`$state`) — with the writers `selectHandles`, `selectObjects`, `selectGeometry`,
  `selectTokens`, `selectBackground` and `clear`, each setting its own slot and emptying the
  rest. `object` and `count` are `$derived`; `count` takes a handed `backgroundSelectable(id)`
  so it never resolves a background itself. It holds no store, engine or coordinate.
- `apps/web/src/lib/map/map-select.svelte.ts` (new): `SelectionController` — the pick priority
  (handle, then object, then the background seam's gesture, then lasso), the vertex and
  whole-object drags, the lasso and its token catch, `rotateSelectedObject`, `deleteSelection`,
  `cancel()`, and `displayState()`/`displayOverlayState()` over `drag-display.ts`. It exposes
  `pointerDown/pointerMove/pointerUp` and `activeDrag`, `objectDrag`, `lasso`, `hoverHandle`,
  `busy`. Handed `toLatticeSnapped` (no axial conversion, RULE-006), the live arrays as getters,
  the handed background seam, `applyOp` and `focusToken`.
- `apps/web/src/lib/components/VectorMapView.svelte`: constructs `selection` and `select`; deletes
  `selectedHandles`, `selectedObjects`, `selectedBackgroundId`, `selectedTokenIds`,
  `selectedObject`, `selectionCount_`, `syncSelectionCount`, `activeDrag`, `objectDrag`, `lasso`,
  `hoverHandle`, `ActiveDrag`/`ObjectDrag`, `objectCatalog`, `beginSelectGesture`,
  `beginHandleDrag`, `updateSelectDrag`, `endSelectDrag`, `finishLasso`, `beginObjectDrag`,
  `updateObjectDrag`, `endObjectDrag`, `rotateSelectedObject`, `deleteSelection`,
  `displayState` and `displayOverlayState` (about 310 lines). The Select branches of
  `onPointerDown/Move/Up` are one call each into the controller. The token sprite's click and
  Shift-click write `selection.selectTokens(...)` in place of its three named clears; the
  background seam's `onPick` is `selection.selectBackground`; the hex controller's
  `dropBackgroundPick` is `selection.dropBackground`; `cancelStroke` clears the three owners
  through `clearSelection()` (`select.cancel()`, `selection.clear()`, `bgCtrl.cancel()`).
  Composers and markup read `selection.*` and `select.*`. Unused imports removed.
- `apps/web/src/lib/map/map-selection.test.ts` and `map-select.test.ts` (new): 35 tests with no
  browser. `MapSelection`: every writer empties the other slots, `dropBackground` touches only
  its own, `object` is the single selected object, `count` follows a token click and a handed
  getter. `SelectionController`, with a fake `invalidate`, a `MemoryStore` with its writes spied
  and a recording `applyOp`: pick priority, the lasso starting by dropping a held background,
  the vertex drag (one op on release, stored wall untouched, a door redraws `overlay`), the
  symbol and room-label drags (one write on release), the View lock arming nothing, the lasso's
  token and geometry catches and its room-label publish, the background gesture routing, hover,
  Rotate (symbol, door, View lock, several selected), Delete (one batched op, selection cleared,
  nothing selected writes nothing) and `cancel`.
- Docs (RULE-018): `README.md` → "Seam controllers" names the fifth seam, "The selection model"
  opens with `MapSelection` and the Multi-token select paragraph points at it, and the
  Background management note says the pick writes through `MapSelection`;
  `docs/spec/SPEC-067.md` and the `SPEC.md` index move Draft → Active and record the points
  below; `PLAN.md`, `PLAN-COMPLETED.md` and `INTAKE.md` bookkeeping.

## Visible behavior changes

None for a user. The test-only `selection-count` readout (behind `VITE_E2E_READOUTS`) is now
`$derived`, so a token click after a geometry pick drops it to 0 at once instead of leaving it
stale until the next pointer event (SPEC-067 §2); no spec asserted the stale value.

## Deviations

- `MapSelection.dropBackground()` is a seventh writer that SPEC-067 §2 did not list. Two callers
  need to drop the background pick and leave the other three slots alone: the lasso start in
  `beginSelectGesture` (the other slots stay until the release decides) and the hex controller's
  `dropBackgroundPick` (WI-228, written after SPEC-067). Using `selectBackground(null)` or
  `clear()` would have changed what survives. SPEC-067 §2 and §4 now name it. Unblock exception.
- `SelectionController` is handed `toLatticeSnapped` and not `toLatticeRaw`: every Select pick and
  drag runs on the snapped point, so a raw conversion would be unused. SPEC-067 §3 reworded.
- `vertexAttraction()` reads `select.activeDrag !== null`, not `select.busy`. SPEC-067 §3 said
  `busy` replaces the `vertexAttraction` read too, but an object drag must not attract to a
  vertex (it would change a Free-snap symbol drag). `busy` replaces only the label seam's guard.
  SPEC-067 §3 reworded.
- The controller's drag, lasso and hover fields are plain fields, not `$state` (SPEC-067 §3 said
  `$state` fields, SPEC-060 §2's default): they are per-frame render bookkeeping read inside
  tracking effects and invalidated explicitly, exactly as in the component before and as in
  `MapBackgrounds` (WI-227). SPEC-067 §3 now says so.
- `deleteSelection` clears the selection, lasso, object drag and background drag but, as before,
  does not null an already-armed vertex drag; `cancel()` (Escape) nulls all three. Preserves the
  old behaviour exactly.
- No RULE-015 Deviations-budget fix was made.
