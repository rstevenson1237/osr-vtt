# WI-223 — Yjs incremental transport

SPEC-065, DEC-132 (a). IN-210. Model `opus`, effort high. Changes an RTDB structure
(RULE-003), the `subscribeYState` guarantee (RULE-001) and migrates a stored node in place
(RULE-007). No rules, Firestore, `.vttcamp`, schema-version or testid change.

## Changes made

- `packages/shared/src/store/firebase-store.ts` — the Yjs node `rooms/{roomId}/yjs/{docName}`
  is now a snapshot `s` plus a `push()` log `u` (SPEC-065 §2).
  - `mergeYUpdate` pushes one update under `u` (no transaction), counts its own pushes per
    doc, and compacts at `YJS_COMPACT_AT` (50, exported).
  - `subscribeYState` attaches `onChildAdded` to `u`, then `onValue` to `s`. After the first
    load each edit reaches the callback as that update alone. `cb(null)` only while nothing
    has been delivered and `s` is empty. It compacts when the initial log has 50 or more
    entries (§3).
  - `getYState` reads the node once and returns `mergeUpdates([s, ...u])`, or a legacy
    string as is.
  - New private `ensureYShape` runs before a doc's first push or subscribe, once per doc per
    instance. It is an idempotent transaction that rewrites a legacy bare string as
    `{ s: <string> }` (§5) and awaits `ensureAuth()` first, because a transaction writes.
  - New private `compactYDoc` folds the log into `s` in a transaction on the whole node,
    and finds nothing to do if the node is already compacted.
  - New module helpers `YNode` and `mergeYNode`, and `onChildAdded` is imported.
- `packages/shared/src/store/campaign-store.ts` — the `subscribeYState` doc comment now
  carries SPEC-065 §4's guarantee ("apply every callback"). The `mergeYUpdate` comment no
  longer says "RTDB transaction".
- `packages/shared/src/store/contract/collab.contract.ts` — the concurrent-merge test
  applies every callback to one `Y.Doc` (new local `waitForYDoc`). It also checks that
  `getYState` returns the same merged text. It runs against all three stores.
- `packages/shared/src/store/yjs-transport.emulator.test.ts` (new) — `FirebaseStore` on the
  emulators:
  - with ~55 KB of notes stored, one small edit reaches a second client's subscriber as one
    callback under 1 KB;
  - the log compacts at the 50th push and the text survives, and a late subscriber gets the
    snapshot;
  - two clients pushing 50 each at the same time, so both compact at once, lose no edit;
  - a raw 50-entry log is compacted on subscribe;
  - a legacy string node keeps its text through a subscribe, a push and a compaction.
- `apps/web/tests/e2e/portability.spec.ts` — `adminNotes` decodes `s` plus every `u` entry.
- `README.md` → "Players' notes": a new paragraph on the node shape, the compaction rule, the
  lazy migration and the stale-tab consequence. The "no migration and no rules change"
  sentence now says "no Firestore migration", and adds that the write grant cascades to the
  node's children.
- `docs/spec/SPEC-036.md` §3 — the RTDB read decodes `s` plus the log.
  `docs/spec/SPEC-065.md` and its `SPEC.md` row → Active (RULE-018).
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — WI-223 row and block removed from PLAN, row
  added to PLAN-COMPLETED, IN-210 moved to §1.2.

## Visible behavior changes

- None on screen. Notes and players' notes look and behave as before.
- Each edit now sends that edit to the other players, not the whole notes document. Once
  every 50 edits, everyone downloads the whole document once, through the snapshot.
- After this deploys, a tab still running the previous build cannot load or save notes for a
  doc that a new tab has already migrated, until it reloads. Nothing is lost (SPEC-065 §5,
  accepted at the gate).

## How to verify

- `pnpm verify` is green (docs check, lint, typecheck, unit). In `pnpm verify:all`, the rules
  and store suites are green, including `yjs-transport.emulator.test.ts`.
- Every Playwright spec passed, `portability.spec.ts` included, but not in one single-worker
  local run. Two full runs each stopped on a different test that touches no notes code:
  `fog.spec.ts` the first time and `session-config.spec.ts` the second. Each failed waiting
  on a join or a tab. Both specs passed when run on their own, and so did every spec the
  stopped runs had not reached. CI's sharded run is the full-suite check.
- The new emulator file and the Yjs contract and listener cases also passed six runs in a
  row with retries off.
- By hand, on the emulator: two clients edit shared Notes. In the RTDB emulator UI,
  `rooms/{id}/yjs/notes` shows `u` entries growing, then folding into `s` at 50.

## Deviations

- **Unblock (RULE-015):** `ensureYShape` awaits `ensureAuth()` before its transaction. A
  bare listener needed no sign-in before, but a transaction writes. The contract's
  concurrent-merge test failed with `permission_denied` without it, when the second client
  had not yet otherwise touched the store.
- **Not in the WI text:** the contract test also asserts that `getYState` matches the
  converged text. It is one assertion in a test this item already changes, and it covers the
  new `getYState` merge in all three stores.
- No Deviations-budget fixes.
- Noticed, not fixed: the class comment in `apps/web/src/lib/collab/yprovider.ts` still
  says `mergeYUpdate` is "an RTDB transaction that … broadcasts the whole merged state".
  The WI keeps `YRoomProvider` unchanged, so the comment is left for a follow-up.
