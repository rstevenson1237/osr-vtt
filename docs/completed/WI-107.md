#### WI-107 — Reconcile SPEC-028 with the code

**Spec:** SPEC-028 §§2, 6, 12 (all annotated in place). **From:** IN-095 – IN-098, IN-100,
IN-101, IN-103, IN-104. **Model:** `sonnet`.

**Changes made.**

- `apps/web/src/lib/map/vector-tools.ts` — `targetedBandFor`'s free-snap branch now checks
  `tool === 'path'` as well as `snap === 'free'`. Corridor's legs are axis-aligned and
  flat-capped under every snap mode (`corridorPoly` has no Free branch), so a free-snap
  circle there was advertising a round cap the tool never draws; Corridor now keeps the
  width×width square (`targetedBandRect`/`bandLo`, already Free-safe) and only Path gets
  the circle (IN-095). Doc comment updated to match.
- `apps/web/src/lib/map/vector-tools.test.ts` — the existing free-snap circle case in the
  `targetedBandFor` describe block now asserts against `'path'` rather than `'corridor'`,
  and a new case pins Corridor's Free-snap square directly (IN-095). The `attractsToVertex`
  describe block gains a case asserting `symbol`/`label` are excluded (IN-103).
- `packages/shared/src/map/vector/symbol-catalog.ts` — `anchorCellFor`'s doc comment notes
  that under Free, `snapCell` is identity, so the function returns the raw pointer
  position — an arbitrary lattice float, not a cell address — and that `MapSymbol.cell`/
  `MapRoom.labelAnchor` can hold such a float under Free, intentionally (IN-100).
- `docs/spec/SPEC-028.md`:
  - §2 — main sentence now lists Path among the cell-anchored tools (it joined at WI-051,
    previously omitted here though present in §7). New **IN-104** amendment replaces the
    two-anchor framing with the code's real three: lattice vertex (`snapPoint`), cell
    centre (`snapCellCenter` — Corridor, Path, N-gon, Carve) and cell corner, floored
    (`snapCell` — Room, Symbol, Label), with `CELL_ANCHORED_TOOLS`'s merge of the last two
    called out as correct for the plumbing but incomplete as a description of behaviour.
    The helper table gains `snapCell`. The WI-042 correction gains two clauses: the Carve
    brush's snapped footprint is a Euclidean disc of cells, kept and documented rather than
    reshaped (**IN-097**, answered in place by the user 2026-09-03), and its `step / 2`
    radius floor collapses the Width control's first two stops under Cell snap, which is
    the floor's known and accepted cost (**IN-098**).
  - §6 — the WI-052 amendment's free-snap sentence now says Path draws the circle, not
    "Corridor and Path"; a new **IN-095** correction paragraph explains why. The WI-048
    amendment's superseded first sentence (dot drawn *in addition to* the cell highlight)
    is struck and annotated as contradicting the sentence that follows it, which is what
    the code actually implements (**IN-101**).
  - §12 — new **IN-103** correction states the allowlist rationale for excluding Symbol and
    Label by name, rather than leaving it implied by their absence from every list.
- `README.md` — five spots brought into parity with the above: the carve-pipeline stroke
  count (four → five cell-anchored tools, Path included), the "Cells, not intersections"
  paragraph (three anchor families, not one shared anchor), the Corridor/Path band
  indicator paragraph (Corridor's Free square vs. Path's Free circle), the Symbol/Label
  bullet (the Free-mode float note), and the Carve bullet (the Euclidean disc and its
  `step / 2` floor collapse).
- `apps/web/tests/e2e/map-draw-feedback.spec.ts` — **CI fix, one push (see Deviations).**
  The existing "Corridor/Path indicator shows the band actually carved" e2e test asserted
  the pre-fix Free-snap circle for the **Corridor**, which the fix above corrects; updated
  to assert the square instead, and extended with the case that test never actually

- `apps/web/src/lib/components/VectorMapView.svelte` — the `snap-band-readout` doc comment
