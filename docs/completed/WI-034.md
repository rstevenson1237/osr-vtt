## WI-034 — Battle map: the capture tool (full-cell bounding box, distinct preview colour)

**Spec:** SPEC-029 §1 · **From:** IN-010 · **Closed:** 2026-08-09 · `claude-code`, `sonnet`,
effort `medium`

### Changes made

- **`packages/shared/src/map/vector/primitives.ts`** — new `captureRect(a, b): BBox`. Same
  corner math as `cellRectPoly`'s full-snap branch, but takes no snap-mode parameter at
  all — it always calls `snapCell(_, 'full')` on both corners, so it genuinely "ignores the
  snap mode" rather than defaulting to one. Returns a plain `BBox`, not a `Poly`: nothing
  here is carved floor geometry, so there is no ring to close. A click with no drag is one
  cell, same as Room's.
- **`packages/shared/src/map/vector/primitives.test.ts`** — `captureRect` cases mirroring
  `cellRectPoly`'s: one-cell click, whole-cell growth, corner-agnostic, and an explicit
  check that it lands on the same rect as a full-snap Room even without a mode argument.
- **`apps/web/src/lib/shell/map-tool-controller.svelte.ts`** — new `'capture'` `MapToolId`,
  and `pendingBattleCapture: vectorMap.BBox | null` on `MapToolController` — the commit
  target for the tool. No document write: nothing outside this client's own state changes
  until WI-036's Start button turns the rect into a real temporary `GameMap`. Cleared in
  `release()` (transient scratch state, unlike `selectedMapRoomId`, which has a sheet
  keeping it live across an activity switch — a pending capture has none).
- **`apps/web/src/lib/shell/map-tool-controller.test.ts`** — `release()` clears

  `ALL_TOOLS` map and to the group-membership assertions.
- **`apps/web/src/lib/shell/types.ts`**, **`apps/web/src/lib/components/shell/Icon.svelte`**

### Visible behavior changes

A referee sees a new **Capture** tool in the Map tools sheet's Shapes group (a crop-frame
icon), visible only to them — a player's palette doesn't show it at all. Selecting it and
dragging (or clicking, then clicking again) draws a teal-tinted bounding box that always
snaps to whole cells regardless of the current Snap selection, with a live "`w × h` cells"
readout while dragging. Releasing commits the rect to in-memory tool state only — nothing
is written to the map, no new `GameMap` document appears, and nothing else in the room
changes. There is not yet any way to *see* the committed rect after the drag ends or to
turn it into an actual battle map (WI-035/WI-036).

### Deviations

- **`INTAKE.md`'s IN-010 row was not moved from §1.1 to §1.2.** Same reasoning WI-033
  recorded: IN-010 covers WI-033 – WI-036 as one Shape-A item, and two of its four work

  WI-036 lands.
- **The first `pnpm verify:all` run failed one of the four new e2e tests** — a wrong test
  assumption, not an implementation bug: a click with no movement only arms the Capture
  tool's click-to-start/click-to-end gesture (exactly like Room's), it doesn't commit a
  degenerate shape immediately. The other 82 e2e tests, including the other three new
  specs, passed on that run. Fixed the test to click twice at the same point instead of
  once; the re-run was fully green (83/83).
- **No keyboard shortcut, no persistent post-commit highlight.** The tool rides Room's
  existing Escape-to-cancel (`cancelStroke()` is generic over the active tool) for free, but
  nothing renders the *last* committed capture once the drag preview clears — there is no
  quick sheet yet (WI-036) to show it, and inventing a persistent on-canvas indicator for a
  rect nothing else in the UI references yet would have been speculative scope.
