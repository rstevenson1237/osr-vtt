# WI-095 — Incised numerals: normal map replaces the emboss pass; material + env-map re-tune

**Spec:** SPEC-045 §3 · **From:** IN-081 · **Model:** `sonnet` · **Effort:** M ·
**Closed:** 2026-09-02

`textures.ts` faked depth with a canvas emboss pass — a darkened copy offset up-left and a
lightened copy offset down-right, then the ink glyph on top. The highlight sits where the
canvas put it, not where the key light is, so it disagreed with the lighting on roughly
half a tumbling die's faces. The fix generates a real normal map per numeral and lets the
existing key/fill/hemisphere rig light the incision as geometry.

## Changes made

- **`apps/web/src/lib/dice/textures.ts`**
  - `drawGlyph`/`drawNumber` lost the emboss offset copies — they now paint a single glyph
    (plus the 6/9 underline) in one color, since the depth cue no longer comes from the
    canvas.
  - New `makeNormalMap(drawHeight)`: paints a grayscale height layer (flat mid-gray
    `#808080`, the numeral shape painted darker at `#3c3c3c` as a recess, blurred 1.5px at
    the edge so the recess has a slope rather than a cliff), then converts it to a
    tangent-space normal map with a Sobel-style central difference per texel
    (`NORMAL_STRENGTH = 3`), at `NORMAL_MAP_SIZE = 128`. `tex.colorSpace = NoColorSpace` —
    normal maps are linear data, not sRGB.
  - `labelNormalMap(label)` + `normalMapCache`: normal maps depend only on the numeral
    label, never on face color or theme, so they're cached separately from — but dropped
    alongside — the `(theme, face, variant, label)`-keyed material cache. Never rebuilt
    per roll.
  - `faceMaterial` hangs `labelNormalMap(label)` on `normalMap`.
  - `d4FaceMaterial` builds its normal map fresh per composition (`makeNormalMap` over the
    same per-corner draw callback used for the diffuse ink), matching how its diffuse
    texture is already composed on demand rather than cached.
  - `clearDiceMaterialCache` also disposes and clears `normalMapCache`.
  - `MATERIAL_PARAMS` retuned: `roughness` 0.30 → 0.34 (keeps the normal-mapped highlight
    soft rather than aliasing against `flatShading`'s hard per-facet normals), `metalness`
    0.10 → 0.09, and a new `envMapIntensity: 0.6` so the added environment map (below)
    actually contributes instead of a flat hemisphere-only gloss.
- **`apps/web/src/lib/dice/scene.ts`**
  - Imports `RoomEnvironment` from `three/addons/environments/RoomEnvironment.js`.
  - New `applyEnvironment(renderer)`, called once from `mount()` after the renderer
    exists: bakes `RoomEnvironment` into a PMREM and sets `scene.environment`, which every
    `MeshStandardMaterial` in the scene picks up automatically — no per-material `envMap`
    assignment needed. Baked once per mount, not per roll.
  - `dispose()` clears `scene.environment`, disposes the baked `envMap` texture.
  - `clear()`'s rollDisposables loop now also disposes `.normalMap` (the d4 composites'
    fresh-per-roll normal map, same lifecycle as their `.map`); the tint-clone comment
    is updated to note clones share both textures with the cached original.
- **`README.md`** § "Dice (II.6)" — the quality-bar bullet gets the retuned material
  numbers and the PMREM environment; a new bullet describes the normal-map mechanism,
  its per-label cache, and that it replaces the emboss pass.
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — ledger moves.

## Visible behavior changes

Every generated die's numerals now shade as carved geometry: the highlight/shadow along
each stroke tracks the actual key light as the die tumbles, instead of a fixed offset
reading correctly on only half the faces at rest. The material overall reads slightly
glossier — the environment map gives the plastic something to reflect beyond the two
directional lights. Face texture color, `flatShading`, face count, material groups,
`locators`, `hullPoints`, the face→value remap and `topFaceIndex` are all unchanged.
