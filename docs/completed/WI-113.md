# WI-113 — `Token.letter`/`ProfileInstance.letter`, `imageRef` optional, schema v30

**Spec:** SPEC-048 §§1–2 · **From:** IN-109 · **Model:** `opus` · **Effort:** M
**Gate cleared:** user, 2026-09-08 · **Completed:** 2026-09-09

Phase 1 of 4 of the token-letter programme. The letter becomes stored data and every
`gen:disc:` ref is parsed into the new fields — and **every ref is left exactly where it
is**, so nothing changes visibly. WI-114 moves assignment onto the field, WI-115 draws it,
and only then does WI-116 clear the refs.

## Changes made

**Schema and types**

- `packages/shared/src/types.ts` — `CURRENT_SCHEMA_VERSION` 29 → **30**. `Token` gains
  `letter?: string` and `Token.imageRef` becomes **optional**, documented as _real art
  only_; `ProfileInstance` gains `letter?: string` beside `portraitRef`.
- `packages/shared/src/schemas.ts` — the same three changes on `TokenSchema` and
  `ProfileInstanceSchema`. `imageRef` keeps `.min(1)` when present: an empty ref was never
  legitimate, and absence is now the way to say "no art".

**The conversion**

- `packages/shared/src/store/asset-store.ts` — new **`genColorHex(colorToken)`**, beside
  the existing `HSL_RE`. Converts a ref's baked `hsl(...)` paint value to the `#rrggbb`
  the colour fields are validated against (DEC-087 question 1), passes an existing hex
  through normalised (`#rgb` expanded), and returns `null` for anything with no honest hex
  — a bare CSS colour name, `rgb(...)` — so the caller leaves the colour absent rather
  than inventing one. Hue wraps, saturation/lightness clamp.

**The migration**

- `packages/shared/src/migrations/index.ts` — the `{ from: 29, to: 30 }` entry (a room-doc
  no-op: tokens and profiles are sub-collections), plus the two document halves
  **`backfillTokenLetter`** and **`backfillProfileLetter`** over a shared
  `backfillLetterFromRef`. Each parses the document's ref, copies the label into `letter`
  verbatim — pre-v28 lowercase `a1`/`a2` included (DEC-087 question 3) — converts the
  baked paint value into `color` **only where the document has none**, and leaves the ref
  untouched. Keyed off the absent `letter` rather than a stored version, so it is
  idempotent and returns an unaffected document **by reference**.

**The two boundaries the halves are applied at**

- `packages/shared/src/portability/vttcamp.ts` — `backfillLetterCollections` maps the
  `tokens` and `profiles` collections in `archiveToSnapshot`, on both the current and the
  legacy (<v11) import paths.
- `packages/shared/src/store/campaign-store.ts` — two new contract members:
  **`setTokenLetter(roomId, tokenId, letter | undefined)`** (RULE-001; one settled write,
  so RULE-003 is not in play) and **`migrateTokenLetters(roomId)`**, the live-room half,
  documented as idempotent and safely racy exactly as `migrateMapBackgrounds` is.
- `packages/shared/src/store/memory-store.ts` and `firebase-store.ts` — both
  implementations. `LocalStore` extends `MemoryStore`, so it is the third implementation
  for free (RULE-009's amendment). `FirebaseStore` reads both collections **raw and
  unconverted** — the signal is an _absent_ field — and patches only `letter` (and `color`
  where it actually changed), never rewriting the document.
- `apps/web/src/lib/components/RoomShell.svelte` — a GM-gated, latched `$effect` calling
  `store.migrateTokenLetters(roomId)` once per room-open, alongside the two migration
  effects already there.

**`imageRef` optional — the read sites**

Five guards, each behaviour-preserving and unreachable at v30 (every ref is left in
place): `apps/web/src/lib/encounter/labels.ts` and `apps/web/src/lib/tokens/labels.ts`
(`creatureLabel` falls back to the id fragment rather than the empty string, so
`creatureDisplayName` can never render empty; `usedGroupLetters` skips a token with no
ref, which is the answer it already gives a non-disc ref), `VectorMapView.svelte` (no ref
⇒ the sprite keeps its plain white texture and raises no broken-image badge),
`EncounterBoard.svelte` (no `<img>` rather than a resolve of nothing), and
`CharacterDock.svelte` (the colour-pick ref rebuild).

**Tests**

- `campaign-store.contract.ts` — three new contract tests, run against `MemoryStore`,
  `FirebaseStore` and `LocalStore`: `setTokenLetter` sets/clears leaving the ref and every
  other field alone; `createToken` persists a letter with **no** `imageRef`;
  `migrateTokenLetters` backfills letter+hex colour across a lettered token, a legacy
  lowercase one, real art (no letter invented), a token with a colour already picked (not
  repainted) and a portrait — then is idempotent against a retyped letter.
- `migrations/index.test.ts` — 10 unit tests over the two halves: the conversion, the ref
  left in place, `a1` verbatim, an escaped `:` decoded, no colour overwrite, `null`
  conversion leaving `color` absent, real art by reference, idempotency, the profile half's
  field and its application to creatures, and the room-doc no-op.
- `portability/vttcamp.test.ts` — the RULE-007/RULE-014 round-trips: letters round-trip
  identically **including absence and an absent `imageRef`**, and a v29 archive is
  backfilled on import and letters nobody twice on re-import. Two existing fixtures were
  updated (see Deviations).
- `store/asset-store.test.ts` — 7 tests on `genColorHex`, including every
  `GEN_TOKEN_PALETTE` swatch and `genColorToken`'s output, the achromatic/clamped edges,
  and the `null` cases.

**Docs** — `README.md` gains the v30 field/migration bullet under "Tokens, assets &
theming" and a paragraph under "Creature names and symbols" recording that
`usedGroupLetters` still reads the ref at v30 and that §3 is what changes it.

## Visible behavior changes

**None** — and that is the point of this phase. The migration backfills but does not
clear: every `gen:disc:` ref stays where it is, so the old art still resolves and still
draws, label assignment still parses the ref, and the new fields sit unread. A referee
opening an existing room sees exactly what they saw, `a1`/`a2` tokens included. The one
thing that happens invisibly is a one-shot patch per lettered token and portrait, written
once by the referee's client on room-open.

  `#rrggbb` `color`, with `imageRef` untouched.

## Deviations

1. **Two `.vttcamp` fixtures were updated rather than left alone.** The v28 creature-name
   round-trip and the v27→v28 no-name-backfill test both asserted that a token carrying a
   `gen:disc:` ref and **no** `letter` survives an import unchanged. At v30 that is no
   longer a valid current-schema document — the backfill rightly gives it a letter — so the
   first fixture now carries the `letter`/`color` a v30 export actually has, and the second
   asserts what it was always about (the _name_ pass leaves the document alone) against the
   v30 shape. Neither test's subject changed.
2. **The backfill is version-agnostic, not gated on `schemaVersion < 30`.** It matches the
   file's existing halves (`lockLegacyBackground`, `foldLegacyMapBackground`) and it is
   load-bearing here rather than merely consistent: through v30 the writers still produce
   `gen:disc:` refs with no `letter` field (that is §5's job), so a creature created during
   the WI-113 → WI-116 window would otherwise have no letter for §3 to read. Keying off the
   absent field heals that window; the cost is that importing a letterless gen-ref archive
   adds letters rather than being a strict identity, which the suite pins explicitly.
3. **`MemoryStore`'s three profile setters were taught to carry `letter`.** They rebuild
   the document from a whitelist of fields rather than merging, so without this
   `setProfileValue`/`setProfilePortrait`/`setProfileColor` would each silently drop a
   profile's letter while `FirebaseStore`'s `merge: true` kept it — the two backends would
   have diverged on the field this item adds. Required to land the field honestly
   (RULE-015's unblock exception).
4. **`IN-109`'s intake row stays in `INTAKE.md` §1.1.** It spans WI-113, WI-114 and
   WI-116; only the first has run, so the row is annotated in place rather than moved to
   §1.2, which would claim the request is closed.
5. **No `setProfileLetter`.** SPEC-048 §5 puts the letter input on `CharacterDock`, which
   "reaches only the player's own token", so `setTokenLetter` is the store method WI-117 is
   blocked on. `ProfileInstance.letter` is written by the migration only, exactly as §§1–2
   specify.
