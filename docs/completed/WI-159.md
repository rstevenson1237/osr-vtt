# WI-159 — Add creature and Download PNG in the docked palette

SPEC-054 §5. Part of Batch 2b (WI-159, WI-161, WI-164, WI-165) — one pull request, one
combined summary.

**Changes made**

- `apps/web/src/lib/components/MapToolbar.svelte` — the Add-creature button and the PNG
  export group (`map-export-tools`/`map-export-max-layer`/`map-export-png`) render
  unconditionally instead of behind `{#if expanded}`. `RoomShell.svelte`'s `dockedSheets`
  already excludes a sheet's id from the docked stack while it is the expanded one
  (`shell.expandedId !== def.id`), so the docked and expanded renders of `MapToolsSheet`
  were already mutually exclusive mounts — removing the gate is enough to satisfy "at most
  one instance of each testid in the DOM at a time" without further plumbing.
- `apps/web/tests/e2e/shell-navigation.spec.ts` — the test asserting these two controls
  were expanded-only now asserts they are visible in the docked palette too (Simplify
  stays expanded-only, unaffected by this item).
- `apps/web/tests/e2e/session-config.spec.ts` — a stale comment ("now lives in the expanded
  Map tools sheet") corrected; the test itself (Add-creature is GM-only regardless of
  docked/expanded) needed no change.

**Visible behavior changes** — "Add creature" (GM only) and "Download PNG" (with its
layer-cutoff selector) now appear in the docked Map tools palette, not only the expanded
sheet.

**How to verify** — `pnpm verify` green. Manually: open the Map tools quick sheet docked
(not expanded); Add creature and Download PNG are visible. Expand the sheet; they remain
visible, still exactly one of each in the DOM (Playwright's `toHaveCount(1)` assertion
covers this).

**Deviations** — none.
