# WI-152 — Empty-state hints

SPEC-054 §1. Part of Batch 1 (WI-152–158) — one pull request, one combined summary.

**Changes made**

- `RoomShell.svelte` — an empty-map hint card (GM-only), shown while `mapCtrl.mapIsEmpty`
  and not dismissed: links to Map tools (expands `maptools`), Assets (`setMainView`) and
  Invite (`copyShareLink`), plus a dismiss button. Dismissal persists per viewer.
- `VectorMapView.svelte` — mirrors `regions.length === 0 && backgrounds.length === 0`
  (square maps only) onto the new `MapToolController.mapIsEmpty`.
- `map-tool-controller.svelte.ts` — new `mapIsEmpty` field, same mirror pattern as
  `fogEnabled`.
- `shell-state.svelte.ts` (+ test) — `dismissedHints` (per-hint, persisted) and
  `railSeen` (WI-154, persisted); `dismissHint`, `markRailSeen`, `resetHints`.
- `EncounterBoard.svelte` — a GM-only "Add a creature with the + card" line when the
  board has no tokens (`castSections.length` stays non-zero for the GM's own Unassigned
  box, so this is a separate branch from the existing player-facing empty message).
- `ShortcutSheet.svelte` (+ `RoomShell.svelte` wiring) — "Show me around" button calls
  `shell.resetHints()`.
- `README.md` — new "First-run cues (SPEC-054)" subsection.

**Visible behavior changes** — a referee sees a dismissable hint card over an empty map;
a dismissed card stays dismissed across reloads until "Show me around" (in the `?`
sheet) resets it. An empty Encounter board shows a one-line hint. Players see neither
(no action they can take).

**How to verify** — `pnpm verify:all` green. Manually: create a room, land on the Map
view with nothing drawn — the hint card appears; dismiss it, reload, confirm it stays
dismissed; open `?`, click "Show me around", confirm it returns.

**Deviations** — none. Both RULE-015 exceptions unused for this item specifically (see
the batch's combined Deviations note for the cross-file e2e-helper fix, filed under
WI-153 where the behavior change that caused it lives).
