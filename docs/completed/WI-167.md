# WI-167 — E2E readouts behind `VITE_E2E_READOUTS`

SPEC-055 §3. Part of **Batch 3** (WI-166, WI-167, WI-168, WI-169) — one pull request,
one combined summary.

## Changes made

- `apps/web/vite.config.ts` — `define` gains
  `import.meta.env.VITE_E2E_READOUTS`, computed from `mode`: `true` for `vite`'s plain
  dev server (mode `development`, what Playwright's `webServer` runs) and under vitest
  (mode `test`); `false` for `pnpm build` (mode `production`) and `pnpm build:local`
  (mode `local-build`). A literal boolean, so both built modes can dead-code-eliminate
  the gated markup.
- `apps/web/src/vite-env.d.ts` — `ImportMetaEnv` gains `VITE_E2E_READOUTS: boolean`.
- `apps/web/src/lib/components/VectorMapView.svelte` — the whole `vf-readouts` block
  (`token-pos-*`, `selection-count`, `measure-readout`, and every other hidden
  introspection span) is now inside `{#if import.meta.env.VITE_E2E_READOUTS}…{/if}`.
  No testid moved or renamed.
- `README.md` — "Test culture (II.9)" documents the flag and its per-mode values.

## Visible behavior changes

None in `vite dev` (what a developer or Playwright sees) or under vitest — the readout
layer renders exactly as before. In `pnpm build`/`pnpm build:local` output, the readout
markup and its testids no longer exist in the DOM (they never rendered anything visible
to a player; this only removes their footprint from a production page's node count and
main entry chunk size).

## How to verify

- `pnpm build && grep -c 'selection-count\|vf-readouts' apps/web/dist/assets/index-*.js`
  — `0` (the one `token-pos-` hit elsewhere in the bundle is `EncounterBoard`'s unrelated,
  always-visible `board-token-pos-*` span).
- `pnpm exec vite --host 127.0.0.1 --port <free-port>` then fetch
  `/src/lib/components/VectorMapView.svelte` — the served module defines
  `VITE_E2E_READOUTS": true`.
- `pnpm test:e2e` — unaffected; Playwright runs against the dev server, where the flag
  is on.
