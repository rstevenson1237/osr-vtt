# WI-135 — A call is visible on every stage, and the Caller is room-scoped

**Spec:** SPEC-050 §2 · **From:** IN-131 · **Model:** `sonnet` · **Closed:** 2026-09-16

## Changes made

- **`apps/web/src/lib/components/TurnStrip.svelte`** — subscribes to `sharedRoll` via the
  store context (the same pattern `CombatTracker` uses) and now renders while an initiative
  call is `staging`, even when no order exists yet: "Initiative called — N of M ready"
  (`turn-strip-call`), computed from `initiativeActors` + the slot readiness count. The
  round/current-entry line only renders when an order exists, so the strip now shows content
  in either or both states. Gained the props needed for `initiativeActors`: `gmUid`,
  `initiativeDie`, `initiativeMode`, `profileTemplate`, `profiles`, `encounterTemplate`, plus
  `roomId` to subscribe.
- **`apps/web/src/lib/components/shell/SessionTab.svelte`** and
  **`.../shell/MobileTopBar.svelte`** — thread the new `TurnStrip` props through from their
  own props (all already carried one level up in `RoomShell`).
- **`apps/web/src/lib/components/RoomShell.svelte`** — both `<SessionTab>` and
  `<MobileTopBar>` call sites gain `gmUid`/`initiativeDie`/`initiativeMode`/`profileTemplate`/
  `profiles`, read from `room.settings`/`room.profileTemplate`/existing `profiles` state.
- **`apps/web/src/lib/components/EncounterBoard.svelte`** — `CombatTracker` now mounts
  unconditionally; the `{#if initiativeMode !== 'free'}` gate that unmounted it (and, with it,
  the Caller controls living inside) whenever the session's mode was Free is gone.
- **`apps/web/src/lib/components/CombatTracker.svelte`** — the Caller row (`caller-name`,
  `caller-select`, `caller-rotate`) moved out of the `isFree`-only branch to render whenever
  an encounter doc exists, regardless of mode or whether an order is running. The stale
  "Free/Caller is Phase 4" / "Phase 4 (Free/Caller mode)" header comment is corrected.
- **`packages/shared/src/types.ts`** — `EncounterMode`'s doc comment drops the "Phase 4"
  framing (all three modes are shipped); `Encounter.callerSeatId`'s comment now describes the
  Caller as SPEC-050 §2 does, rather than "declared now for schema stability".
- **`README.md`** — "Encounter board (II.3)" corrects "free/caller (rotating Caller marker)"
  as a tracker-mode description to state the Caller is room-scoped and available in all three
  modes; "Top status bar" documents `TurnStrip`'s new call-progress line.
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — ledger moves.

No schema change: `Encounter.callerSeatId`, `setCaller`/`rotateCaller` (as `setCaller` calls
in `CombatTracker`) and `sharedRoll` all existed already (RULE-007 not engaged).

## Visible behavior changes

- **A player on the Map view (or any stage) now sees a Call for Initiative in progress.**
  Before, the only signal was `combat-staging-note` inside `CombatTracker`, rendered on the
  Encounter board alone — a player elsewhere saw their die button behave differently with no
  explanation.
- **The Caller is reachable in Side and Individual mode, not just Free.** The referee can now
  set/rotate a Caller from the Encounter board while running side-based or individual
  initiative, and the Caller's name shows there too — previously `caller-select`/
  `caller-rotate` existed in code but were unreachable because `EncounterBoard` never rendered
  the tracker in Free mode, the only branch that rendered them.
- Nothing else moves: no `data-testid` changed (RULE-005) — `turn-strip-call` is new, none
  existing moved.

## How to verify

- `pnpm verify` — lint, typecheck, unit; green.
- In the app: as referee, start a Side-mode encounter, press **Call for Initiative**, then
  switch to the Map view (or check a mobile session) — the top bar reads "Initiative called —
  0 of N ready" and updates as players stage. On the Encounter board, set a Caller while Side
  or Individual mode is running — the caller's name now appears without switching to Free
  mode.
- `pnpm verify:all` runs the emulator-backed rule/store/e2e suites; not run locally in this
  sandbox (see Deviations).
