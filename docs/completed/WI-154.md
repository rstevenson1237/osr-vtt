# WI-154 — Rail shows all three views; labels until first interaction

SPEC-054 §3. Part of Batch 1 (WI-152–158) — one pull request, one combined summary.

**Changes made**

- `RoomShell.svelte` — desktop rail renders `MainViewTabs` (`variant="rail"`, all of
  `visibleViews`) and `QuickSheetRail` directly, both `showLabels={!shell.railSeen}`;
  `ActivityDrawer` now holds only the rail-move handle. First click on a rail icon
  calls `shell.markRailSeen()`.
- `ActivityDrawer.svelte` — dropped `views`/`active`/`onSelect`; its trigger now shows a
  `grip` icon ("Rail options") and its panel renders only the `extra` (move-handle)
  snippet.
- `MainViewTabs.svelte`, `QuickSheetRail.svelte` — new `showLabels` prop; when true (rail
  variant only) the label renders beside the icon instead of visually hidden.
- `shell-state.svelte.ts` — `railSeen` (see WI-152's summary for the shared
  `dismissedHints`/`railSeen` persistence change).
- e2e: `helpers.ts`'s `openActivityDrawer`/`closeActivityDrawer` now describe (and are
  used only for) the move-handle drawer; `openActivity`'s `switchTo` path clicks
  `activity-tab-*` directly, since every view is always visible. `shell-navigation.spec.ts`
  updated to match (no drawer-open step before a view-tab click).
- `backgrounds.spec.ts` — two tests (SPEC-039 §3, §2/§4) now wait for
  `vector-map-canvas` after `background-pick-…`, as Gate 19 and §2 already did.
  `addBackground` is async and ends by switching to the map; the old helper's
  drawer-open step used to absorb that latency, and without it the Assets-tab
  click was skipped as "already selected" before the switch landed (CI shard 1
  failure on PR #213, ~50% locally before the fix, 16/16 after).
- `README.md` — "Rail, drawer and rail side" rewritten for the new split; "State"
  section lists the two new persisted fields.

**Visible behavior changes** — all three main-view icons (for a seat that can see them)
and every visible quick-sheet toggle sit in the rail directly, no hover needed. Until a
viewer's first rail click, each icon's label renders beside it (not just in `title`) —
this also reaches touch devices, which never see `title`. The hover drawer that used to
list all three views now holds only the "move rail to the other side" control.

**How to verify** — `pnpm verify:all` green, including `shell-navigation.spec.ts`'s
rail-move test (drawer still opens on hover/click to reveal the move handle) and the
main-view-tab-switching tests (now clicking `activity-tab-*` with no drawer step).
Manually: open a room, confirm all three view icons + sheet toggles show labels; click
one, confirm labels disappear; reload, confirm they stay gone.

**Deviations** — none for this item. See WI-153's summary for the batch's one
cross-cutting Deviation (the e2e join-gate helper fix, filed there as an unblock since
it originates from WI-153's behavior change, not this one).
