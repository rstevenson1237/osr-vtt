# WI-193 — Per-layer dirty tracking

SPEC-057 §4.2, DEC-118. Single unit (Shape A). IN-175. Model `opus`, effort xhigh.

Built because WI-192 measured the large-dungeon vertex drag over budget (42 – 44 ms of JS
per move against 33 ms).

## Changes made

- `apps/web/src/lib/map/map-renderer.ts` (new) — `createMapRenderer(passes, scheduler?)`:
  `invalidate(...layers)` marks layers dirty (no argument: all of them) and schedules one
  `requestAnimationFrame`; the flush runs each dirty layer's pass once, in z-order
  (`grid`, `floor`, `overlay`, `fog`, `tools`). `flush()` draws now and cancels the pending
  frame; `dispose()` cancels it and ignores later invalidations. The dirty set is cleared
  before any pass runs, so a pass that invalidates schedules the next frame instead of
  re-entering this one.
- `apps/web/src/lib/map/drag-sight.ts` (new) — `createDragSight(base, owner)`: reconciles
  every segment except the dragged owner's against the doors once, and returns the
  per-move function that adds the owner's working copy back (a region's perimeter or a
  wall's segment clipped by the open doors; a door clipped into the cached segments, or
  appended as a blocker). Same walls a full `buildVectorScene` of the displayed geometry
  would give, up to order; `movement` is never built. An owner deleted mid-drag previews
  the committed scene without it, as `displayState()` does.
- `packages/shared/src/map/vector/los.ts` — the open-door half of `reconcileDoors`
  extracted and exported as `clipOpenDoors(segs, openDoors)`; `reconcileDoors` now calls
  it. Behaviour unchanged (it no longer mutates the list it was handed when there are no
  open doors, which no caller relied on).
- `apps/web/src/lib/map/vector-engine.ts` — `RenderedScene = Pick<VectorScene, 'floor' |
  'sight'>`, and `renderScene` takes it: the floor layer never drew `movement`, so the
  drag preview need not build one.
- `apps/web/src/lib/components/VectorMapView.svelte` —
  - `renderAll`'s body split into five passes, each an `*Inputs()` (every value the layer
    is drawn from) and a draw; `renderAll()` is now `renderer.invalidate()` (every layer,
    coalesced) and stays at the discrete call sites (commits, clicks, cancels).
  - One tracking `$effect` per layer runs that layer's `*Inputs()` and invalidates only it
    — replacing the four effects that called `renderAll` (selected hex, selected
    background, grid settings, label editor) and the `renderAll()` in every store
    subscription callback, each of which used to redraw every layer synchronously.
  - Hot paths invalidate only what they move: Select hover, lasso and background drag
    `tools`; vertex drag `floor` + `tools` (+ `overlay` for a door); object drag
    `overlay` + `tools`; stroke/Road/River previews and the Measure move `tools`; the Pen
    move `overlay`; the hex fog stroke `fog`; the Eye countdown `tools`. A Select press
    invalidates `tools` only.
  - `liveScene()` feeds the floor pass (and the Eye's visibility): the committed `scene`
    at rest, and during a vertex drag the `createDragSight` preview, cached for as long as
    the drag and the committed arrays under it are unchanged.
  - The measure readout is recomputed on demand (`currentStrokeMeasure()`) rather than
    stored by the draw pass, since the pointer path publishes it before the frame's flush;
    the `strokeMeasure` local is gone.
  - PNG and battle-map preview exports `flush()` first; unmount `dispose()`s the renderer.
- `apps/web/bench/render-large-dungeon.ts` — the call sequence restructured into the same
  five passes; cases now `rest`, `drag-rebuild` (the WI-192 path, kept for comparison),
  `drag` (the WI-193 path: working copy mutated in place, `createDragSight`, `floor` +
  `tools` only), `hover` (`tools` only) and `pan`; the JSON adds `dragSetupMs`.
- Tests (new): `apps/web/src/lib/map/map-renderer.test.ts` (7 — deferral, coalescing,
  z-order, invalidate-all, `flush`, invalidation from inside a pass, `dispose`);
  `apps/web/src/lib/map/drag-sight.test.ts` (8 — region, wall, movement-only wall, open
  and closed door drags each equal to a full rebuild; in-place mutation; deleted owner).
  `packages/shared/src/map/vector/los.test.ts` +2 (`clipOpenDoors` is per segment; it does
  not mutate its input).
- `README.md` — "Render budget and the measured figure" rewritten: how the view draws
  (renderer, passes, tracking effects, hot-path masks, the drag preview) and the new
  measured table.
- `DECISIONS.md` — the Postponed "Full-viewport-diff rendering" entry annotated as built,
  with the figure.
- `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md` — WI-193 closed; IN-175 moved to §1.2.

## Visible behavior changes

- A vertex drag on a large map tracks the pointer at a fraction of the former cost; a
  hover no longer redraws every layer. Nothing drawn looks different: same layers, same
  order, same walls during and after a drag.
- The map redraws on the next animation frame after a change rather than synchronously
  inside the event or effect — at most one frame later, and several changes in that frame
  draw once.

## Deviations

- **IN-197 not decided here.** `PLAN.md` noted that WI-171 §2.1 asked for IN-197
  (`renderAll` takes inputs, one `requestRender()` funnel) to be decided at WI-193's gate
  if WI-193 were built; the gate (2026-09-23) cleared WI-193 alone. This item's passes do
  take gathered inputs and `invalidate` is a single funnel, but only inside
  `VectorMapView` — IN-197's extraction is not done and IN-197 stays open.
- **The Select press invalidates `tools` alone** rather than every layer, so the drag's
  one-off reconciliation (10 – 16 ms) lands on its first move instead of on top of a
  full redraw at pointer-down. The press changes nothing any other layer draws; selection
  changes are reactive and invalidate their own layers.
- No RULE-015 unblock change and no Deviations-budget fix.
