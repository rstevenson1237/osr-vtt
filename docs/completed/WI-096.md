# WI-096 — Dice meet each other: throw tuning, plus a documented rule for a stacked die

**Spec:** SPEC-045 §5 · **From:** IN-083 · **Model:** `sonnet` · **Effort:** M ·
**Closed:** 2026-09-02

Collisions were already on — `DiceScene.simulate` puts every die in one Rapier world as a
`ColliderDesc.convexHull` with default groups and no filtering, so Rapier resolves
die-against-die exactly as it resolves die-against-floor. What suppressed them was the
throw: each die spawned at an independent random angle around the full circle, on a wide
ring, with a gentle inward launch, so dice at unrelated angles simply landed apart. The fix
is throw tuning only, inside `simulate()` — no physics-architecture or collision-group
change — plus a documented rule for a die that lands resting on another.

## Changes made

- **`apps/web/src/lib/dice/scene.ts`**
  - New constants: `SPAWN_ARC` (`Math.PI * 0.7`), `SPAWN_RADIUS_MIN`/`SPAWN_RADIUS_SPAN`
    (spawn ring 1.1–2.0, was 1.4–2.6) and `INWARD_VELOCITY` (1.15×, was 0.7×).
  - `simulate()` now picks one shared `throwAngle` per roll and jitters each die's spawn
    angle within `SPAWN_ARC` of it, instead of an independent angle per die around the
    full circle — dice launched from the same side of the tray cross paths. The spawn
    ring is tighter and the inward launch stronger.
  - `MAX_STEPS` raised 300 → 360 (~5s → ~6s hard cap): more contacts can mean longer
    settles, and the extra headroom is computation only — the headless sim isn't paced to
    real time, so it doesn't lengthen wall-clock roll latency.
  - Top-of-file doc comment gains a paragraph on the tuning and the stacked-die decision
    (below); the throw-tuning block itself carries an inline comment.
  - **The stacked-die rule (SPEC-045 §5): accepted as a legitimate outcome, not nudged
    apart.** `topFaceIndex` already reads the most-up locator regardless of tilt, so a
    stacked die's value is exactly as correct as a flat one's — nothing about the read
    path assumes the die is level. No settle-time separation pass, no extended step
    budget specifically for stacked dice, no rejection/re-roll of the throw. This is a
    deliberate choice among the three the spec named (nudge apart / extend the budget for
    them / accept the stack), not the absence of one: a separation pass would need to run
    after the sim has already committed to the seed-derived resting orientations RULE-013
    depends on, which is exactly the kind of correction R3.1's "no-flip settle" replaced.
- **`README.md`** § "Dice (II.6)" — new bullet describing the retuned throw, the new
  constants, and the documented stacked-die decision, placed before the existing overlay
  lifecycle bullet.
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — ledger moves.

## Visible behavior changes

Dice in a multi-die roll now visibly strike one another during the tumble — previously
they landed apart even when several were rolled together. A die that comes to rest tilted
against another die is possible and is not corrected; its face value still reads right.
No change to a single die's roll, no change to which face lands up (RULE-013 unaffected —
the sim runs headlessly first and the remap applies to its result regardless of contacts).

## Deviations

None. The change is exactly the throw-tuning constants named as options in SPEC-045 §5
(spawn arc, spawn ring, inward velocity), plus the `MAX_STEPS` headroom the spec calls for
watching, plus the documented stacked-die rule the spec requires the work item to pick.
