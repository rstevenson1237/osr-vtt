# WI-085 — Select picks up an unlocked background; the `selectedBackgroundId` bridge and `background-adjust-{id}` are retired

**Spec:** SPEC-039 §2 · **From:** IN-062 · **Decisions:** DEC-070 (Assets panel keeps
add/lock/Fit/remove, loses "Adjust on map") · **Agent:** `claude-code` (`sonnet`) ·
**Effort:** high · **Closed:** 2026-08-18

The second link of the WI-084 → WI-085 → WI-086 chain: `MapBackground.locked` existed and
was settable (WI-084) but nothing on the canvas read it. This work item moves the guard
SPEC-038 §3 put on *when the gesture is armed* to *what the object permits* — the ordinary
Select tool now grabs an unlocked background itself, lowest priority behind vertex handles,
whole objects and the lasso, and a locked one is invisible to it.

## Changes made

**Canvas (`VectorMapView.svelte`)**

- `beginSelectGesture` gains a fourth, lowest-priority pick: after a vertex handle and
  `pickObject` both miss, `beginBackgroundGesture` is tried before the press falls back to
  starting a lasso. `pickBackgroundGesture` scans `orderedBackgrounds` topmost-`order`
  first, skips locked ones, and runs the existing `backgroundHitTest` (handle-before-body)
  against each candidate — so a press on what will become the resize handle resizes from
  the very first click, with no separate select-then-resize step.
- Selection state moved off the shared `MapToolController` and into the canvas's own Select
  state: a new local `selectedBackgroundId` (`$state`), mutually exclusive with
  `selectedHandles`/`selectedObjects` (each pick clears the other two, matching SPEC-039 §2)
  and gated on `isGM` and `!locked` in the `selectedBackground` derived, so a lock applied
  mid-selection (by this client or another) drops the gesture immediately.
- The background move/resize handlers (`updateBackgroundDrag`, `endBackgroundDrag`) moved
  from a top-level pointer-event interceptor that ran before every tool, to the `selecting`
  branch of `onPointerMove`/`onPointerUp` — reachable only while the Select tool is active,
  which is the behavior change SPEC-039 §2 exists to make: with no background selected,
  every map tool now works everywhere on the map, over a placed image included.
- `clearSelection()` (Backspace/Delete, tool switch, Escape) now also clears the background
  pick and any in-progress `bgDrag`, so Escape and a tool switch drop a live background
  gesture exactly as they already did for handles/objects.
- The `selected-object` DOM readout reports a picked background as `background:id`, and
  `selection-count` counts it — the same one-object-at-a-time contract every other Select
  kind already had.
- The pure resize math (`apps/web/src/lib/map/background-transform.ts`) is untouched: still
  the one bottom-right, ratio-locked handle. The eight-way corner/edge model is SPEC-039
  §3/WI-086.

**Assets panel (`BackgroundsPanel.svelte`)**

- `background-adjust-{id}` and `selectForAdjust` are removed. `Add` still returns the main
  view to Map (so the referee can see and pick up the image they just placed) but no longer
  selects it — navigation only, per DEC-070's override clause.
- `remove()` no longer clears a panel-owned selection field; a removed background falls out
  of the canvas's own `backgrounds` list and `selectedBackground` self-heals to `null`.
- The row's `class:selected` binding and the `.adjust`/`.bg-row.selected` styles are gone
  with the button they served.

**Controller**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `selectedBackgroundId` and its
  doc comment are removed; nothing else on the controller referenced it.

**Tests and docs**

- `apps/web/tests/e2e/backgrounds.spec.ts` — the move/resize gesture test now drives the
  Select tool (`switchToEditMode` + `selectMapTool(..., 'vector-tool-select')`) and drags
  directly on the canvas instead of clicking the retired button (RULE-005); it also asserts
  `selected-object` reports `background:id`. A new test asserts a locked background is not a
  Select object — the same drag over it starts an empty lasso and leaves the stored rect
  unchanged.
- `README.md` — "The selection model" gains the background pick in the priority order and
  the `selected-object`/`selection-count` mirror note; "Background management" replaces the
  "Adjust on map" bullet with the canvas-selection behavior and drops the retired testid
  from the enumerated list.

**Unrelated CI fix (Deviation)**

- `packages/shared/src/store/room-uploads.emulator.test.ts` — the sole failing check on this
  PR's first CI run was this file's `deleteRoom` sweep test timing out at the default 5000ms
  under GitHub Actions, with the Storage emulator's jar still downloading when the test
  started. Nothing in this work item touches uploads or Storage; bumped the one test to a
  15000ms timeout (user-approved, RULE-015 exception — see Deviations).

## Visible behavior changes

- On the map, with the Select tool active: clicking inside an **unlocked** background picks
  it up and starts moving it; clicking (and dragging) its bottom-right corner resizes it,
  ratio-locked, in the same gesture as the pick. A **locked** background is never grabbed by
  Select — the press falls through to whatever else is under it.
- Picking a background clears any live vertex/object selection, and vice versa; Escape
  drops a background selection the same way it already dropped a handle/object one.
- The Assets → Backgrounds panel no longer has an "Adjust on map" button. **Add** still
  switches back to the Map view, but the referee now picks the new image up with Select
  rather than it being pre-selected.
- With no background selected, every map tool behaves exactly as it did before this change,
  everywhere on the map — including over a placed image, which was not true under the old
  panel-armed gesture.

  Emulator Suite — both updated/new cases pass.
- `room-uploads.emulator.test.ts` run directly against the Firebase Emulator Suite (not the
  sandbox's real-network path above) — both its tests, including the one CI's first run
  timed out on, pass with the 15s budget.
- In the app: open a room as referee → **Assets** → place a background → **Map** →
  switch to Edit → pick **Select** → click-and-drag inside the image to move it, and on its
  bottom-right corner to resize it (ratio locked). Lock it from the Assets panel, return to
  the map, and confirm the same press now falls through — e.g. starts a lasso — instead of
  grabbing the image.
