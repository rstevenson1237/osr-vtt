# WI-115 — The letter is drawn over any art, two-tone by seat, with a real glyph outline

**Spec:** SPEC-048 §4 · **From:** IN-110 · **Agent:** `claude-code` · **Model:** `opus` ·
**Effort:** M · **Closed:** 2026-09-09

## Changes made

- **`apps/web/src/lib/tokens/letter-style.ts` (new)** — the pure half of the render pass, so
  the two-tone rule, the cap and the sizing are testable without a Pixi renderer.
  `letterGlyphs(letter)` caps at `GEN_TOKEN_LABEL_CAP` (3, unchanged) counted in Unicode code
  points, so one emoji is one glyph. `letterStyleFor(token)` returns `null` when there is
  nothing to draw — an absent letter, or an empty/whitespace-only one, absence being a
  legitimate state (SPEC-048 §1) — and otherwise the glyphs, the `LetterMode`
  (`character` | `creature`), the fill, the outline colour and width, and the font size.
  **Two-tone by seat (DEC-086 (a)):** `ownerSeatId` present → white fill (`0xf6f1e6`), black
  outline; absent → black fill (`0x1a1a1a`), white outline. The doc comment states what the
  rule tests — _"is this somebody's character?"_, not _"who created it"_, which nothing
  records. Font size is `renderGenTokenSvg`'s own 30/24/18-over-64 ratios by glyph count,
  scaled by `Token.size`, so a drawn letter is the size of the disc letter it will replace;
  the outline is `max(3, fontSize / 6)` so it scales with the glyph and survives a busy
  uploaded image behind it.
- **`apps/web/src/lib/tokens/letter-style.test.ts` (new)** — 10 cases pinning the pair of
  colour rules, that the colours key off the seat and **not** the disc's lightness (the same
  token on `#ffffff` and on `#101010` styles identically — `discStyle`'s contrast flip is
  replaced, not extended), that a real outline is always present and never equal to the fill,
  the two absence cases, the 3-glyph cap in code points, and the size/glyph-count scaling.
- **`apps/web/src/lib/components/VectorMapView.svelte`** —
  - a `lettersByToken: Map<string, PIXI.Text>` beside `spritesByToken`,
    `backgroundsByToken`, `ringsByToken` and the two badge maps: a **sixth** per-token
    display object, and the first text ever drawn on a token;
  - `syncTokenLetters(list)`, called from `syncSprites` after `syncTokenRings`. It creates a
    `PIXI.Text` lazily for each token `letterStyleFor` returns a style for, sets
    `anchor 0.5` and `eventMode = 'none'` (so it never intercepts a pointer the sprite
    should receive), adds it to the tokens layer **after** the sprite so it draws on top,
    positions it from `sprite.position` — never `token.pos`, which is stale mid-drag, the
    same convention `syncTokenRings` follows — and inherits the sprite's `visible` and
    `alpha`, so a GM-only or away-dimmed token dims whole. A token whose letter is cleared or
    which leaves the list has its `Text` **destroyed**, not hidden;
  - the outline is a genuine stroke on the glyph — `style.stroke = { color, width, join:
'round' }` on the text itself. Pixi paints the stroke first and the fill over it, so the
    letterform keeps its full weight. The disc's ring is not involved;
  - `resyncTokenDecorations` (WI-118) gains one line repositioning the letter, so it tracks a
    live drag with the disc, ring and badges; its doc comment is updated to name the letter
    and to point the per-token-container end state at IN-113;
  - the unmount teardown clears `lettersByToken` with the other token-layer maps;
  - a new `data-testid="token-letter-readout"` DOM mirror — `glyphs:mode` per lettered token,
    sorted and space-joined — because the letters are Pixi-drawn and otherwise invisible to a
    test. A _string_ mirror on purpose, the same idiom as `strokeMeasureText_`: `renderAll`
    reaches this code every frame and an equal string assigns without re-invalidating the
    `$effect`s that call it.
- **`README.md` §II.7** — a new bullet recording §4: the render pass, its five station-keeping
  properties, the two-tone rule and what it does and does not test, why the outline is
  load-bearing rather than decorative, the cap and sizing, that the status ring is untouched,
  that a `gen:disc:` token draws both letters until §5 clears the refs, that the container
  refactor is deliberately IN-113's, and the readout testid. The neighbouring §§1–2 bullet's
  "SPEC-048 §§4–5 are what change those two" is corrected to "§5".
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — WI-115 removed from §2 and its row added
  to `PLAN-COMPLETED.md` §3; the IN-110 row moved from `INTAKE.md` §1.1 to §1.2 (RULE-018).

## Visible behavior changes

- **A token's letter is now drawn on the map over whatever art it has.** A token with an
  uploaded image, a saved URL or bundled art that carries a `letter` shows that letter on top
  of the image — which is the headline of the request, and was impossible while the letter
  lived inside `imageRef`.
- **The letter is two-tone by seat.** A token with an owning seat draws white with a black
  outline; a creature or scenery token draws black with a white outline — regardless of how
  light or dark its colour disc is. The old lightness-based flip no longer decides it.
- **The letter follows a drag**, along with the disc, ring and badges (WI-118's pass, extended).
- **Until SPEC-048 §5 clears the refs, a `gen:disc:` token draws its letter twice** — the
  letter baked into the disc SVG underneath, and the render pass over it, at the same size and
  position. This is the intended intermediate state: §5 is what removes the baked one, and
  landing it early would leave tokens with no letter and no art.
- Nothing else moves: the status ring, the colour disc, the away and broken-image badges and
  the collapsed-group bubble are unchanged.

## How to verify

- `pnpm verify` (lint + typecheck + unit) — green, including the 10 new
  `letter-style.test.ts` cases.
- `pnpm verify:all` (adds rules/store/e2e against the emulator) — green.
- Manually: open a room's map, add a creature batch from the Encounter board (each member gets
  a `letter`), and confirm each token shows its letter in **black with a white outline**. Then
  give a seat's token an uploaded image or a pasted URL and set its letter — the letter draws
  **over the image**, in **white with a black outline**. Drag either across the map: the letter
  stays centred on the token for the whole gesture and at the drop point.
- In a test or the console, `[data-testid="token-letter-readout"]` lists every drawn letter as
  `glyphs:mode`, sorted — e.g. `A:creature B:creature C:character`.

## Deviations

None. WI-118 had already landed, so — as SPEC-048 §4 anticipated — the letter joined a drag
that already re-syncs its token's decorations and no drag fix was needed here, which is what
the section's contingency Deviation was reserved for. The per-token `PIXI.Container` stays
out, as §4 requires, and remains IN-113.
