# WI-191 — Remove the room password

SPEC-057 §3, DEC-116. Single unit (Shape A). IN-165.

## Changes made

- `packages/shared/src/types.ts` — `CURRENT_SCHEMA_VERSION` 32 → **33**; `Room.password`
  removed.
- `packages/shared/src/schemas.ts` — `password` removed from `RoomSchema`.
- `packages/shared/src/store/campaign-store.ts` — `password` removed from `createRoom`'s
  input; the `MAX_ROOMS_SOFT` comment no longer cites `Room.password` as a precedent.
- `packages/shared/src/store/memory-store.ts` — `createRoom` no longer takes or writes
  `password` (`LocalStore` inherits it).
- `packages/shared/src/store/firebase-store.ts` — `createRoom` likewise; the
  `migrateRoomCollections` stamp write also sends `password: deleteField()` when the raw
  room doc carries one, so the stored plaintext is deleted on the referee's next open.
- `packages/shared/src/store/upload-containment.ts` — `MAX_ROOM_UPLOAD_BYTES_SOFT` comment
  no longer cites `Room.password` (DEC-116 names both rewordings).
- `packages/shared/src/migrations/index.ts` — v32 → v33 step, and the exported
  `stripRoomPassword` it is built on (identity by reference on a doc without the key, so it
  is safe to reapply). No `COLLECTION_MIGRATION_STEPS` entry.
- `packages/shared/src/portability/vttcamp.ts` — `archiveToSnapshot` applies
  `stripRoomPassword` after the version walk, so an archive stamped v33+ by another build
  cannot carry a password back in.
- `apps/web/src/lib/components/Lobby.svelte` — the password field, its state and its
  `createRoom` argument are gone.
- Tests: `migrations/index.test.ts` (v32→v33 deletes it and nothing else; an older room
  walked to current loses it; `stripRoomPassword` is identity without the key; no
  collection step, a v32 stamp is behind); `portability/vttcamp.test.ts` (import drops it
  from a v32 archive and from a current-stamped one; what remains round-trips identically);
  `store/firebase-store.contract.test.ts` (emulator: a raw stored password is hidden on
  read and deleted from the document by `migrateRoomCollections`).
- Docs: `README.md` (Create form paragraph; v33 note under "Collection backfills"),
  `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md`.

## Visible behavior changes

- The Create room form in the hosted Lobby no longer shows "Room password (optional —
  stored for later, not enforced yet)". A room name is the whole form.
- The testid `create-room-password` no longer exists (no Playwright spec used it).
- A referee opening an existing room that had a password stored deletes it from the room
  document; nothing about the room looks different.
- Exported `.vttcamp` archives are stamped schema v33 and never contain `password`.

## How to verify

- `pnpm verify` — lint, typecheck, unit (migration and `.vttcamp` tests above).
- `pnpm verify:all` — adds the emulator store suite, including
  `FirebaseStore room password removal (emulators, SPEC-057 §3, v33)`.
- Manually: the hosted Lobby's Create form shows only the room name and the Create button.

## Deviations

- **The Firestore write-back** is an implementation choice the spec leaves implicit: a
  room-doc migration only runs on read (in `roomConverter`), so on its own it would hide
  the password without deleting it. The deletion rides the existing stamp write in
  `FirebaseStore.migrateRoomCollections`, which the v33 bump already triggers once per room
  on the referee's next open — matching DEC-116's "room-doc migrations run on open" impact
  note, with no new store method and no rules change. Covered by the emulator test above.
- No Deviations-budget fixes; no unblocking changes.
