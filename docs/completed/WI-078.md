## WI-078 — Selection consolidation: one Select tool (click + lasso), `selectEdge` retired, multi-select Backspace-delete, loop-preserving vertex removal

**Changes made.**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `MapToolId`'s
  `selectVertex` / `selectEdge` / `selectObject` collapse into one `select`.
  `SelectMode` and `selectModeForTool` deleted; `isSelectTool` is now a single
  comparison. Doc comments on `selectedMapRoomId` and `rotatableSelection`
  updated (the latter now says a multi-selection has no single thing to turn).
- `apps/web/src/lib/map/tool-groups.ts` — the `select` group holds one tool;
  its label is now "Select — click a vertex or object, drag to lasso". The
  header comment's "no one-tool groups left" claim is corrected — Select is a
  one-tool group again, which the existing single-tool fallback already
  handles.
- `apps/web/src/lib/components/MapToolbar.svelte` — three `TOOL_META` entries
  become one: `select`, testid **`vector-tool-select`**, wearing the group's
  `cursor` icon. No Playwright spec referenced the three retired testids
  (`vector-tool-select-vertex` / `-edge` / `-object`), so RULE-005 needed no
  spec rewrite — verified by grep across `apps/web/tests/`.
- `apps/web/src/lib/shell/types.ts`, `components/shell/Icon.svelte` — the
  `vertex` / `edge` / `object` glyphs are removed from `IconId` and the icon
  map; they existed only for the three retired buttons.
- `apps/web/src/lib/map/vector-tools.ts` — the substance of the change:
  - `Handle` is now a single point (`point`, `ring`, `locate` returning one
    `Point`) rather than an `a`/`b` pair with a multi-point `locate`. `ring`
    (`RingVertexRef`) exposes which floor ring the point sits in and where —
    what removal needs and what `locate`'s closure previously kept private.
  - `edgeHandles` and `pickEdgeHandle` **deleted** — edge-dragging is retired
    outright (DEC-060), not hidden.
  - New `sameHandle` (owner + ring + position, never identity — `vertexHandles`
    rebuilds every frame) and `ownerKey`.
  - New `objectBounds` (the lattice box each `pickObject` branch hit-tests),
    `lassoBBox`, and `lassoSelect` — containment, not intersection, returning
    one mixed `{ handles, objects }` set. `ObjectCatalog` extracted so
    `pickObject` and the lasso share one parameter type.
  - New `removeRegionVertices`: re-stitches a ring across the gap, drops a
    collapsed hole, returns `null` when the outer ring falls below 3 points
    (SPEC-037 §4). Rebuilds points as plain objects, so a reactive proxy never
    reaches the store.
  - New `buildHandleRemovalOp`: groups a selection by owner and emits a
    `floorRegionBatch` / `wallsBatch` / per-door ops from a caller-supplied
    snapshot map.
  - New `batch` `VectorEditorOp` kind, with `isNoopVectorOp`, `invertVectorOp`
    (reverses *and* inverts) and `commitVectorOpForward` support — one
    Backspace across several op kinds stays one Ctrl+Z.
- `apps/web/src/lib/map/vector-engine.ts` — `ToolPreviewInput.selectMode` is
  gone; `objectHighlight` becomes `objectHighlights` (a list); new
  `selectedHandles` and `lasso`. `renderToolPreview` draws every handle
  unconditionally while Select is active (selected/hovered ones solid at the
  enlarged radius, matched with `sameHandle`), the live lasso as a faintly
  filled outlined region, and one box per selected object. The edge-highlight
  branch is deleted.
- `apps/web/src/lib/components/VectorMapView.svelte` — one gesture path
  replaces the three-mode branch:
  - `beginSelectGesture` picks a vertex handle first, falls through to
    `pickObject`, and otherwise opens a lasso; `onPointerMove`/`onPointerUp`
    dispatch on `activeDrag` → `objectDrag` → `lasso` → hover. `finishLasso`
    collects and publishes a lassoed room label the way a click does.
  - Selection state is `selectedHandles` (plain local — handles carry closures
    and are compared by value) + `selectedObjects` (`$state`), with
    `selectedObject` derived for the single-target consumers (rotate, the Room
    quick sheet, the `selected-object` readout) and `selectionCount_` as the
    reactive mirror for the new readout.
  - `deleteSelectedObject` → `deleteSelection`: geometry through `applyOp`
    (one undo entry), objects through the same direct store calls as before,
    with a door caught both ways removed only once. Backspace/Delete now fires
    whenever the selection is non-empty.
  - `ActiveDrag` loses `refs`/`offsets`/`vertex` for a single `ref`;
    `beginSelectDrag` → `beginHandleDrag`; `objectHighlightBBox` takes a
    selection and delegates to `objectBounds` (keeping the snap-sized label

    `selection-count` readout beside `selected-object`.

**Visible behavior changes.**

- The Map tools palette shows **one Select button** where there were three.
- Clicking with Select picks a vertex handle if one is under the pointer, an
  object otherwise; dragging over open canvas draws a **lasso** and, on
  release, selects every vertex handle and every object wholly inside it.
- **Backspace/Delete deletes the whole selection**, not just one object.
  Deleting a floor vertex re-stitches its ring; a ring left with fewer than 3
  points drops (a hole is filled back in, an outer ring takes its region); a
  wall or door endpoint deletes its segment. Vertex deletions undo as one
  Ctrl+Z; object deletions remain outside the undo stack, as before.
- **Edge-dragging is gone.** Grabbing a wall, door or floor-ring edge and
  dragging both endpoints together is no longer possible — moving a wall means
  dragging each endpoint. This capability loss was accepted in DEC-060.
- Selected handles now draw solid at the enlarged radius, and several objects
  can show highlight boxes at once.

**How to verify.** `pnpm verify:all` — lint, typecheck, and the emulator
battery (unit + rules + store + Playwright e2e) all green; the run reported
`all suites green`. Note `pnpm verify` (the non-emulator lane) still fails on
`packages/shared/src/store/account-recovery.emulator.test.ts`, which needs the
Auth emulator and fails identically on the unmodified base branch — it passes
under `verify:all`. By hand: open a room's map → Map tools → **Select** → click
a floor corner and drag it; click a symbol and drag it; drag a box over open
canvas across several vertices and a symbol, then press Backspace — everything
in the box goes, and one Ctrl+Z restores the geometry. The `selection-count`
and `selected-object` readouts in `vf-readouts` mirror the Pixi-drawn state.

**Deviations.**

- **The hover highlight started working again.** `ToolPreviewInput.hoveredHandle`
  was compared to the rendered handles with `===`, and `vertexHandles` rebuilds
  its array every frame, so the match never succeeded and the highlight was
  dead. Drawing the *selected* handles needs a by-value comparison
  (`sameHandle`), and applying two different comparison rules in one loop to
  preserve a latent bug would be worse than fixing it; hovering a handle now
  enlarges it, as README's SPEC-033 §4 section already describes.
- **A new `selection-count` testid** was added beside `selected-object`. The
  selection is Pixi-drawn, so a multi-select had no observable surface at all
  otherwise. Additive only — no existing testid moved or changed.
- `objectHighlightBBox` keeps the label's snap-sized highlight box rather than
  adopting `objectBounds`' 1×1 hit-test cell, so the on-screen highlight is
  unchanged from before this work item.
