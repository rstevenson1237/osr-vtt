# WI-213 — Why `room-uploads.emulator.test.ts` hits `RESOURCE_EXHAUSTED`

Investigation (findings only). IN-076. Model `sonnet`, effort medium. Spec: SPEC-034 §4. No product code changed.

## Changes made

None to code. Findings, each logged as an intake item:

1. **The "oversized message" is not a payload.** Reproduced locally against the Firestore emulator: 3 of 9 attempts of the single test failed (`--retry=0`). The reported size differs every time — 5,048,064, 185,207,048, 4,294,738,945 bytes (≈ 2³²) vs the 4,194,304 cap — and the test's rooms hold a handful of tiny docs. A real message cannot be 4 GiB; this is a corrupted gRPC length prefix on the `Listen` stream. The "~434 MiB / accumulated emulator state / listener too broad" diagnoses in `vitest.store.config.ts` and the test's comments are wrong.
2. **Trigger: `deleteRoom`'s fan-out.** The failure lands inside `deleteRoom`, ~0.3 s after "before delete", never in createRoom/joinRoom/upload. `deleteRoom` fires one `getDocs` per collection concurrently: 11 room collections + 9 per map + `maps` + `encounter` + `slots`, ≈ 25+ targets at once on the Firestore SDK's single multiplexed `Listen` stream (a `getDocs` is a watch target).
3. **Confirmed by experiment.** Serializing the `getDocs` calls in `deleteCollectionDocs` (temporary patch, reverted) gave 10 of 10 passes at `--retry=0`, against ~1 in 3 failing before. Not run on the CI runner itself; the CI log was not available to this session.
4. **`retry: 2` masks it** in `vitest.store.config.ts`; the timeout bumps (5 → 15 → 30 → 60 s) never addressed it.

Intake raised: IN-223 (bound `deleteRoom`'s concurrency), IN-224 (remove `retry: 2`, correct the three wrong comments).

## How to verify

Findings are reproducible: with `node_modules/.bin` on `PATH`, run `node scripts/firebase-emulators.mjs exec --project osr-vtt "pnpm --filter @osr-vtt/shared exec vitest run --config vitest.store.config.ts src/store/room-uploads.emulator.test.ts --retry=0"` repeatedly; roughly one run in three fails with `RESOURCE_EXHAUSTED … (N vs 4194304)`, N varying.
