# WI-200 — `verify:all` names the failing test

**Batch 4** (with WI-199). Closed 2026-09-23.

## Changes made

- `scripts/verify.mjs`: Modified to write the full output of each failing step to a temporary log file and print its path, instead of relying on a blind 40-line tail. Now reports `Full output: <path>` and the failing step command.

## Visible behavior changes

When a verification step fails, users now get:
1. The last 40 lines of output (as before, for quick scanning)
2. The full output path for later inspection
3. The exact command to re-run that step

This eliminates the need to re-run the suite just to see earlier lines of a failure.

## How to verify

- Run a verification step that fails (e.g., `pnpm verify` with a lint violation) — output includes "Full output: /tmp/verify-lint-<timestamp>.log" pointing to the complete log.
- Verify the log file exists and contains complete output: `cat /tmp/verify-lint-*.log | wc -l` shows full line count, not the capped 40.
