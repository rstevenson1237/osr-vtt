# WI-089 — Local mode: `LocalStore` over a `.vttcamp` file, the local build, the local lobby

**Spec:** SPEC-041 · **From:** IN-065 · **Agent:** `claude-code` · **Model:** `opus` ·
**Effort:** high · **Closed:** 2026-08-18

The second half of the WI-088 → WI-089 chain. WI-088 amended RULE-009 to state the backend
**per build**, admitting a build with no backend at all; this is that build. The campaign
becomes a `.vttcamp` file on the referee's disk, the store becomes a third `CampaignStore`
implementation over it, and every surface whose meaning is "another person" stops being
rendered. The hosted build is untouched.

**Changes made.**

_`packages/shared` — the store_

- **`src/store/local-store.ts` (new).** `CampaignFile` (the host's `name` / `autosave` /
  `read` / `write`, with `write` required to be atomic), `LocalSaveState`,
  `LOCAL_SAVE_DEBOUNCE_MS = 750`, `MemoryCampaignFile` (an in-memory `CampaignFile` for
  tests), and **`LocalStore extends MemoryStore`**. It adds persistence and nothing else:
  `openCampaign()` (`file.read` → `archiveToSnapshot` → `importRoom`, so migration-on-import
  and the RULE-014 "unsupported schema" refusal come for free), `createCampaign()`,
  `campaignRoomId`, `save()` / `flush()` / `dispose()`, and
  `saveState()` / `subscribeSaveState()`. `createRoom` and `importRoom` are overridden to
  bind the **first** room as the campaign; `deleteRoom` unbinds it. `persist()` re-checks
  `dirty` after each write, because mutations land freely while the `await`s are in flight.
  A failed write leaves the store dirty and reports the error rather than pretending the
  file is current.
- **`src/store/memory-store.ts`.** A mutation observer: `ReactiveValue`/`ReactiveCollection`
  gain an `onMutate` hook, `RoomBucket.watch(notify)` wires every value in a room (including
  the lazily created `dragging`/`yjs` channels and every `MapBucket`) to it, and
  `MemoryBackend.onChange(cb)` exposes it. Deliberately coarse — *that* something changed,
  never what — because the write-back is whole-file. Also: `importRoom` now keeps each
  document's own `id` in its body, matching what this store's own writers already do (see
  Deviations).
- **`src/store/firebase-asset-store.ts` (new)** — `FirebaseStorageAssetStore`,
  `listRoomUploadRefs` and `deleteRoomUploads`, moved verbatim out of `asset-store.ts`,
  which is now free of the Firebase SDK (see Deviations).
- **`src/store/local-store.contract.test.ts` (new)** — the full `CampaignStore` contract
  suite against `LocalStore`, with persistence live.
  **`src/store/local-store.test.ts` (new)** — eight cases the contract cannot see: the
  file written on create, the round-trip through the file, a 20-mutation burst collapsing
  into one debounced write, the manual path never writing on its own, a failed write, save-
  state publication, refusal of an empty/unsupported archive, and no writes after the
  campaign room is deleted.
- **`package.json`** — `"sideEffects": false`. **`src/index.ts`** — exports the two new
  modules. **`src/store/firebase-store.ts`**, **`room-uploads.emulator.test.ts`**,
  **`asset-store.test.ts`** — imports repointed at `firebase-asset-store.js`.

_`apps/web` — the build boundary_

- **`src/lib/firebase/client.ts`** — now also owns `getAssetStore()` (moved from
  `assets.ts`, which no longer imports Firebase), and exports `APP_MODE`, `MULTIPLAYER` and
  `AppRoot`.
- **`src/lib/firebase/client.local.ts` (new)** — the local counterpart with the same
  exported surface: a `BundledAssetStore`, `openLocalCampaign` / `createLocalCampaign`, and
  `AppRoot = LocalRoot`. No Firebase import of any kind.
- **`vite.config.ts`** — mode `local-build` aliases the specifier `…/firebase/client` to
  `client.local.ts` and builds to `dist-local`. A resolver decision, not a runtime branch.
  (`local` itself is refused by Vite: it collides with the `.env.*.local` postfix.)
- **`package.json` (both)** — `pnpm build:local`, plus `preview:local`.
  **`.gitignore`**, **`.prettierignore`**, **`eslint.config.js`** — ignore `dist-local`.

_`apps/web` — the app_

- **`src/App.svelte`** — reduced to the two context sets (`ASSET_STORE_KEY`,
  `SESSION_MODE_KEY`) plus `<AppRoot />`; the route logic moved verbatim into
  **`HostedRoot.svelte` (new)**, which is also where the hosted `setContext(CAMPAIGN_STORE_KEY, getStore())`
  now lives.
- **`LocalRoot.svelte` (new)** — two states, no routing. **`LocalLobby.svelte` (new)** —

- **`src/lib/local/campaign-file.ts` (new)** — the two `CampaignFile` implementations:
  `showOpenFilePicker`/`showSaveFilePicker` handles (autosave, atomic via `createWritable`)
  and the download-plus-file-input fallback (manual).
- **`src/lib/context.ts`** — `SESSION_MODE_KEY` and the `SessionMode` interface.
- **Mode gating** (one flag, read in six containers): `RoomShell.svelte` (join gate →
  automatic "Referee" seat, presence subscription/heartbeat/publish/clear, the bottom bar's

  (room-id pill, copy-invite, `AccountControls`, presence chips and head count),

  and publishes), `MapToolbar.svelte` (the Ping tool), `AssetsActivity.svelte` (the uploads
  note).

**Visible behavior changes.**

**Hosted build: none.** Every gate added is `{#if multiplayer}`, and `MULTIPLAYER` is `true`
there; no testid moved, was renamed or was removed (RULE-005). One string changed: the
uploads-disabled note now reads "the hosted project's Blaze plan" instead of "the Firebase
project's Blaze plan" (see Deviations).

**Local build (new, `pnpm build:local`):** a lobby with Open campaign… / New campaign… and
no sign-in, rooms list or join code; no join gate — the referee is seated automatically;
no invite link, QR, room id, presence chips, disconnect badges, account controls, Players
section, GM transfer, inactive-seat pruning or Delete room; no peer cursors, pings or peer
carve strokes, and no Ping tool; a campaign-file pill showing the file name and save state
with Save and Close; on non-Chromium browsers, an explicit warning that saving is manual.

**How to verify.**

```sh
pnpm verify:all          # lint + typecheck + unit + rules + contract (×3 stores) + e2e
pnpm build && pnpm build:local
grep -rioE "firebase|firestore|osr-vtt|appspot|identitytoolkit|firebaseio" apps/web/dist-local | wc -l   # 0
```

Then, by hand: `pnpm --filter @osr-vtt/web preview:local`, open the served page in Chrome,
**New campaign…**, name it, pick a path; draw on the map; watch the pill go
Saved → Unsaved changes → Saved; reload the page and **Open campaign…** the same file — the
map, tokens and log come back. In Firefox or Safari the same flow shows the manual-save
warning and Save downloads the file. Open the hosted build (`pnpm dev`) and confirm the
invite link, presence chips, Players section and Ping tool are all still there.

**Deviations.**

1. **`MemoryStore.importRoom` dropped every document's `id`** (required to unblock,
   RULE-015 exception). It stored `{...body}` with `id` destructured out, while every other
   writer in that store stores the id *in* the body — `MemoryStore` has no converter to
   re-attach a document key the way `FirebaseStore` does. Hosted builds never noticed
   (import is a rare path there); local mode loads **every** campaign through it, so an
   opened campaign came back with id-less tokens and maps. Fixed in place; the round-trip
   test in `local-store.test.ts` asserts the token id survives.
2. **`FirebaseStorageAssetStore` moved to its own module, and `packages/shared` is marked
   side-effect-free** (also required to unblock). Without both, the local bundle still
   carried the Firebase SDK: `BundledAssetStore` is in every build, so `asset-store.ts` is
   always in the module graph, and a top-level `import … from 'firebase/storage'` beside it
   is a side-effectful import the bundler must keep. Nothing else changed in the moved code.
3. **One hosted string reworded.** The uploads-disabled note said "the Firebase project's
   Blaze plan". A local build carries both branches of that `{#if}` in its bundle (Svelte
   cannot fold a runtime condition), so the word survived into `dist-local` and would trip
   the naive grep SPEC-042 §3 asks for. "the hosted project's Blaze plan" means the same
   and takes the residue to zero.
4. **Shared rolls and roll readiness are still reachable in a local build** — the one item
   in SPEC-041 §3's removed list that could not be removed by not rendering. In this app the
   *only* way to open a `sharedRoll/current` is the encounter board's **Call for
   initiative**, and the referee's own Roll and "Apply results to initiative" actions live
   in `SharedRollReadiness`. Removing those surfaces would remove initiative from the
   encounter board, which §3 explicitly **keeps**. Both components already render nothing
   unless a call is open, so in a local build they appear only during the referee's own
   initiative call and never show another seat. Reworking initiative so it does not travel
   through the shared-roll document is a change to the encounter contract, not a decision
   about what to render, and belongs in its own intake item.
5. **The Vite mode is `local-build`, not `local`.** Vite refuses `local` as a mode name —
   it collides with the `.env.*.local` postfix. The script SPEC-042 §2 names,
   `pnpm build:local`, is unchanged.
6. **`pnpm build:local` shipped here** rather than waiting for WI-090. SPEC-042 §2 lists it
   as part of the artefact, but "the local build mode" is WI-089's scope and the mode is
   untestable without a way to invoke it. The launcher, the distribution README, the release
   process and the **CI** assertion remain WI-090's.
