## WI-077 — Capture tool moves to the battle-map quick sheet; `capture` removed from `TOOL_GROUPS`

**Changes made.**

- `apps/web/src/lib/map/tool-groups.ts` — `capture` removed from the `shapes`
  group's `tools` array (and the comment explaining why it used to share that
  group's gesture). New exported `PaletteToolId = Exclude<MapToolId,
  'capture'>`, and `MapToolGroup.tools` is now typed `PaletteToolId[]` — the
  type system now enforces that `capture` can never re-enter a group by
  accident. `groupForTool` casts its lookup (`tool as PaletteToolId`) with a
  comment explaining why that's safe: `.includes` only compares by value, and
  `capture` correctly finds no match in any group. Its doc comment now says so
  explicitly instead of claiming every `MapToolId` is grouped.
- `apps/web/src/lib/map/tool-groups.test.ts` — new `GROUPED_TOOLS` (every
  `MapToolId` but `capture`); "places every tool in exactly one group" now
  asserts against that list and that `capture` is absent from
  `toolsInGroupOrder()`. New test asserting `groupForTool('capture')` is
  `undefined` — the named exemption DEC-066 called for. The old
  `groupForTool('capture')?.id).toBe('shapes')` assertion is gone.
- `apps/web/src/lib/components/MapToolbar.svelte` — `capture` removed from
  `TOOL_META` (now typed `Record<PaletteToolId, …>`, so a future omission
  fails typecheck instead of rendering `undefined`); `visibleGroups`'s filter
  drops the `id !== 'capture' || isGM` clause, leaving only the `toolSubset`
  filter (SPEC-029 §4's battle-map View-only restriction). The capture is no
  longer reachable from this palette at all, for any seat.
- `apps/web/src/lib/components/shell/sheets/BattleSheet.svelte` — new
  **Capture area** button (`data-testid="vector-tool-capture"` — the testid
  moves here per DEC-066), `onclick={() => (controller.activeTool =
  'capture')}`. The sheet body is restructured so the button shows whenever
  the current map is ordinary (not itself a battle map): above the existing
  pending-capture preview/Start UI, or above the "draw a capture rect" hint
  when nothing is pending yet. Doc comment updated to describe the new entry
  point.
- `apps/web/src/lib/components/VectorMapView.svelte` — `captureAllowed`'s doc
  comment updated: it used to say "`MapToolbar` never renders the Capture
  button for a non-GM seat"; now describes the battle-map quick sheet's
  Capture area button as the (GM-gated) entry point instead. The gesture
  logic itself (`captureAllowed = tool === 'capture' && isGM`) is unchanged.
- `apps/web/tests/e2e/helpers.ts` — new `armCaptureTool(page)`:
  `selectMapTool`'s counterpart for `capture`, opening the battle quick sheet,
  clicking the Capture area button, and closing the sheet again.
- `apps/web/tests/e2e/battle-map-capture.spec.ts` — every capture-arming call
  site now goes through `armCaptureTool` (or, in the Free-snap test, an
  explicit maptools-sheet Snap selection followed by `armCaptureTool`) instead
  of `selectMapTool(page, 'vector-tool-capture')`. The "capture tool is
  referee-only" test now checks the Capture area button inside the **battle**
  sheet for the GM, and that a player never even sees the battle sheet's
  toggle (`quick-sheet-toggle-battle`) — the sheet itself is GM-gated, so
  there's no separate palette-level check left to make. Unused `selectMapTool`
  import removed.
- `apps/web/tests/e2e/battle-map-lifecycle.spec.ts` — both capture-arming call
  sites switched to `armCaptureTool`. Unused `selectMapTool` import removed.
- `README.md` — the Tools section's "two things narrow `MapToolbar`'s
  `TOOL_GROUPS`" paragraph is now one (`toolSubset` only), pointing to the
  Battle maps section for `capture`. The Battle maps section's Capture
  paragraph rewritten to describe the sheet-button entry point and the
  `TOOL_GROUPS` exemption; the Battle map quick sheet paragraph now mentions
  the Capture area button. The quick-sheets table's `battle` row updated.
- `docs/spec/SPEC-029.md` — status header's "Reopened … Closes again when
  WI-077 lands" now records the closure directly.
- `PLAN.md` — WI-077 removed from §2; execution order line updated.
- `INTAKE.md` — IN-059's row moved from §1.1 to §1.2.
- `PLAN-COMPLETED.md` — row added to §3.

**Visible behavior changes.** The Capture tool no longer appears in the Map
tools palette for anyone (it used to be filtered out for non-GM seats, but
still occupied a slot in the `shapes` group for the referee). Starting a
battle map now begins with a **Capture area** button on the Battle map quick
sheet; clicking it arms the same click-and-drag / click-then-click gesture on
the map canvas as before. The canvas gesture, its whole-cell snapping, its
preview colour, and the rest of the Start/Exit flow are unchanged.

**How to verify.** Join a room as the referee → open the Battle map quick
sheet (referee-only) → click **Capture area** → drag a box on the map canvas
→ the sheet shows the preview and a **Start battle map** button. Open the Map
tools palette and confirm no Capture button appears there for any seat.
Automated: `pnpm verify` — lint and typecheck are green; `apps/web`'s 334 unit
tests (including `tool-groups.test.ts`'s new/updated cases) and 599 of
`packages/shared`'s 600 unit tests pass. The one failure,
`account-recovery.emulator.test.ts`, requires the Firebase Auth emulator
(`firebase auth/network-request-failed` with no emulator reachable) and fails
identically on the unmodified base branch in this sandbox — a pre-existing
environmental gap unrelated to this change, not something WI-077 introduced or
is in scope to fix. `pnpm verify:all` (rules/store/e2e against the emulator)
was not run: this sandbox has no cached emulator binaries and no network path
to fetch them.

**Deviations.** None. The implementation follows DEC-066 as recorded: the
sheet button arms the existing canvas gesture, `capture` leaves `TOOL_GROUPS`
entirely (not merely hidden), and the testid relocation plus the four
Playwright touch points in `battle-map-capture.spec.ts` /
`battle-map-lifecycle.spec.ts` shipped in this PR.
