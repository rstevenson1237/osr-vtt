# WI-227 — Background sprites and the move/resize gesture leave `VectorMapView`

**Closed 2026-10-18.** From IN-200. SPEC-060 §2–§5, DEC-126. Model target `sonnet`, run on
`sonnet`; effort `high`.

---

## Changes made

- `apps/web/src/lib/map/map-backgrounds.svelte.ts` (new): the `MapBackgrounds` seam
  controller. It owns the `bgSprites` map and load-sequence guard, the clear colour
  (`applyColor`), the sprite pass (`apply`, per-image settle, broken-image report, live rect
  kept under a drag), the live rect read by the composers (`liveRect`, `dragging`) and the
  Select gesture: `pointerDown` (GM-only pick, topmost unlocked image, handle before body),
  `pointerMove` (move/resize, sprite moved directly, invalidates `tools`), `pointerUp` (one
  settled `setBackgroundTransform`, none for a click that never moved), `cancel()` and
  `destroy()`. It is handed one coordinate conversion, `toSpace` (raw lattice point on a
  square map, the world pixel on a hex map — RULE-006), and reports a pick through `onPick`.
  Nothing in it is `$state`, as before.
- `apps/web/src/lib/components/VectorMapView.svelte`: constructs `MapBackgrounds` as `bgCtrl`
  and deletes `bgSprites`, `bgLoadSeq`, `bgDrag`, `applyBackgroundColor`, `applyBackgrounds`
  and the pick/begin/update/end/live-rect functions plus `handleHexBackgroundMove`.
  `beginSelectGesture`, `handleHexPointerDown`, the hex pointer-move branch, `onPointerMove`,
  `onPointerUp`, `clearSelection` and the `toolsInputs` composer call the controller in the
  same branch positions. `onPointerDown`/`onPointerMove`/`beginSelectGesture` now also receive
  the world pixel so the controller converts for itself (SPEC-060 §4). `selectedBackgroundId`
  and the selection exclusion stay in the component (WI-229 moves them). Unused imports
  removed.
- `apps/web/src/lib/map/map-backgrounds.test.ts` (new): 14 tests with a fake `invalidate`,
  store and layer, no browser — sprite order and placement, removal, an unloadable image,
  a superseded pass, hex scaling, clear colour, player and locked picks, topmost pick, move
  and single write, no write for a stationary click, corner resize, cancel, and a hex drag
  that never calls the lattice conversion.
- Docs (RULE-018): `README.md` → "Seam controllers" names `MapBackgrounds` and "Background
  management" points at it; `docs/spec/SPEC-067.md` §1 names the `onPick` callback in place of
  `beginBackgroundGesture`; `PLAN.md`, `PLAN-COMPLETED.md` and `INTAKE.md` bookkeeping.

## Visible behavior changes

None. Backgrounds draw, pick, move, resize and write exactly as before, on square and hex
maps.

## How to verify

  through.

## Deviations

- The work item says the controller "calls the existing `patchBackground`". `patchBackground`
  is a private helper inside the stores; the gesture's only store call is the public
  `setBackgroundTransform`, which is what the controller calls, unchanged.
- The work item says the controller is handed "the coordinate conversions the map's grid kind
  declares". It is handed the single `toSpace` (lattice on square, identity on hex), so the
  seam holds no lattice conversion it could reach from a hex map.
- `onPointerDown`, `onPointerMove` and `beginSelectGesture` gained a `worldPx` parameter so
  the controller receives raw world pixels (SPEC-060 §4); their callers were all in the file.
- No RULE-015 unblock or Deviations-budget fix.
- Not run: the full `pnpm verify:all`; the e2e run was the three affected specs.
