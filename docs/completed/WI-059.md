## WI-059 — Carve: simplification tolerance bounded by the stroke's width

> **Verified.** `pnpm lint` clean; `pnpm typecheck` 0 errors; the targeted
> `boundedTolerance`/`tolerance` and `map-tool-controller` unit suites pass (9 and 11
> tests). Full `pnpm test:all:emulators` not run — no store/rules/schema involvement.

**Changes made.**

- `packages/shared/src/map/vector/tolerance.ts` — new `TOLERANCE_WIDTH_FRACTION = 0.25`
  and `boundedTolerance(policy, width, exactBand)`, implementing SPEC-028 §10: bound the
  policy tolerance to `width · k`, force exactly `0` when `exactBand` is true.
  `toolTolerance` itself is unchanged; `boundedTolerance` composes with it.
- `packages/shared/src/map/vector/tolerance.test.ts` — four new cases: normal-width
  unaffected, sub-half band bounded down, `exactBand` forces 0, slider override bounded.
- `apps/web/src/lib/components/VectorMapView.svelte` — new `strokeTolerance()` helper:
  picks `bandWidth` for Corridor/Path and `width` for other floor tools (Carve included,
  DEC-032), sets `exactBand` for Corridor/Path off `free` snap, calls `boundedTolerance`.
  `commitFloorStroke`/`commitFogStroke` both call it in place of the bare `toolTolerance`.
- `README.md` — the Carve pipeline's "Simplification" step now states the per-tool policy
  is a ceiling, not the number used, and names the width bound and the snapped-exact case.
- `SPEC.md` — SPEC-028's status line records §10 as shipped at WI-059, and §10 gains a
  "Shipped in WI-059" note naming the implementation (`boundedTolerance`, `k = 0.25`,
  `strokeTolerance()`'s width/exactBand derivation).
- `PLAN.md` — IN-039 retired from §1.1 to §1.2; the upcoming table, execution order, and
  "Cleared gates" paragraph updated; this entry added.

**Visible behavior changes.** A Path or Corridor drawn with a sub-half-cell width (⅛ or ¼
cell, SPEC-028 §7) under Cell or Half snap no longer collapses toward a sliver on commit.
A free-snap Path at a narrow width is simplified more gently (bounded by its own width);
at or above default widths it's unaffected, since `width · 0.25` already sat above the
existing policy values. Room, N-gon and Polygon are unaffected — their policy tolerance is
already `0`.

**How to verify.** Set Path/Corridor to Cell snap, pick the ⅛ or ¼ band width, draw a long
bent run — the band keeps full width along every leg. Switch to Free snap with a narrow
Path width and confirm the stroke reads smooth, not faceted/collapsing.
`pnpm --filter @osr-vtt/shared exec vitest run tolerance` and
`pnpm --filter apps/web exec vitest run map-tool-controller` reproduce the suites.

**Deviations.** None.
