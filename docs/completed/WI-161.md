# WI-161 — Tool hotkeys from TOOL_GROUPS

SPEC-054 §7. Part of Batch 2b (WI-159, WI-161, WI-164, WI-165) — one pull request, one
combined summary.

**Changes made**

- `apps/web/src/lib/map/tool-groups.ts` — each `MapToolGroup`'s `tools` field changes from
  a bare `PaletteToolId[]` to a `ToolEntry[]` (`{ id: PaletteToolId; key?: string }`), so
  the hotkey is a field on the tool's own `TOOL_GROUPS` entry per the spec's wording.
  `groupForTool`, `toolsInGroupOrder`, `VIEW_TOOL_IDS` read `.id` off each entry, unchanged
  in their own return shape. Two new exports: `keyForTool(tool)` and `toolForKey(key)`
  (case-insensitive), the single source both the palette and the global handler read. Keys
  bound: V=select, H=pan, E=eye, M=measure, P=ping, R=room, C=corridor, W=wall, D=door,
  T=text (WI-165). Every other tool stays unbound.
- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — new `lockHintVisible` state and
  `trySetTool(id)` method: the one path a tool switch goes through, whether from a palette
  click or a hotkey. It drops a tool outside the current battle-map/hex-crawl subset
  (mirroring `MapToolsSheet`'s own `toolSubset` derivation) and shows the existing
  View-lock hint (SPEC-054 §4) instead of arming a disabled drawing tool, exactly as a
  click already did.
- `apps/web/src/lib/components/MapToolbar.svelte` — both tool rows' `onclick` now call
  `onTrySetTool(id)` instead of the inline `locked ? showLockHint() : (activeTool = id)`;
  the local `lockHintVisible`/`showLockHint`/timer are removed in favour of the
  controller's, passed in as a prop. The palette tooltip appends `(key)` when a tool has
  one bound.
- `apps/web/src/lib/components/shell/MapToolPalette.svelte` — wires `lockHintVisible` and
  `onTrySetTool` from the shared `MapToolController` into `MapToolbar`.
- `apps/web/src/lib/components/RoomShell.svelte` — `onGlobalKey` gains a hotkey branch:
  while the Map view is the main view, and after the existing modal/typing-target/
  Ctrl-Meta-Alt guards, `toolForKey(e.key)` resolves the pressed key and calls
  `mapCtrl.trySetTool(tool)`. Digits, `?` and `L` stay reserved (handled earlier in the
  same function, never reachable here).
- `apps/web/src/lib/components/shell/ShortcutSheet.svelte` — a "Map tools" section lists
  every bound hotkey, read straight off `TOOL_GROUPS` so this sheet can't drift from the
  handler.
- `apps/web/src/lib/map/tool-groups.test.ts` — updated the one test asserting `.tools`'
  bare-id shape, and added coverage for `keyForTool`/`toolForKey` (round-trip, reserved
  keys, case-insensitivity).
- `apps/web/src/lib/shell/map-tool-controller.test.ts` — new tests for `trySetTool`: sets
  the tool in Edit, shows/clears the lock hint under View, never locks a View-group tool,
  ignores a tool outside the active battle-map/hex-crawl subset.

**Visible behavior changes** — pressing V/H/E/M/P/R/C/W/D/T while the Map view is active
switches to the matching tool (unless a text field or dialog has focus, or Ctrl/Meta/Alt
is held). The palette tooltips now show the bound key. The `?` shortcuts sheet lists a new
"Map tools" section. A hotkey for a disabled drawing tool under the View lock shows the
same "Switch to Edit to draw" hint a click already did.

**How to verify** — `pnpm verify` green. Manually: open the Map view, press `R`/`C`/`W`/`D`
etc. and confirm the tool switches; press `?` and see the new section; switch to View mode
and press `W`, confirming the lock hint appears instead of arming Wall.

**Deviations** — none.
