# WI-188 — Hex fog: `HexTile.revealed` and the Reveal / Hide hex tool

SPEC-056 §9, DEC-113. Single unit (Deceptive). IN-192.

## Changes made

- `packages/shared/src/types.ts` — `CURRENT_SCHEMA_VERSION` 31 → **32**; `HexTile` gains
  `revealed?: true` (absent = hidden; `false` never stored), documented as a fourth field
  that keeps a tile's document alive.
- `packages/shared/src/schemas.ts` — `HexTileSchema.revealed: z.literal(true).optional()`.
- `packages/shared/src/converters.ts` — `hexTileBody` writes `revealed`; new
  `hexTileHasContent(tile)`, the one sparseness test both stores now use.
- `packages/shared/src/store/campaign-store.ts` — new method
  `setHexesRevealed(roomId, mapId, hexes, revealed)`: sets/clears the flag on a set of
  hexes in one batched write, leaves terrain/contents/note alone, creates flag-only tiles,
  deletes a tile left with nothing, ignores duplicates, no-ops on an empty list.
- `packages/shared/src/store/memory-store.ts` — implements it (one `setMany` + one
  `deleteMany`, the in-memory analog of one commit); `patchHexTile` refactored onto a pure
  `nextHexTile` and now carries `revealed` through the three existing setters. `LocalStore`
  inherits both.
- `packages/shared/src/store/firebase-store.ts` — implements it as one read-then-write
  transaction per ≤400 hexes (`DELETE_BATCH_LIMIT`); `patchHexTile` carries `revealed`
  through and uses `hexTileHasContent`.
- `packages/shared/src/store/campaign-store.contract.ts` — two contract tests (all three
  stores): a set revealed in one call incl. a duplicate, negative keys, a painted tile and
  flag-only tiles; hiding deletes a flag-only tile, keeps a painted one without the flag,
  leaves no stub for an untouched hex, and the setters keep the flag (painting a revealed
  hex, then clearing the paint, leaves a flag-only tile).
- `packages/shared/src/migrations/index.ts` + `index.test.ts` — v31 → v32 no-op step (no
  document half, no `COLLECTION_MIGRATION_STEPS` entry, per DEC-113's "no backfill");
  tests that the room doc passes through unchanged and a v31-stamped room re-stamps
  without walking a step.
- `packages/shared/src/portability/vttcamp.test.ts` — round-trip of revealed tiles on a
  fogged hex map, a flag-only tile included.
- `packages/shared/src/map/hex/axial.ts` + `axial.test.ts` — new pure
  `axialLine(a, b)`: every hex on the straight line, ends included, each adjacent to the
  next; tested over every pair of the sample hexes.
- `apps/web/src/lib/map/hex-fog.ts` + `hex-fog.test.ts` (new) — the pure half: the
  revealed-key set, `hexFogged`, the stroke (start / extend with `axialLine` / the changes
  it commits), the live preview set, and Reveal all / Reset's hex lists.
- `apps/web/src/lib/shell/map-tool-controller.svelte.ts`, `map/tool-groups.ts` (+ both
  tests) — new `MapToolId` `hexFog`, appended to `HEX_TOOL_IDS`, excluded from
  `PaletteToolId`.
- `apps/web/src/lib/components/MapToolbar.svelte` — **Reveal / Hide hex** button (new
  testid `hex-tool-fog`) in the hex-only Paint row, rendered only for the referee while the
  map's fog is on.
- `apps/web/src/lib/map/vector-engine.ts` — `renderFog` takes an optional
  `hex: { size, revealed }`; a hex map's fog is a viewport-plus-one-hex fill,
  inverse-stencil-masked by the revealed hexes (mask rebuilt only when the set changes).
- `apps/web/src/lib/components/VectorMapView.svelte` — the tool's press / drag / release

- `apps/web/tests/e2e/hex-map.spec.ts` — new spec: tool absent until fog is on; click

## Visible behavior changes

- On a hex map with fog on (Session settings → Fog of war), players see every hex that
  has not been revealed as fog — terrain, contents, symbols, roads, rivers and coordinate
  pills are covered; the referee sees the same fog as a ~0.4 wash.
- The referee's Map tools sheet gains **Reveal / Hide hex** in the hex Paint row while fog
  is on. Click or drag: starting on a fogged hex reveals every hex crossed, starting on a
  revealed one hides them; the change lands on release. Its hint says so.
- **Reveal all** / **Reset fog** (expanded sheet) now work on hex maps: Reveal all reveals
  every hex carrying terrain, contents or a note; Reset fog hides every revealed hex.
- For a player on a fogged hex: no note on hover, Select/Label do not pick it, Terrain does
  not paint it; tokens standing in fogged hexes are not drawn for players.
- Rooms move to schema v32 on open; nothing visible changes on existing hex maps until the
  referee turns fog on for them. Square maps are unchanged.

## Deviations

None against the gate: no rules change (hex tiles were already member-or-GM write with no
field validation), no testid moved, no Deviations-budget fix. Two readings of SPEC-056 §9
that the text left open, recorded in the spec in place rather than decided silently:

- **No mode control on the tool** — the first hex of a stroke decides reveal vs hide,
  the Terrain tool's toggle carried over to a brush.
- **Reveal all on a hex map** reveals every hex carrying terrain, contents or a note; an
  infinite plane has no "whole floor" to reveal.

Two consequences implemented as part of "players see unrevealed hexes as fog", named here
because they reach beyond drawing: tokens in fogged hexes are hidden from players (square
fog's rule, which without a hex branch would have hidden *every* token on a fogged hex
map, since `fogRegions` is empty there), and a player cannot pick, label or terrain-paint a
fogged hex, so the sheet cannot show or blindly overwrite its note. The rendering uses an
inverse stencil mask rather than square fog's `cut()` holes — adjacent revealed hexes
share edges, which a cut path does not triangulate reliably — and was checked by
screenshot for both roles before this record was written.
