# WI-192 — Render benchmark

SPEC-057 §4.1, DEC-118. Single unit (Shape A). IN-175. Model `sonnet`, effort medium.

## Changes made

- `apps/web/bench/render-large-dungeon.html` / `.ts` (new) — drives the real
  `createVectorMapEngine` through the same call sequence `renderAll` makes (grid, hex
  clears, scene, doors, overlay objects, annotations, fog, alignment, tool preview with
  the Select tool's `vertexHandles`) over a synthetic dungeon: 408 floor regions (144
  rooms, a quarter of them 16-gons, plus corridors), 144 walls, 288 doors, 60 symbols,
  144 room labels, fog revealing half the regions. Three cases — rest, vertex drag
  (one vertex moved, `buildVectorScene` rebuilt per move), pan — each split into JS time
  and the frame that follows.
- `apps/web/bench/run.mjs` — takes the page name as an argument (default unchanged:
  `hex-overlay-cost`).
- `README.md` — new "Render budget and the measured figure" section after the layer model.
- `DECISIONS.md` — the Postponed "Full-viewport-diff rendering" entry annotated with the
  number.
- `PLAN.md`, `PLAN-COMPLETED.md` — row moved.

## Visible behavior changes

None. Bench code and docs only; nothing under `src/` changed.

## How to verify

`node apps/web/bench/run.mjs render-large-dungeon` (prints JSON; ~1 minute). Three runs
here gave drag JS 42.1 / 43.4 / 44.3 ms, rest 18.8 – 27.1 ms, `buildVectorScene` ≈ 25 ms,
pan ≈ 2 ms. `pnpm verify` for lint/typecheck.

## Result for WI-193's gate

**Over budget on a vertex drag** (≈ 43 ms of JS per move against 33 ms), within budget at
rest. WI-193 is therefore not denied on the number. About 60% of the drag is the per-move
LoS rebuild, so the "rebuild on release" half of SPEC-057 §4.2 addresses the larger share
on its own.

## Deviations

- **The budget did not exist.** SPEC-057 §4.1 says to record against "the budget stated in
  `README.md`", but `README.md` states none (only "the standing Chromebook budget", no
  number). I wrote one down — 33 ms of main-thread JS per interaction frame, the 30 fps
  floor `DECISIONS.md` already uses for the dice overlay — as part of the README section.
  **The verdict depends on that choice** (at 60 fps / 16.7 ms rest would also be over).
  Please confirm or replace it at WI-193's gate.
- The container has no GPU, so the raster column is software (SwiftShader) and is reported
  as a ratio, not a budget figure; the verdict rests on the JS column.
- IN-175 stays in `INTAKE.md` §1.1: its second work item, WI-193, has not landed.
- One missing-asset 404 appears in the page console (an asset ref unresolved in the
  bench); it does not affect the timed geometry work.
