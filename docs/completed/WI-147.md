**Spec:** SPEC-042 §§2, 5 · **From:** IN-149, IN-070, IN-073 · **Agent:** `claude-code` ·
**Model:** `sonnet` · **Effort:** M · **Closed:** 2026-09-20

## Changes made

- New `.github/workflows/release-local.yml`. Triggers on a `v*` tag push; a `create-release`
  job creates the GitHub release once, then a `linux`/`macos`/`windows` matrix each: builds
  `pnpm build:local` with `VITE_APP_VERSION` set to the tag, re-runs SPEC-042 §3's
  Firebase-strip grep against the fresh `dist-local` (fails the release on a hit), builds
  that platform's launcher as a Node Single Executable Application, zips it with
  `dist-local` (as `app/`) and the distribution README, and attaches the platform zip to
  the release. Independent of `deploy.yml` and `ci.yml` — neither is touched, reused or
  triggered.
- New `apps/web/scripts/launcher/server.cjs` + `sea-config.json`. The SEA's `main`: a
  dependency-free static file server (node: builtins only) that serves the `app/`
  directory beside the launcher binary on `127.0.0.1:4173`, falls back to `index.html` for
  the hash-routed SPA, and opens the OS default browser.
- New `docs/distribution/LOCAL-RELEASE-README.md` — SPEC-042 §2's four bullets: what local
  mode is/isn't, the browser-support save split, URL-vs-bundled assets, and that backing up
  the `.vttcamp` file is the user's job. Copied into each release zip as `README.md`.
- `apps/web/vite.config.ts` — a `define` stamping `import.meta.env.VITE_APP_VERSION` from
  the `VITE_APP_VERSION` env var, falling back to the literal `'dev'` (DEC-104). No mode
  guard: harmless in the hosted build, which renders it nowhere.
- `apps/web/src/vite-env.d.ts` — `VITE_APP_VERSION: string` added to `ImportMetaEnv`.
- `apps/web/src/lib/components/LocalLobby.svelte` — one render site, a footer line reading
  `import.meta.env.VITE_APP_VERSION`, `data-testid="local-app-version"`.
- `README.md` — new "Releasing a local build" subsection under Local mode, covering the
  workflow's four steps and the version render site.
- This session: this file, `PLAN-COMPLETED.md` §3 row added, the item removed from
  `PLAN.md` §2 along with its now-stale ordering references, `INTAKE.md`'s IN-070/IN-073/
  IN-149 rows moved §1.1 → §1.2.

## Visible behavior changes

A `v*` tag pushed to `main` now produces a GitHub release with three platform zips, each a
self-contained `dist-local` bundle plus a launcher and README. The local lobby shows the
running build's version (the tag, or `dev` for a build made outside the workflow) in its
footer. `package.json`'s `"version": "0.0.0"` is unchanged and is now documented as
permanently meaningless.

## How to verify

`pnpm verify` is green. Locally: `node --experimental-sea-config
apps/web/scripts/launcher/sea-config.json` from `apps/web/scripts/launcher/` produces
`sea-prep.blob`; injecting it into a copied `node` binary via `postject` and running it
against a `pnpm build:local` output served a real page at `127.0.0.1:4173`, including the
SPA fallback and a JS asset (verified in this session, artifacts not left in the tree).
`VITE_APP_VERSION=v9.9.9-test pnpm build:local` then `grep -rlE
'firebase|firestore|osr-vtt|appspot|identitytoolkit|firebaseio' apps/web/dist-local`
returned no matches, matching WI-089/WI-090's numbers (3.62 MB main chunk). The workflow
itself can only be exercised by pushing a real `v*` tag, which this session did not do.
