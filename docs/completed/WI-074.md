# WI-074 — Encounter Template default → Initiative only

**Status:** Completed 2026-08-11

## Changes made

- **`packages/shared/src/types.ts`** — `DEFAULT_ENCOUNTER_TEMPLATE` changed from the three
  Difficulty (roll) / Danger (roll) / Clock (counter, max 6) fields to a single
  `{ id: 'initiative', label: 'Initiative', type: 'initiative', default: 'd6', pinned: true }`
  field, routing Side-based **Call for Initiative** (DEC-065). Updated the doc comment to
  say the constant now seeds `createRoom` only, and to point at
  `LEGACY_ENCOUNTER_TEMPLATE_V14` for what an old room's migration produces instead.

- **`packages/shared/src/migrations/index.ts`** — Added a new, exported
  `LEGACY_ENCOUNTER_TEMPLATE_V14` constant local to this file: a frozen literal copy of the
  old Difficulty/Danger/Clock array. Re-pointed the v13→v14 migration step's backfill at it
  instead of at `DEFAULT_ENCOUNTER_TEMPLATE`, so a room migrating today still gets the
  widgets it genuinely had in v14, independent of what the live default now seeds. Updated
  the step's comment accordingly. No schema version bump — `encounterTemplate`'s stored
  shape is unchanged, only which value seeds a fresh room versus an old one being migrated.

- **`packages/shared/src/migrations/index.test.ts`** — Both v13→v14-related assertions
  (`'v13 -> v14 seeds the default `encounterTemplate`...'` and the v1→v22 walk-forward test)
  now import and assert against `LEGACY_ENCOUNTER_TEMPLATE_V14` instead of
  `DEFAULT_ENCOUNTER_TEMPLATE`.

- **`packages/shared/src/store/campaign-store.contract.ts`** — The
  `updateEncounterTemplate` contract test's seeded-room assertion now expects
  `['initiative']` instead of `['difficulty', 'danger', 'clock']`.

- **`apps/web/src/lib/components/TensionBar.svelte`** — Updated the header doc comment: it
  no longer claims `DEFAULT_ENCOUNTER_TEMPLATE` seeds Difficulty/Danger/Clock, since that's
  now only true of `LEGACY_ENCOUNTER_TEMPLATE_V14` for a migrated room; a fresh room seeds
  Initiative only.

- **`README.md`** — Updated the "Session bar" bullet and the "Nothing about the strip is
  hardcoded" paragraph (Encounter profile section) to describe the Initiative-only default
  for a freshly-created room and `LEGACY_ENCOUNTER_TEMPLATE_V14` for a room migrated through
  schema v14, decoupled per DEC-065.

- **`PLAN.md`** — Removed the WI-074 row from §2 and its slot in the execution-order note;
  §2's status line cleared.

- **`PLAN-COMPLETED.md`** — Added the WI-074 row to §3.

- **`INTAKE.md`** — Moved the IN-056 row from §1.1 (Open and scheduled) to §1.2 (Closed
  intake), citing WI-074 / DEC-065.

## Visible behavior changes

A brand-new room's Encounter profile (Session settings) now starts with a single pinned
**Initiative** field (die `d6`) instead of Difficulty / Danger / Clock. The encounter status
strip in the top bar shows just that field by default. A room already carrying an
`encounterTemplate` — including any room that migrates forward through schema v14 from
today onward — is unaffected: it keeps (or is backfilled with) the Difficulty / Danger /
Clock widgets exactly as before. The referee can still freely relabel, retype, reorder,
unpin, delete, or add fields to either template.

## How to verify

1. `pnpm verify` — lint and typecheck pass; the shared and web unit suites pass in full
   (599 + 333 tests) except the pre-existing `account-recovery.emulator.test.ts` failure,
   which requires a running Firebase Auth emulator unavailable in this sandbox and
   reproduces identically on the base branch (unrelated to this change; already noted in
   WI-073's completion record).
2. Create a new room and open Session settings ▸ Encounter profile — the seeded field is
   Initiative (Initiative d6), pinned, and it's the only field the status-bar strip shows.
3. `pnpm --filter @osr-vtt/shared run test:unit` — `migrations/index.test.ts` and
   `campaign-store.contract.test.ts`'s memory-store run cover the frozen
   `LEGACY_ENCOUNTER_TEMPLATE_V14` backfill and the new fresh-room seed respectively.

## Deviations

None. The change is exactly what DEC-065 specified — the migration's input was frozen into
`LEGACY_ENCOUNTER_TEMPLATE_V14` before `DEFAULT_ENCOUNTER_TEMPLATE` changed to
Initiative-only — plus the doc-comment and test updates that change necessarily touches
(RULE-018).
