## WI-131 — Measurement follows the grid kind

**Status: Completed 2026-09-14**

SPEC-049. Fixes a live RULE-006 breach: the Measure tool resolved every drag through
`toLatticeRaw` (`world / grid.cellSize`), a square-lattice divisor a hex map does not
declare, then reported a Euclidean span in that undeclared space. A hex map now reports
`axialDistance` — the hex-crawl travel distance and the only distance a hex map has — and
the Grid & measurement label and a freshly created hex map's default follow the grid kind,
per the amended DEC-093 (no backfill, no migration).

### Changes made

- **`packages/shared/src/types.ts`** — added `DEFAULT_HEX_MEASURE = { perSquare: 6, unit:
  'miles' }` beside `DEFAULT_MEASURE`, and `createDefaultGameMap` now seeds it for
  `gridKind === 'hex'` instead of the square default. `RoomMeasure` itself is unchanged —
  no new field, per DEC-093's amendment declining a distinct `perHex`. `CURRENT_SCHEMA_VERSION`
  untouched; nothing backfilled onto an existing map (DEC-093, user, 2026-09-11).
- **`apps/web/src/lib/map/vector-tools.ts`** — new `hexMeasureSpanText(a, b, at, measure)`,
  beside `measureSpanText`: takes the drag's two hexes (`hexMap.Axial`), reports
  `hexMap.axialDistance(a, b)` through the same `formatSpan`/`perSquare`/unit formatting
  `measureSpanText` already used, so the two never disagree on rounding or unit placement.
  `at` is passed in rather than averaged from `a`/`b`, since a hex pair has no lattice
  midpoint of its own.
- **`apps/web/src/lib/components/VectorMapView.svelte`** — the Measure tool's pointer-down
  and pointer-move now also resolve each end through `hexAt` (the same `pixelToAxial` Select's
  own click already uses) into a new `measureHexDrag: { a: Axial; b: Axial } | null`, nulled
  everywhere `measureDrag` already is (`handleCollabPointerUp`, `cancelStroke`). `measureDrag`
  itself, the ruler line and the chip's anchor are unchanged — that's a plain pixel round-trip
  through `cellSize`, not a square-lattice assumption, so it draws correctly on either grid
  kind. The `strokeMeasure` readout branches on `hexGrid`: hex maps go through the new
  `hexMeasureSpanText(measureHexDrag?.a, measureHexDrag?.b, <measureDrag midpoint>, map.measure)`;
  square maps are unchanged.
- **`apps/web/src/lib/components/shell/SessionActivity.svelte`** — imports `isHexMap`; a new
  `measureIsHex` derived flag switches the Grid & measurement field's label between "Per
  square" and "Per hex". The field, its `data-testid="measure-per-square"`, and
  `setMapMeasurement` are all unchanged — same `perSquare`/`unit` pair, different label.
- **Docs** — `docs/spec/SPEC-049.md` (no change needed, already describes the landed shape),
  `PLAN.md`, `PLAN-COMPLETED.md`, `INTAKE.md`.

### Visible behavior changes

- **A hex map's ruler now reports a real number.** Dragging the Measure tool across a hex map
  reports a hex-step count times `perSquare`, in `unit` — previously a square-lattice quantity
  that had no meaning on that map.
- **Grid & measurement's field reads "Per hex"** instead of "Per square" when the active map
  is a hex map. The input and its default value are otherwise the same control.
- **A freshly created hex map defaults to `6 miles` per hex** instead of `10 feet`. Existing
  hex maps are untouched — they keep whatever `measure` they already had (most, `{10, feet}`),
  and a referee sets `6`/`miles` once through the same field.

### How to verify

1. `pnpm verify` — lint, typecheck, unit. Green.
2. Create a new hex-crawl map: Grid & measurement shows "Per hex", `6`, `miles`.
3. Open an existing hex map (predates this change): its `measure` is untouched — no value
   changed on its own.
4. Pick the Measure tool on a hex map and drag from one hex to a neighbour two hexes away:
   the chip reads `12 miles` (2 hexes × 6). Compare against a square map, where the same drag
   reads the Euclidean span in `perSquare`/`unit` as before.
5. Neither `measureSpanText` nor the new `hexMeasureSpanText` has a dedicated unit test today
   (`vector-tools.test.ts` doesn't reference either); step 4's manual check is what exercises
   the new path this session.
