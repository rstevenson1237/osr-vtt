# WI-170 — Strings extraction to `lib/strings`

SPEC-055 §5. Single unit. IN-195. Model `haiku` (executed on a heavier line), effort low.

## Changes made

- `apps/web/src/lib/strings/` (new) — one module per component (`<Component>.ts`, exporting
  `<Component>Strings`) plus `index.ts` re-exporting them. 46 modules, about 180 strings.
- 46 Svelte components under `lib/components/**` and `App.svelte` — each imports its module as
  `S` and renders `{S.key}` in place of the literal. Covered: single-line static text nodes and
  `title` / `aria-label` / `placeholder` / `alt` attributes.
- No testid moved. No translation mechanism is added.

## Visible behavior changes

None. Rendered text is unchanged.

## How to verify

`pnpm verify` — docs, lint, typecheck and unit green. e2e was not run (no emulator suite in this
session); no testid or rendered string changed.

## Deviations

- **Partial coverage, deliberately.** Not moved: text mixed inline with elements, multi-line text
  nodes, text containing entities, and strings built in `<script>` blocks (toasts, errors, dialog
  titles, confirm copy). Those need judgement per site, not a mechanical pass. Logged as IN-220.
- Ran on a heavier model than the `haiku` target.
