## WI-058 — Mobile: `dvh`, `touch-action` on the map host, safe-area insets
> **Verified.** `pnpm lint` clean, `pnpm typecheck` 0 errors, `pnpm test:all:emulators`
> exited 0 (74 e2e passed, 1 skipped — quarantined `portability.spec.ts`). Headless
> Chromium triggers no URL-bar-collapse or notch, so DEC-050's gate calls for a
> real-device check before closing.

**Changes made.**

- `apps/web/index.html` — viewport meta tag gains `viewport-fit=cover`, so
  `env(safe-area-inset-*)` resolves to real values instead of zero (SPEC-033 §3).
- `apps/web/src/App.svelte` — `:global(html, body)` gains `overscroll-behavior: none`;
  `main`'s `min-height: 100vh` gains a `100dvh` fallback.
- `apps/web/src/lib/components/RoomShell.svelte` — `.shell` (desktop)'s bare
  `height: 100vh` gains the same `100dvh` fallback `.mshell` already carried. `.mshell`'s
  last grid row becomes `calc(52px + env(safe-area-inset-bottom, 0px))`, and the frame
  gains `box-sizing: border-box` plus left/right safe-area padding for a landscape notch.
  `.mrail-bottom` absorbs its own bottom inset the same way, rather than shrinking its
  52px tap target.
- `apps/web/src/lib/components/VectorMapView.svelte` — `.vf-canvas-wrap` gains
  `touch-action: none` declaratively, matching what `pan-zoom.ts` already set imperatively
  on the inner `<canvas>`; the wrapper itself carried none, so gestures landing on it or
  on padding between the two still raced the browser's native pan/pinch.
- `README.md` — new "Viewport, touch and safe areas" subsection; `SPEC.md`'s SPEC-033
  status line records §§1–3 shipped.
- `PLAN.md` — IN-033 retired from §1.1 to §1.2; this entry added.

**Visible behavior changes.** On a mobile browser whose URL bar collapses on scroll (iOS
Safari in particular), the app frame now fills exactly the visible viewport instead of
being taller than it. The map canvas no longer competes with the browser's native touch
pan/pinch/zoom. The mobile bottom tab bar and frame's left/right edges now pad around the
iPhone home indicator and any landscape notch. None of this is visible on desktop or in
headless/desktop-emulated mobile testing.

**How to verify.** On a real mobile browser (not reproducible in desktop devtools
emulation — DEC-050): scroll to trigger the URL bar's collapse and confirm the mobile chip
rail and tab bar stay pinned to the visible bottom edge; drag on the map canvas and
confirm the page never pans or bounces; on a notched device confirm the tab bar and
frame's side edges clear it. `pnpm test:all:emulators` confirms no regression elsewhere.

**Deviations.** None.
