**Changes made.**

- `packages/shared/src/map/hex/catalog.ts` — `HEX_TERRAIN_CATALOG` gains 11 entries, `HEX_CONTENTS_CATALOG` gains 16, each with a comment marking the WI-101 boundary. No existing entry's `kind`, `color` or `label` changed.
- 37 `.svg` files moved from `docs/intake/hex-symbols/` (deleted from there) into `apps/web/public/assets/hex/terrain/*.svg` and `apps/web/public/assets/hex/contents/*.svg`, each re-authored white (`#111111` → `#ffffff`, a mechanical substitution across every `stroke`/`fill` attribute using it — not a redraw) via a one-off script (not committed; scratch tooling).
  - **10 supersede an existing kind's `ref`, kind string unchanged**: terrain `hills`, `desert`, `water`; contents `camp`, `castle`, `cave`, `fort`, `temple`, `town`, `village`. Each pack filename was an exact match to an existing `kind` string in the catalog it belongs to — the criterion used throughout to decide "does this file replace something or is it new," rather than judging by visual similarity (the spec's own `mountains`/`mountain-major` example is exactly the wrong guess this avoids).
  - **27 are new kinds** with no existing kind string to alias: terrain `barren`, `grass`, `ice-floe`, `mountain-major`, `mountain-minor`, `palm`, `plateau`, `reed`, `scrub`, `tree-deciduous`, `tree-evergreen`; contents `capitol`, `cave-filled`, `city`, `cloud-stronghold`, `hamlet-thorpe`, `lighthouse`, `mine`, `mountain-stronghold`, `palace`, `ruin`, `rock-shelter`, `shire`, `shrine`, `tower-keep`, `tree-fortress`, `volcano`.
  - **Catalog membership was read from the art, not the filename split** `docs/intake/hex-symbols/README.md` guessed (per the spec's explicit instruction): the README classified `cave`/`cave-filled` and `rock-shelter` as terrain-shaped by name pattern, but their art is a single schematic glyph at full scale (not the small repeated ground-texture motif every other terrain file uses), and `cave` collides exactly with an existing **contents** kind — so all three moved to the contents catalog. That correction changes the terrain/contents split from the README's guessed 17/20 to the actual 14/23.
  - **A second two-tone file the spec didn't name**: SPEC-047 §6 calls `sym-water.svg` "the one two-tone file," but `sym-cloud-stronghold.svg` also carries `class="tint ink"` with the same `fill="#a8c4d0"`. Both got the same treatment — the fill attribute dropped (the path then inherits the root `fill="none"`, leaving a plain white stroke) — since the reasoning ("a multiply tint cannot express two tones") applies identically. Recorded here per RULE-015 as required to complete this section faithfully, not a scope change.
