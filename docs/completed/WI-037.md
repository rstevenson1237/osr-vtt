# WI-037 — `RULE-AMENDMENT`: scope RULE-006's single-coordinate-space guarantee to square-grid map types

A standalone rule amendment (RULE-017) — its own branch, its own

## Changes made

- **`RULES.md`** — RULE-006 rewritten. The lead is now the invariant that actually
  generalises: **never store pixel coordinates**, geometry is stored in the abstract
  units of its map's grid, and the screen-space multiplier is applied once at the
  render/LoS-build boundary. The single-space guarantee is restated **per grid kind** —
  a map still has exactly one coordinate space, spaces are never mixed inside a map, and
  no consumer may assume a space the map's grid kind does not declare — with the two
  kinds spelled out: square-grid maps in **lattice (cell) units as floats** (`cellSize`
  as the multiplier), hex-grid maps in **axial hex coordinates** with `0,0` at the map's
  centre (hex size as the multiplier). Adds the explicit non-carry-over: axial
  coordinates are not lattice units — neighbours, distance and the floor union do not
  transfer, and a square-lattice consumer (LoS, `pointInFloorUnion`, token snapping) is
  undefined on a hex map and must not be reached from one. Closes with a dated
  **"Amended by WI-037"** blockquote recording the pre-amendment text and that nothing
  changes for square-grid maps, following RULE-007's ratified-exception pattern.
- **`README.md`** § "Map system — vector (II.2)" → Data model — notes that RULE-006 fixes
  the space per grid kind rather than globally, that the cell lattice documented below is
  the square-grid map's space, and that every map today is square-grid, so the section is
  the whole story until SPEC-030's axial space lands alongside it.
- **`docs/spec/SPEC-030.md`** — the blocking ⚠️ warning is now a **cleared** notice. It
  keeps the reason a hex map is a genuinely different space, and records that RULE-006
  was amended by WI-037 on 2026-08-13, so WI-038 – WI-041 are unblocked.
- **`PLAN.md`** — WI-037 removed from §2; execution order now opens at WI-038 and lists
  WI-037 among the completed; WI-038's gate cell records that its block is lifted; the
  standing "WI-037 still needs its own session and branch" paragraph replaced with the
  closure note (WI-065 keeps the same standalone-commit requirement).
- **`PLAN-COMPLETED.md`** §3 — row added.
- **`INTAKE.md`** §1.1 — IN-011's disposition annotated: WI-037 closed, WI-038–041 open.

## Visible behavior changes

**None.** No code changed — the diff is five markdown files. Nothing about square-grid
maps is redefined: every map that exists today still stores lattice units as floats with
`cellSize` applied once at the render boundary, and every consumer reads exactly what it
read before. The amendment only makes room for a second space that does not yet exist.
