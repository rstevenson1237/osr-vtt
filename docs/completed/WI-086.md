# WI-086 — Eight resize handles: corners ratio-locked, edges free

**Spec:** SPEC-039 §3 (reverses SPEC-038 §3) · **From:** IN-063 · **Agent:** `claude-code`
(`sonnet`) · **Effort:** medium · **Closed:** 2026-08-18

The third link of the WI-084 → WI-085 → WI-086 chain: WI-085 gave Select a background pick
with the old single ratio-locked handle carried over unchanged. This work item replaces that
one handle with eight — four corners (still ratio-locked) and four edge midpoints (free on
their one axis) — so a referee can stretch a scanned or photographed floor plan to correct a
distortion the ratio-locked handle could never reach.

## Changes made

**`apps/web/src/lib/map/background-transform.ts`**

- New `BgHandle` type (`'nw' | 'n' | 'ne' | 'e' | 'se' | 's' | 'sw' | 'w'`) and two ordered
  lists, `BG_CORNER_HANDLES` and `BG_EDGE_HANDLES`, used both by the hit test's
  corner-before-edge tie-break and by the render engine's draw loop.
- `backgroundHandlePoint(rect, handle)` now takes a handle and returns where any of the eight
  sits (four corners, four edge midpoints) — previously hardcoded to the bottom-right corner.
- `resizeBackground(rect, pointer, handle, aspect)` is handle-parameterised. Two private
  helpers do the arithmetic: `resizeCorner` (generalizes the old single-handle math with a
  `signX`/`signY` pair naming which corner is the fixed anchor — `se` with `signX: 1, signY:
  1` is byte-for-byte the old behaviour) scales `w`/`h` together from the native aspect;
  `resizeEdgeX`/`resizeEdgeY` move one dimension only, anchored at the opposite edge. Both
  clamp the driven axis to `MIN_BACKGROUND_CELLS` rather than inverting the rect, matching the
  existing single-handle guarantee — a corner clamps the driven axis and derives the other
  through the native ratio, an edge clamps its own axis only.
- `backgroundHitTest` grows from one handle to eight plus the body: it now returns
  `{ kind: 'handle', handle } | { kind: 'body' } | null` (was `'handle' | 'body' | null`),
  checking all four corners, then all four edges, then the body — corner-before-edge and
  handle-before-body where their grab radii overlap, per SPEC-039 §3.
- The stored `BgRect` shape (`x, y, w, h`) is untouched — **no migration ships**, per the spec.

**`apps/web/src/lib/components/VectorMapView.svelte`**

- `bgDrag.kind` widened from `'body' | 'handle'` to `'body' | BgHandle`, so the in-progress
  gesture remembers which of the eight handles (if any) is driving it.
- `pickBackgroundGesture` unpacks the new `backgroundHitTest` result shape into that same
  `'body' | BgHandle` kind.
- `updateBackgroundDrag` passes `bgDrag.kind` through to `resizeBackground` as the handle
  argument whenever the gesture isn't a body move.

**`apps/web/src/lib/map/vector-engine.ts`**

- Imports `backgroundHandlePoint`, `BG_CORNER_HANDLES`, `BG_EDGE_HANDLES` from
  `background-transform.ts`. `drawBackgroundAlignment` now loops over all eight handles and
  draws each as the same square affordance the old single bottom-right handle used — the
  eight handles are visually identical; only what dragging each one does differs.

**Tests**

- `apps/web/src/lib/map/background-transform.test.ts` — the existing single-handle
  `resizeBackground`/`backgroundHitTest` cases now pass `'se'` explicitly and still pass
  unchanged (proving `se` is byte-for-byte the old behaviour); new cases cover the other three
  corners' opposite-corner anchoring and per-corner clamping, all four edges' one-axis
  move/anchor/clamp, `backgroundHandlePoint`'s placement of all eight handles, and
  `backgroundHitTest`'s corner-before-edge tie-break.
- `apps/web/tests/e2e/backgrounds.spec.ts` — a new case drags the east edge handle and asserts
  `w` grows, `h` is untouched, and the resulting ratio no longer matches the starter map's
  native 4:3 (the capability that did not exist under the single ratio-locked handle). The
  existing bottom-right-corner resize case is unchanged and still exercises `se`.

**Docs**

- `README.md` — "On the canvas" (background selection) rewritten from "single bottom-right
  handle, ratio locked" to the eight-handle model: corner vs. edge behaviour, the
  corner-before-edge/handle-before-body hit-test order, and the per-axis clamp. The alignment
  grid bullet now says "all eight handles" and notes free edge stretching is why the overlay
  stays visible the whole time something is selected.

## Visible behavior changes

- A selected, unlocked background now shows eight resize handles instead of one: the four
  corners (unchanged position/behaviour from before) plus four new edge midpoints.
- Dragging a corner behaves exactly as the old single handle did — `w`/`h` scale together from
  the image's native ratio, anchored at the opposite corner.
- Dragging an edge midpoint is new: it moves one dimension only (stretching the image),
  anchored at the opposite edge — there was previously no gesture in the app that could do
  this.
- Nothing else changes: a locked background still offers no handles at all, and with no
  background selected every map tool behaves exactly as before.
