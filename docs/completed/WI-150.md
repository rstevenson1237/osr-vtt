# WI-150 — The freshness hook

DEC-102 answered **(b)**: relocate `remind-plan-status.sh`'s durable state off `PLAN.md`
to a gitignored `.claude/status.local`, rather than retire the hook. The guard, its
trigger surface (Bash long-running patterns + any `Agent` dispatch) and its 15-minute
freshness window are all unchanged; only which file it reads and denies against moves.

**Changes made**

- `.claude/hooks/remind-plan-status.sh` — reads/denies against `.claude/status.local`'s
  mtime instead of `PLAN.md`'s; also denies (rather than allowing through a missing-file
  check) when the status file doesn't exist yet. Header comment updated to describe the
  new target and cite DEC-102.
- `.gitignore` — adds `.claude/status.local`.
- `CLAUDE.md` — the "Write status back before any long-running operation" paragraph now
  names `.claude/status.local` (gitignored, no diff cost) instead of `PLAN.md`, citing
  DEC-102/DEC-029.
- `DECISIONS.md` — DEC-029 already carried its "superseded in part by DEC-102" annotation
  from the gate (RULE-019); no further edit needed here.
- `.claude/settings.json` — unchanged: the hook's registration (matcher, command path) is
  identical: still three `PreToolUse` hooks.

**Visible behavior changes** — none to the app itself. Session-visible: the freshness
hook now denies a long-running Bash/Agent call unless `.claude/status.local` (not
`PLAN.md`) was written in the last 15 minutes, and that file never shows up in `git
status` or a PR diff.

**How to verify** — `pnpm verify` (lint + typecheck + unit) is green. Manually: run a
matched long-running command (e.g. `pnpm playwright test`) without touching
`.claude/status.local` first and confirm the hook denies with the updated message naming
`.claude/status.local`; write to that file and retry to confirm it then allows.

**Deviations** — none. Both RULE-015 exceptions unused.
