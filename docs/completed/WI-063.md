# WI-063 — Coarse pointers get an equivalent, not a hover

**Spec:** SPEC-033 §4 · **From:** IN-034 · **Decision:** DEC-059
**Agent:** `claude-code`, model `opus`, effort `high` · **Closed:** 2026-08-08

The three hover-only affordances get a coarse-pointer answer under one rule: **a coarse
pointer never gets a gesture — it gets a visible target it can tap, or a target big enough
to hit.**

## Changes made

**The signal.**

- `apps/web/src/lib/components/RoomShell.svelte` — passes `isCoarsePointer={media.isCoarsePointer}`
  to `VectorMapView`. Updated the `createShellMedia()` comment, which claimed nothing below
  read the signal; that is now false, and the Pixi stage is why.
- `apps/web/src/lib/components/VectorMapView.svelte` — new optional `isCoarsePointer` prop,
  defaulting to `false` so every non-`RoomShell` mount keeps the pre-§4 behaviour.

**The note dot (the room-label tooltip's coarse equivalent).**

- `apps/web/src/lib/map/vector-tools.ts` — added `noteDotCenter` (the dot's lattice
  position: the midpoint of the label cell's top edge, derived from `labelAnchor` alone so
  the renderer and the hit test agree without either measuring the label text) and
  `pickNoteDotAt` (nearest-dot pick, taking the already-filtered list of rooms that
  actually render a dot).
- `apps/web/src/lib/map/vector-engine.ts` — `renderOverlayObjects` takes an optional
  `noteDotRoomIds` set and draws the dot on the label's own container at local
  `(0, -cellSize / 2)`; new exported `noteDotRadiusPx(cellSize)` scales the drawn radius
  off the cell with a `MIN_NOTE_DOT_PX` floor, the same shape of rule as
  `MIN_LABEL_FONT_PX`.
- `apps/web/src/lib/components/VectorMapView.svelte` — `noteDotRooms` / `noteDotRoomIds`
  deriveds (coarse pointer **and** non-empty players' notes); `handleNoteDotPointerDown`
  runs in `wireStagePointerEvents`' `pointerdown` **before** `handleCollabPointerDown` and

  separate from `hoverLabel`; `activeLabel` / `activeLabelText` / `showLabelTooltip`

  `labelTooltipAnchor` so hover and pin position identically. `pinnedLabel` is cleared by a
  tap elsewhere (not consumed), a second tap on the same dot, `openLabelEditor` for that
  room, and the camera-invalidation path that already cleared `hoverLabel`.

## Visible behavior changes

**On a coarse pointer only:**

- A room label whose players' notes are non-empty shows a small dot above it. Tapping the
  dot opens that room's notes in the same popover a mouse gets by hovering, and pins it
  there; tapping the dot again, tapping elsewhere, editing the label, or moving the camera
  closes it. Tapping the dot never triggers the active tool.
- Select-tool vertex handles are drawn at the larger radius all the time.
- Every canvas pick — handles, doors, symbols, labels, drawings — catches within 22px
  instead of 9px.
- Tapping a control no longer leaves it stuck in its hover appearance.

**On a fine pointer: none.** No dot renders, the hover tooltip is unchanged, `PICK_PX`
evaluates to the same 9, handles draw at the same radius, and every wrapped `:hover` rule
still matches — a mouse-driven desktop is pixel-identical.

## How to verify

- `pnpm verify` — lint, typecheck, unit. The new `vector-tools` and
  `vector-engine-note-dot` cases cover `PICK_PX` and the dot's geometry.
- `pnpm verify:all` — adds the emulator suites and both Playwright projects. The new
  `mobile.spec.ts` case is the end-to-end proof; `map-draw-feedback.spec.ts`'s three
  existing `map-label-tooltip` assertions are the desktop-unchanged proof.
- By hand: open a room on a touch device (or Chrome DevTools device emulation, which
  reports `(pointer: coarse)`), write notes on a room from the Room quick sheet, and tap
  the dot that appears above its label.

## Deviations

- **Five `latticeThreshold(9)` sites, not six.** The gate and DEC-059 both say six; the
  file has five — both Select handle picks (`beginSelectDrag`, `onPointerMove`), the door
  click, and two `pickObject` calls (`beginObjectDrag`, `onLabelToolClick`). All five were
  converted, so the scope is what was approved; only the count in the prose was off.
- **`ActivityDrawer`'s hover block had to be split.** `.current.open, .current:hover` shared
  a declaration; wrapping it whole would have taken the drawer's open-state styling away
  from touch — a regression §4 does not ask for. The state selector stays unconditional and
  only the hover half is gated.
- **`RoomShell`'s `createShellMedia()` comment was rewritten.** It asserted that nothing
  below read `isCoarsePointer`, which this work item makes false. Required by RULE-018, not
  an opportunistic edit.
- **The e2e test asserts the label editor's position before using it.** The dot's screen
  position is derived from the label cell centre and the default 70px cell at an un-panned
  camera; the spec asserts that centre lands where that arithmetic predicts, so a future
  change to the default camera fails on a clear assertion rather than on a tap that
  silently misses.
- **`noteDotRadiusPx` is exported from `vector-engine`** rather than kept private, purely so
  it is unit-testable without a canvas — the same reason `gridLineBounds`,
  `adaptiveCornerRadius` and `snapCursorColors` are already exported from that module.
- **Pre-existing unrelated failure.** `packages/shared/src/store/account-recovery.emulator.test.ts`
  fails under a bare `pnpm verify` with `auth/network-request-failed` because it needs the
  Firebase emulator; it fails identically on a clean tree at this commit and passes under
  `pnpm verify:all`, which runs the emulators.
