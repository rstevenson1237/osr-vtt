# WI-226 — Pen, ping, measure and cursor publishing leave `VectorMapView`

**Closed 2026-10-17.** From IN-202. SPEC-060 §2–§5, DEC-126. Model target `sonnet`, run on
`sonnet`; effort `high`.

---

## Changes made

- `apps/web/src/lib/map/map-draw.svelte.ts` (new): the `MapDraw` seam controller. It owns the
  live pings (`livePings`, the only `$state`, plus the per-ping target map and
  `resolvePings()`), the freehand Pen buffer, the Measure path (lattice path and its hex
  path, with their live extensions) and the throttled cursor publish. Its pointer handlers
  are `pointerDown`/`pointerMove`/`pointerUp` (SPEC-060 §4), `finishMeasure()` and
  `cancel()` clear the gesture state, and `subscribe()` opens the peer-cursor and ping
  listeners — none at all when `multiplayer` is false (SPEC-041 §3). Cursors and pings stay
  on RTDB; the released Pen stroke is the one `writeDrawing` (RULE-003). Imports only
  types from `@osr-vtt/shared`.
- `apps/web/src/lib/components/VectorMapView.svelte`: constructs `MapDraw`, deletes the
  `penPoints`/`measure*`/`lastCursorPublish`/`livePings`/`pingTargets` locals, the three
  `handleCollab*` functions, `publishCursorThrottled` and `resolvePingsForRender`.
  `wireStagePointerEvents` calls the controller in the same branch positions;
  `cancelStroke`/`finishMeasure` delegate; the `toolsInputs`/`overlayInputs`/
  `currentStrokeMeasure` composers read `draw.livePath`, `draw.liveHexPath` and
  `draw.annotationsWithLiveStroke`. The renderPings `$effect` is unchanged apart from
  reading `draw`. Four now-unused imports removed.
- `apps/web/src/lib/map/map-draw.test.ts` (new): 15 tests with a fake `invalidate`, store and
  tokens, no browser — cursor throttle and local-build guard, listener guard and wiring,
  ping resolution against moved tokens, ping routing, Pen buffer/write/cancel, Measure
  path (lattice and hex), finish/cancel, and the fall-through for other tools.
- Docs (RULE-018): `README.md` → "Seam controllers" names `MapDraw`, and the note-dot
  paragraph now names `MapDraw.pointerDown`; `docs/spec/SPEC-060.md` §2 records the Measure
  exception and §4 the async `pointerUp`.

## Visible behavior changes

None. Pen, Ping, Measure and live cursors behave as before, with the same store calls.

## Deviations

- The work item's text names `measureDrag` and `measureHexDrag`, which do not exist in
  the code; the Measure state is `measurePath`/`measureLive`/`measureHexPath`/
  `measureHexLive`, and they now reach the renderer only through `invalidate('tools')` and
  `cancel()` from the component's `cancelStroke`.
- The three former `renderAll()` calls inside the moved handlers became
  `invalidate('overlay')` (Pen release) and `invalidate('tools')` (Measure click): a seam
  never calls `renderAll` (SPEC-060 §2), and those are the only layers that read the
  moved state. The draw output is unchanged.
- `MapDraw` is handed both `toLatticeRaw` and `hexAt`, which SPEC-060 §2 otherwise forbids;
  the Measure path needs both (SPEC-049 §1) and the work item says it reads `hexAt`.
  SPEC-060 §2 now records the exception. WI-228 repoints `hexAt` at the hex controller.
- `pointerUp` returns `Promise<boolean>` (the Pen release awaits `writeDrawing`); SPEC-060 §4
  now says so.
- No RULE-015 unblock or Deviations-budget fix.
- Not run: the full `pnpm verify:all` and `check-local-strip`; the e2e run was the four
  affected specs.
