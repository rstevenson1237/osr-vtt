#### WI-111 — The hex terrain tool: one click, one hex

**Spec:** SPEC-047 §7. **From:** IN-091 (DEC-082 (b), narrowed). **Model:** `sonnet`.

**Changes made.**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `MapToolId` grows one member,
  `hexTerrain`. New controller state: `selectedHexTerrainKind = $state('plains')`, the
  hex-only counterpart of `selectedHexSymbolKind`, independent of it exactly as
  `setHexTerrain`/`setHexContents` are independent writes.
- `apps/web/src/lib/map/tool-groups.ts` — `HEX_TOOL_IDS` grows to append `hexTerrain`
  after `river`; `PaletteToolId` now also excludes it, alongside `hexSymbol`/`road`/
  `river`/`hexLabel`.
- `apps/web/src/lib/map/tool-groups.test.ts` — `ALL_TOOLS`/`HEX_ONLY_TOOLS` grow to include
  `hexTerrain`; the `HEX_TOOL_IDS` pin extended with it at the end.
- `apps/web/src/lib/components/shell/MapToolPalette.svelte` — `bind:selectedHexTerrainKind`
  wired straight to the controller field, the same wire `selectedHexSymbolKind` uses.
- `apps/web/src/lib/components/MapToolbar.svelte` — `selectedHexTerrainKind` prop;
  `hexTerrain` joins `HEX_TOOL_META` (testid `hex-tool-terrain`, icon `shapes`) and the
  hex-only tool row, gated on `isHexMap` like its row-mates. A `hexTerrainPreview` (resolved
  through `hexMap.hexTerrainEntry(selectedHexTerrainKind).ref`, the same pattern
  `hexSymbolPreview` uses) shows on the button. A new `HEX_TERRAIN_KINDS` catalog list and a
  `hex-terrain-kind` `<select>` render only while `hexTerrain` is active (`showHexTerrainKind`).
  **Not added to `SNAP_TOOLS`**: §7 states both snap modes would resolve to the same hex, so
  the Snap selector stays hidden for this tool, as it is for Select and Label.
- `apps/web/src/lib/components/VectorMapView.svelte` — the stage `pointerdown` handler
  short-circuits `hexTerrain` (a hex map has no lattice to hand `onPointerDown`) into a new
  `placeHexTerrainAt`: resolve the pointer to a hex through `hexAt` (the same `pixelToAxial`
  wrapper Select's own click already uses), read that hex's current `terrain` out of the
  already-subscribed `hexTiles`, and call `store.setHexTerrain` with the toolbar's selected
  kind — or `null` when that kind is already painted there, the click-to-erase gesture §7
  specifies. No new store method: this is a second caller of the existing `setHexTerrain`.
  `HINTS` (`Record<MapToolId, string>`) gains a `hexTerrain` entry.
- `apps/web/tests/e2e/hex-map.spec.ts` — one new test: the Terrain tool paints a hex through
  `setHexTerrain`, the hex-tile sheet shows it pressed, and the same click again clears it.
- `docs/spec/SPEC-047.md` §7 — a "Built by WI-111" annotation covering the mechanism above.
- `README.md` — "Terrain and contents" gains a bullet on the Terrain tool; the "`HEX_TOOL_IDS`
  is authored, not derived" bullet's tool list is updated to include Terrain.
- `INTAKE.md` — IN-091's row moves from §1.1 to §1.2, closed via this item.
- `PLAN.md` / `PLAN-COMPLETED.md` — WI-111 moves from the upcoming table to the completed
  ledger.

**Visible behavior changes.**

A hex-crawl map's Map tools palette gets a fifth button in the hex-only row — Terrain —
alongside Label, Symbol, Road and River, showing the art of whichever `HEX_TERRAIN_CATALOG`
kind is currently selected. Selecting it and clicking a hex paints that hex with the chosen
terrain (the same fill and overlay the hex-tile sheet's own terrain picker already produces);
clicking the same hex again with the same kind selected clears it. No union, no border colour,
no scatter, no drag — one click per hex, and adjacent same-terrain hexes keep their visible
seams, exactly as SPEC-047 §7 specifies.

**How to verify.**

- `pnpm verify` — lint, typecheck, unit. Green.
- `pnpm verify:all` — adds rules/store/e2e against the Firebase emulators, including the new
  hex-map Terrain-tool case. Green (emulator suites, 1529s).
- By hand: create a hex crawl, switch to Edit, open Map tools, pick Terrain from the hex-only
  row, choose a kind from the new picker, and click a hex on the canvas. Confirm the hex
  paints, the hex-tile sheet shows that kind pressed, and clicking the same hex again clears
  it back to unpainted (`map-hex-tile-count` returns to its prior value).

**Deviations.**

None to the scope §7 states — no brush, no union, no border colour, no scatter, no snap
selector — which was followed exactly. The one addition beyond the spec's own bullet list
is the e2e test, which exercises the gesture rather than changing it; its first draft read
back the paint through the tool's own kind picker as if the click had also selected the
hex, which it does not (Terrain places only, like Symbol — Select and Label are the two
tools that publish `selectedHex`). Fixed to read the paint back through Select instead,
which is what a referee would actually do next.
