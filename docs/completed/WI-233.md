# WI-233 — A room a newer build has opened stops the stale tab

**Closed 2026-10-17.** From IN-229, IN-230, IN-231 and IN-232 (one fix). SPEC-070, DEC-137
(a). Model target `sonnet`, run on `sonnet`; effort `high`.

---

## Changes made

- `packages/shared/src/migrations/index.ts`: `newerRoomVersion(raw)` returns the higher of the
  raw doc's `schemaVersion` and `collectionsMigratedTo` when either is above
  `CURRENT_SCHEMA_VERSION`, else `null`; a missing or non-numeric field counts as `0`.
- `packages/shared/src/store/campaign-store.ts`: `NewerRoom` (`{ newer }`), `NewerRoomError`
  and the `isNewerRoom` guard. `subscribeRoom`'s callback type is now
  `Room | NewerRoom | null`; `getRoom` documents the new rejection (RULE-001).
- `packages/shared/src/converters.ts`: `roomConverter.fromFirestore` runs the check on the raw
  doc before `migrateRoom` and the parse and throws `NewerRoomError`.
- `store/firebase-store.ts`: `subscribeRoom` turns that throw into `{ newer }`, so the snapshot
  listener stays open; `getRoom` rejects through the converter.
- `store/memory-store.ts` (and so `LocalStore`): the same check on the doc they hold, in
  `getRoom` and `subscribeRoom`.
- `apps/web/src/lib/components/RoomShell.svelte` and `strings/RoomShell.ts`: on `NewerRoom`
  the shell holds `room` at `null` (every room-gated write effect stays off) and renders
  `newer-room-panel` with a `newer-room-reload` button (`location.reload()`); the panel names
  this build's `VITE_APP_VERSION` unless it is `dev`. `TokenPickerDialog.svelte` narrows the
  new callback type.
- Tests: contract cases in `store/contract/room.contract.ts` (each number alone, both, a doc
  that fails `RoomSchema`, the return to a `Room`, a doc exactly at this build's version)
  with a new `seedRoomFields` seed on `campaign-store.contract.ts` and the three runners
  (`MemoryStore`, `LocalStore`, `FirebaseStore`); a `subscribeCurrentRoom` helper keeps the
  existing contract cases on plain `Room`s. `converters.test.ts` (new) covers
  `newerRoomVersion` and asserts `migrateRoom` is not called for a newer doc. e2e:
  `apps/web/tests/e2e/newer-room.spec.ts`.
- Docs (RULE-018): `SPEC-070` Active; `SPEC.md` index row; `SPEC-062` §5 now points at
  SPEC-070; `README.md` → "Room load, creation and version".

## Visible behavior changes

- A tab whose room a newer build has opened (stamp above this build's) replaces the room view
  with "This room was updated by a newer version of the app. Reload to continue." and a Reload
  button; no write path is reachable from it. If the stamp later stops being newer, the room
  view returns on its own.
- Nothing changes for a room at or below this build's version, and nothing changes for local
  builds in practice.

## How to verify

- `pnpm verify` — docs check, lint, typecheck, unit (includes the `MemoryStore` and
  `LocalStore` contract runs and `converters.test.ts`).
- `pnpm verify:all` — adds rules, the `FirebaseStore` contract against the emulators, and the
  e2e suite including `newer-room.spec.ts`.
- By hand: open a room as referee, raise `schemaVersion` on `rooms/{roomId}` in the emulator
  UI; the tab shows the Reload panel. Lower it again and the room returns.

## Deviations

None. The `subscribeCurrentRoom` helper and the `seedRoomFields` parameter are part of the
contract-suite cases the work item named, not a separate fix. Known gap, as specified
(SPEC-070 §4): a newer player tab never stamps the room, so a stale referee tab is only
stopped once a newer referee has opened it.
