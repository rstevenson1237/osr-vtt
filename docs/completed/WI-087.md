# WI-087 — `Token.name`, schema v28, the name+quantity picker, and per-group A–Z symbols

**Spec:** SPEC-040 · **From:** IN-064 · **Agent:** `claude-code` · **Model:** `opus` ·
**Effort:** high · **Closed:** 2026-08-18

A creature had no name. Every surface that showed one called `creatureLabel()`, which
strips the path and extension off `Token.imageRef` — so for a generated creature the
"name" the referee read was `gen:disc:a1:%23aabbcc`, a fragment of an asset URL. The
symbol had the mirrored problem: the lowercase letter identified the *kind* and the
number identified the individual. SPEC-040 inverts that — the **name** identifies the
kind, the **letter** identifies the individual.

## Changes made

**Schema (RULE-007).**

- `packages/shared/src/types.ts` — `CURRENT_SCHEMA_VERSION` 27 → **28**; `Token` gains
  `name?: string`, documented as an absence-is-legitimate field on the `Token.color`
  pattern.
- `packages/shared/src/schemas.ts` — `TokenSchema.name` optional, so the converter stops
  stripping it on read and write.
- `packages/shared/src/migrations/index.ts` — the v27 → v28 step: a no-op on the room
  doc, and **no document half either**. That is the decision, not an omission: the
  obvious backfill is `creatureLabel`'s output, which is the exact string IN-064 calls
  unacceptable, and storing it would make it permanent rather than merely displayed.
- `packages/shared/src/migrations/index.test.ts` — the two step tests (no-op on the room
  doc; invents nothing).
- `packages/shared/src/portability/vttcamp.test.ts` — `name` added to the fixture token,
  so every existing round-trip assertion covers it; plus a round-trip over a named
  creature, a numbered sibling and an unnamed token (absence must survive as absence),
  and a v27 → v28 import that leaves `name` unset. The hardcoded `toBe(27)` in the
  "ordinary map" round-trip is now `toBe(CURRENT_SCHEMA_VERSION)`.

**Store (RULE-001).**

- `packages/shared/src/store/campaign-store.ts` — `setTokenName(roomId, tokenId, name)`
  on the contract; `undefined` clears back to absence.
- `packages/shared/src/store/memory-store.ts`, `firebase-store.ts` — both
  implementations, mirroring `setTokenColor` (`deleteField()` on the Firebase side).
- `packages/shared/src/store/campaign-store.contract.ts` — one contract test covering
  create-with-name, rename, and clear-to-absent, running against `MemoryStore` and
  `FirebaseStore` alike.

**Naming and symbols.**

- `apps/web/src/lib/encounter/labels.ts` — `tokenLabel` prefers `Token.name`, so the

## Visible behavior changes

- **Add creature now asks for a name.** The picker shows **Name** and **Quantity** for a
  creature. `Goblin` ×3 creates three tokens named `Goblin 1`, `Goblin 2`, `Goblin 3`;
  `Goblin` ×1 creates one named `Goblin`, with no trailing number. Leaving Name empty
  behaves exactly as before this change.
- **Generated symbols are uppercase and per group.** Three goblins read A, B, C; three
  orcs in their own group read A, B, C again. Deleting "B" and adding a creature reuses B.
  Tokens created before this change keep their `a1`/`a2` discs untouched.
- **The Encounter Board card, the Character quick sheet header, the initiative order and
  the turn strip** show the creature's name instead of a ref fragment. A creature with no
  stored name reads exactly as it did before.
- **A creature can be renamed** by double-clicking the quick sheet header, the same
  gesture a character's rename already used.
- **Batch colour** is now derived from the name rather than the type letter, so a second
  batch of the same creature comes out the same colour. Picking a colour on the
  Generate-default tab no longer flattens a batch to one repeated symbol.
- A `.vttcamp` written by this build stamps schema 28; a v27 or older archive still
  imports, with names left absent.

## Deviations

- **SPEC-040 §5's "the map token's label" has no referent, and is annotated in place
  rather than built.** A map token has never rendered a text label, and §4 defines its
  on-map identity as the **letter**, which is deliberately not the name. The agreement
  rule was therefore read across the surfaces that do name a creature — the board card,
  the quick sheet header, and the initiative order, which was printing the whole
  `gen:disc:` ref and is what §5's first bullet was actually about. Giving a map token a
  rendered name label is a render-pass change and belongs to a new intake item, not this
  one. Same treatment WI-041 gave SPEC-030 §5.
- **A picked colour no longer collapses a generated batch onto one shared ref.** Before
  this change, customizing *either* field on the Generate-default tab made the picker
  return one concrete ref that every token in the batch shared. Left alone, choosing a
  colour for three goblins would have silently produced three identical "A" discs —
  taking away the A/B/C this work item exists to add, on a path a referee is likely to
  take. So the colour now rides out on `TokenPickerResult.genColor` and only a typed
  **character** collapses the batch. The spec does not name this case; it is the reading
  that keeps §4 true everywhere the picker can reach.
- **`Token.name` is `string | undefined` on the store method**, where SPEC-040 §3 writes
  the signature as `setTokenName(roomId, tokenId, name)`. `undefined` clears the field
  back to absence, mirroring `setTokenColor` exactly — which is what §3's own insistence
  that "absence stays a legitimate state" requires of a setter.
- **One unrelated test line changed to unblock the bump:** `vttcamp.test.ts` asserted
  `schemaVersion` `toBe(27)` literally, which any schema bump breaks. It now reads
  `CURRENT_SCHEMA_VERSION`. Recorded here per RULE-015's unblock exception.
- **The new card-title testid is `board-card-name-{tokenId}`, not
  `board-token-name-…`.** The first spelling broke six e2e specs at once: the suite's
  shared `CARD` selector is `[data-testid^="board-token-"]` minus two explicit
  exclusions, so a name span under that prefix counted as a second card on every card. A
  comment on the span now says so.
- **`room-uploads.emulator.test.ts` flaked twice mid-run** with a 30s timeout and a
  Firestore `RESOURCE_EXHAUSTED` on a Listen stream — the same test WI-085 and WI-086
  both had to bump the timeout for (5s → 15s → 30s). It passed on a clean tree, passed
  alone on this branch, and passed in the final green `pnpm verify:all`, and nothing in
  this work item touches Storage, uploads or `deleteRoom`. No change was made for it.
