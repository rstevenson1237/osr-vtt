# WI-121 — Retire the six aliased terrain kinds from the authoring surfaces

**Spec:** SPEC-047 §8 · **From:** IN-115 · **Agent:** `claude-code` · **Model:** `sonnet` ·
**Effort:** S · **Closed:** 2026-09-11

## Changes made

- `packages/shared/src/map/hex/catalog.ts` — `HexTerrainEntry` gains an optional
  `paintable?: boolean` field (default true); the six aliased rows (`grass`, `ice-floe`,
  `palm`, `plateau`, `scrub`, `tundra`) each get `paintable: false`. Added
  `paintableHexTerrainCatalog()`, filtering `HEX_TERRAIN_CATALOG` to drop both `unknown`
  and any `paintable: false` row. No row's `kind`, `ref`, `color` or `ink` changed, so no
  migration is owed (RULE-007).
- `apps/web/src/lib/components/shell/HexTilePanel.svelte` — the terrain palette
  (`TERRAINS`) now comes from `hexMap.paintableHexTerrainCatalog()` instead of a
  component-local `unknown`-only filter over `HEX_TERRAIN_CATALOG`. Contents (`CONTENTS`)
  is untouched.
- `apps/web/src/lib/components/MapToolbar.svelte` — the Terrain tool's kind picker
  (`HEX_TERRAIN_KINDS`) now maps `hexMap.paintableHexTerrainCatalog()` instead of the raw
  `HEX_TERRAIN_CATALOG` (which previously filtered nothing, so it also offered `unknown`).

## Visible behavior changes

- The hex-tile quick sheet's terrain row and the Terrain tool's kind picker no longer
  offer `Grass`, `Ice Floe`, `Palms`, `Plateau`, `Scrub` or `Tundra` (nor, on the toolbar
  picker, `Unknown`, which it had been offering by omission). A hex already painted with
  one of the six still renders its existing art unchanged — only new authoring is
  affected.

## How to verify

- `pnpm verify` (lint + typecheck + unit) — green.
- Manually: open a hex map, select a hex, and check the terrain swatches in the quick
  sheet and in the Terrain tool's toolbar picker — neither lists the six retired kinds or
  `Unknown`. A hex stored with one of the six kinds (e.g. via an existing save) still
  draws its aliased art on the map.
