# WI-143 — CI in twelve minutes

Spec: SPEC-053 §2. From: IN-143. DEC-105 (shard per job, N = 4 as a tuning number).

## Changes made

- `.github/workflows/ci.yml` — three jobs replace the previous four:
  - `static`: lint + typecheck + build, sharing one `pnpm install`. Each step runs even
    if an earlier one failed (`continue-on-error` + a final check step), so a single push
    surfaces all three results.
  - `test-emulators-core`: Vitest units, Firestore/Storage rules tests and the
    `CampaignStore` contract suite, inside one `firebase emulators:exec`. No Playwright,
    no browser install.
  - `test-e2e`: a 4-way `matrix.shard` running `playwright test --shard=i/4` via
    `pnpm --filter @osr-vtt/web exec playwright test --shard=…` (not `pnpm run test:e2e
    -- --shard=…` — see Deviations), each shard inside its own `firebase emulators:exec`.
    Same specs, same `chromium`/`mobile-chromium` projects — nothing skipped, quarantined
    or `fixme`'d. Failure artifacts (error-context dump, trace upload) now key off
    `matrix.shard` so parallel uploads don't collide.
- `package.json` — new `test:emulators:core` script (`test:unit && test:rules &&
  test:store`, no `test:e2e`) backing the new core job and available for local use.
  `test:all:emulators` is unchanged (still the local one-shot, all four suites serial).
- `apps/web/playwright.config.ts` — `retries` on CI: 2 → 1 (SPEC-053 §2.3).
- `README.md` — new "CI shape" paragraph in Test culture (II.9) describing the three
  jobs and the retry change; `test:emulators:core` added to the Dev commands list.
- `PLAN.md` — status notes during execution; this item's row removed from §2.

## Visible behavior changes

CI on a pull request now runs three jobs instead of four (`lint`, `typecheck`, `build`
merged into `static`; `test-emulators` split into `test-emulators-core` and a 4-shard
`test-e2e` matrix, so `test-e2e` shows as four check runs). A Playwright flow failing
twice on CI fails the PR instead of getting a third silent retry. No change to what the
suite covers or to local dev commands other than the new `test:emulators:core` script.

## How to verify

- `pnpm verify:all` locally: lint/typecheck green; `pnpm test:all:emulators` green —
  924 + 516 unit tests, 142 rules tests, 113 store tests, 100/100 Playwright e2e tests
  (all `chromium` + `mobile-chromium` specs, unsharded).
- Inspect `.github/workflows/ci.yml`'s three jobs and the matrix definition on `test-e2e`.
- PR #193's own CI run (commit `4aaf1a3`) is the real-world confirmation: all 6 jobs
  green, `test-e2e` shards each ran a real quarter of the suite (`34 passed (11.8m)` on
  shard 2, e.g. — not 100), and the PR's total wall clock was 19:48:36 → 20:01:27 UTC,
  **~12m51s** — down from the pre-WI-143 baseline of 28–35 min, essentially at the
  twelve-minute target.

## Deviations

Two things surfaced during verification, both recorded here per RULE-015 rather than
silently worked around:

1. **The `test-e2e` step's arg-forwarding was broken on the first two pushes.**
   `pnpm --filter @osr-vtt/web run test:e2e -- --shard=i/4` does not strip pnpm's own
   `--` before forwarding to the resolved script command, so Playwright received a
   literal `-- --shard=i/4` and silently ran the **full 100-test suite on every shard**
   instead of a quarter of it (confirmed locally: `playwright test -- --shard=1/4
   --list` lists all 100 tests; `pnpm --filter … exec playwright test --shard=1/4
   --list` correctly lists 26). This is what produced the first CI run's ~27–31
   minute-per-shard timing — a straightforward bug in this PR's own CI-shape change, not
   a CI-infrastructure regression, and not something a bounded Deviations budget was
   needed for: fixed directly (switched to `pnpm --filter … exec playwright test
   --shard=…`, which forwards args with no `--` needed) and pushed.
2. **A pre-existing test flake surfaced and was investigated, not fixed here.**
   `session-config.spec.ts`'s Gate 6 test failed twice in a row on `test-e2e (3)` while
   the shard bug above was still live (i.e. each failure was one ordinary shot at the
   full suite, same odds as pre-WI-143 CI — not evidence that parallel shard load makes
   it reproducible). The failure — a third same-context tab timing out at 8s waiting for
   `room-name` — is in test/app code this work item doesn't touch, so fixing the
   underlying timing sensitivity is out of scope (RULE-015); logged as **IN-150** for
   its own triage instead. It did not recur on the properly-sharded run that confirmed
   this work item.
3. The first local `pnpm verify:all` run in this session failed the emulator suite
   because a leftover `cloud-firestore-emulator` process from an earlier,
   separately-timed-out run was still holding port 8080 — killing that stale process and
   re-running produced a clean pass. Unrelated to this work item's changes; noted only
   because it briefly looked like a regression.
