## WI-076 — Edit/View as one binary button; default View on session join

**Changes made.**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `mapMode`'s initial
  `$state` value changed from `'edit'` to `'view'`; its doc comment now cites
  DEC-064 instead of claiming "unchanged from every prior session's behaviour."
  `setMapMode`/`MapToolMode` are otherwise untouched — the lock's mechanics
  (forcing the active tool back to Pan on entering View) are unaffected.
- `apps/web/src/lib/components/MapToolbar.svelte` — the two-button
  `map-mode-edit` / `map-mode-view` pair inside the `map-mode-toggle` group is
  replaced by one `<button data-testid="map-mode-toggle">` whose label tracks
  `mapMode` (`Edit` / `View`), `aria-pressed={mapMode === 'edit'}`, and whose
  `onclick` toggles to whichever mode isn't currently active.
- `apps/web/src/lib/shell/map-tool-controller.test.ts` — the "defaults to
  edit, unlocked" case now asserts `'view'` (DEC-064); the other `setMapMode`
  cases were already mode-agnostic (they set `activeTool` and call
  `setMapMode` explicitly) and needed no change.
- `apps/web/tests/e2e/helpers.ts` — new `switchToEditMode(page)`: opens the
  Map tools sheet, clicks `map-mode-toggle` if the mode isn't already Edit,
  and closes the sheet again.
- `apps/web/tests/e2e/{battle-map-capture,battle-map-lifecycle,fog,
  map-draw-feedback,mobile,presentation,rooms-manager}.spec.ts` — each file's
  local `createRoomAndJoin`/`createRoomAsGm` now calls `switchToEditMode`
  right after joining, so specs that draw on the map keep behaving as they
  did under the old Edit default. `fog.spec.ts`'s referee-only test also
  switches the **player** page to Edit before it clicks `vector-tool-room`
  (checking the fog controls are absent for a player), since the lock is
  per-viewer state and the player's own client also now joins in View.
  `map-draw-feedback.spec.ts`'s IN-031 lock test targets the single
  `map-mode-toggle` testid in place of the retired `map-mode-edit` /
  `map-mode-view` pair (RULE-005).
- `README.md` — the Edit/View soft-lock paragraph now documents the single
  `map-mode-toggle` button and the `'view'` default, citing DEC-064.
- `PLAN.md` — this entry removed from §2 and the execution order line
  updated.
- `INTAKE.md` — IN-058's row moved from §1.1 to §1.2.
- `PLAN-COMPLETED.md` — row added to §3.

**Visible behavior changes.** The Map tools sheet shows one `Edit`/`View`
button instead of two; clicking it toggles between the two states. Every
freshly joined session (referee or player) now starts with the map in View —
the carve/edit tools are locked until that button is clicked to enter Edit.
Previously every session started in Edit, unlocked.

**How to verify.** Join a room in a fresh tab → open the Map tools sheet →
the carve/edit tools (Room, Wall, Door, etc.) are disabled and the button
reads `View`; click it → the button reads `Edit` and the tools are enabled.
Automated: `pnpm verify:all` (lint, typecheck, and the full emulator suite —
unit, rules, store, e2e) — all green, `all suites green` (722s for the
emulator suites).

**Deviations.** None beyond what DEC-064 already called out as in-scope: the
e2e updates for the new View default and the merged testid are exactly the
"any e2e spec that assumes edit-tools are immediately clickable on load
need an explicit `map-mode-edit` click added at the top" work the decision
named as part of this PR.
