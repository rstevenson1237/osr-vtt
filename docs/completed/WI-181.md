# WI-181 — Multi-token select

SPEC-056 §3, DEC-109. Single unit (Deceptive). IN-167.

**Changes made**

- `apps/web/src/lib/map/tool-groups.ts` — `isViewTool('select')` is now `true` (SPEC-056
  §3, DEC-109), so the Select button is never locked under the View soft-lock. Select
  keeps its own one-tool `TOOL_GROUPS` entry — icon, cursor, hotkey unchanged — only the
  lock gate changes; `apps/web/src/lib/map/tool-groups.test.ts` and
  `apps/web/src/lib/shell/map-tool-controller.test.ts` cover it.
- `apps/web/src/lib/map/vector-tools.ts` — new pure `lassoSelectTokens(rect, tokens,
  cellSize)`: every token whose centre (converted from `Token.pos`'s pixel space into the
  lasso's lattice-space rect) lies inside the swept region, tested the way a vertex
  `Handle` is (a point, not a whole-bbox containment like an `ObjectSelection`). Unit
  tests in `vector-tools.test.ts`.
- `apps/web/src/lib/tokens/labels.ts` — `tokenRingColor`'s third parameter is the whole
  current selection (`readonly string[]`) now, not one id, so every selected token's ring
  shows white, not just the last one clicked. `labels.test.ts` updated and extended.
- `apps/web/src/lib/components/VectorMapView.svelte` — the core of the item:
  - `selectedTokenIds` (`$state<string[]>`) is the token half of Select's catch, mutually
    exclusive with `selectedHandles`/`selectedObjects`/`selectedBackgroundId` the same way
    those three already are with each other; a `selected-token-count` readout mirrors it.
  - `beginSelectGesture`/`beginBackgroundGesture` clear `selectedTokenIds` on a definite
    geometry/background pick; `finishLasso` tries `lassoSelectTokens` first — **a lasso
    that catches any token selects tokens only** — before falling through to the existing
    handle/object catch.
  - **Read-only geometry under View** (the other half of "Select joins the View group"):
    `beginHandleDrag`, `beginObjectDrag` and `rotateSelectedObject` each skip arming the
    actual drag/write when `mapCtrl.mapMode === 'view'`, though the pick still selects (so
    it stays inspectable — the Room quick sheet keeps opening on a picked `mapRoom`, for
    instance). Backspace is gated the same way. Backgrounds are deliberately left out of
    this gate — DEC-109 enumerates vertices/symbols/labels/doors/drawings, not the
    GM-only background gesture.
  - `attachDragHandlers` (the per-token pointer handler, unaffected by the active tool
    except Eye/Ping, as before): `Shift`-click toggles a token in the multi-selection in
    either Edit or View; a plain click on a token already in the selection leaves the
    whole set selected, so grabbing any of several selected tokens without Shift drags
    the group. Every other selected, actionable token records its pickup-time offset
    (`dragSetOffsets`) and its sprite moves by the same delta live; on drop the whole set
    commits through one `store.moveTokens` batch (`moveTokensUndoable`, one undo entry,
    `lastBatchMoveCount` reading the set's size) — mirroring a collapsed group's anchor
    drag, RTDB `publishDrag` anchor-only the same way. A token that itself anchors a
    collapsed group is excluded as a passenger (it keeps moving through its own
    anchor-drag path, or its stacked members would desync). **Gated on real movement**
    (a `moved` flag set only by `globalpointermove`): a plain click that never drags
    touches no passenger — found and fixed during this item's own e2e pass, since this
    map's default grid quantizes a stationary click's "snap on drop" to a few pixels of
    drift, which previously relayed into every other selected token too.
- `apps/web/tests/e2e/select-tokens.spec.ts` — new spec, three cases: Select stays
  enabled under View while the geometry it picks there is read-only (a lasso-caught door
  survives Backspace); Shift-click toggles a token into and back out of the selection;
  a lasso that catches several tokens selects tokens only, and dragging one moves the
  whole set as one undoable batch.
- `README.md` — "Edit/View soft lock" gains a paragraph on Select joining the View group;
  "The selection model" gains a new "Multi-token select" paragraph.

**Visible behavior changes** — The Select tool button is no longer disabled under the
View lock. Under View, Select can still pick a vertex, symbol, label, door or drawing —
it highlights and (for a room) still opens the Room quick sheet — but dragging it or
pressing Backspace does nothing; switching to Edit restores full editing exactly as
before. Shift-clicking a token adds or removes it from the current multi-selection, in
either mode. A lasso drag that sweeps over any token now selects tokens only (previously
a lasso never caught a token at all). Dragging any token that is part of a multi-selection
moves every selected token together, as one undo step. Every currently-selected token's
ring renders white, not only the one most recently clicked.

**How to verify** — `pnpm verify` (lint/typecheck/unit) and `pnpm verify:all` (adds
rules/store contract suites and the full Playwright e2e suite against the emulators,
including the three new `select-tokens.spec.ts` cases) both green. Manually: as referee,
add three creatures, Shift-click two of them (both rings turn white,
`selected-token-count` reads 2), drag one — all the clicked tokens move together and
Ctrl+Z restores them in one step. Flip the Edit/View toggle to View: Select stays
clickable; picking a wall endpoint or a placed door highlights it, but dragging it or
pressing Backspace leaves it exactly where it was.

**Deviations** — none.
