**Spec:** SPEC-047 §4 · **From:** IN-122 · **Agent:** `claude-code` · **Model:** `haiku` ·
**Effort:** XS · **Closed:** 2026-09-14

## Changes made

None. Checking the code against the gate found the defect already fixed —
`apps/web/src/lib/components/MapToolbar.svelte`'s `HEX_SYMBOL_KINDS` already reads
`hexMap.paintableHexContentsCatalog().map((e) => e.kind)`, which excludes both
`UNKNOWN_HEX_KIND` and any `paintable: false` row, matching `HexTilePanel`'s `CONTENTS`
exactly. This landed as an uncredited part of **WI-123** (`docs/completed/WI-123.md`,
2026-09-11): that item needed `paintableHexContentsCatalog()` for its own two retired
contents rows (`ruins`, `tower`) and, having built the filter, applied it to both
authoring surfaces that read the catalog — the toolbar picker alongside the quick sheet
it was gated against — rather than leaving the toolbar on the raw `HEX_CONTENTS_CATALOG`
it started from. WI-123's own completion summary (line 20-22) records touching
`MapToolbar.svelte` for exactly this reason, though it did not cross-reference this
item (WI-128 did not exist yet — IN-122 was raised checking WI-121's fix, and WI-128
scheduled from it, three days after WI-123 itself ran).

## Visible behavior changes

None beyond what WI-123 already shipped (2026-09-11): the hex Symbol tool's kind picker
does not offer `Unknown`.
