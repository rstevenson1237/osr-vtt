# WI-039 — Hex crawl: infinite hex grid rendering + coordinate pills

**Spec:** SPEC-030 §1 (and §5, partly) · **From:** IN-011 · **Model:** `opus` ·
**Closed:** 2026-08-13

WI-038 left a hex map with a coordinate space, a schema and a store-level producer,
and nothing that drew one. This is the renderer: the infinite flat-top grid, the
`q,r` pill on every hex, the camera that opens on `0,0`, and the two guards that
make a hex map safe to put on stage — View tools only, and a create button so the
map type is reachable at all.

## Changes made

**Pure geometry (new).**

- `packages/shared/src/map/hex/grid.ts` — the viewport arithmetic the grid renders
  from, in pixels, store-free: `hexColumnsInRect` (per column, because a column's
  vertical offset grows with `q` and one global `r` range would over-cover by half
  the `q` span), `hexesInRect`, `hexCountInRect` (the cap check, without building
  the array), `hexOwnedEdgePath` (the three edges a hex owns — NE→E→SE→SW — so
  every edge of the plane is stroked once, not twice), and `hexPillAnchor` (the
  midpoint of the hex's bottom edge). One hex of margin, which is also what keeps
  the viewport's west and north edges from going missing under the three-edge rule.
- `packages/shared/src/map/hex/index.ts` — re-exports it, so it arrives under the
  existing `hexMap` namespace.
- `packages/shared/src/map/hex/grid.test.ts` — 15 cases: the culler covers every
  hex whose centre is in the rect and reaches past every edge, is column-major and
  duplicate-free, scales with the rect and inversely with the size; `hexCountInRect`
  agrees with `hexesInRect`; the owned-edge path is corners 5-0-1-2 and **tiles the
  plane** (no edge in a 9×9 block emitted twice, every interior edge emitted once);
  the pill anchor is the bottom edge's midpoint.

**Renderer.**

- `apps/web/src/lib/map/vector-engine.ts` — `renderHexGrid(size)` on the
  `VectorMapEngine` interface, `renderGrid`'s counterpart: same z-slot between
  `floor` and `overlay`, same pan/zoom/wheel/resize triggers, and mutually
  exclusive with it (each call clears the other's config, and the viewport
  redraw key carries the hex size). New `hexPills` container above `gridGraphics`;
  `paintHexGrid` (one path, one `stroke()`, blank past `MAX_HEXES_DRAWN`);
  `makeHexPill` (`axialKey`'s `"q,r"` on a translucent chip, world-sized like a
  room label); `drawHexPills` caching nodes per `axialKey` across redraws, with
  `null` retiring all of them; exported `hexPillFontPx`/`hexPillsReadable` so the
  legibility rule is unit-testable without a canvas. `exportPng` grew a hex branch
  beside the square one — the frame gets a one-shot grid _and_ one-shot pills, and
  the live pills are hidden for the extract, exactly as the live grid already was.
- `apps/web/src/lib/map/vector-engine-hex.test.ts` — the pill font scales with the
  hex and stays inside it; pills draw at default zoom, drop when the zoom takes
  them below legibility, and the rule is a screen-size rule (a bigger hex survives
  further out) and monotonic in the zoom.

**Wiring.**

- `apps/web/src/lib/components/VectorMapView.svelte` — `hexGrid` derived through
  `isHexMap(map)` (the only place the component reads `map.hex`); `renderAll`
  picks `renderHexGrid(hexGrid.size)` over `renderGrid(...)`; with no remembered
  camera a hex map opens centred on the origin hex rather than putting `0,0` in
  the top-left corner; an effect mirrors the grid kind onto the controller; two
  new introspection readouts, `map-grid-kind` and `map-hex-size`.
- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — `isHexMap` state and
  `setHexMap(on)`, carrying the same fall-back-to-Pan rule `setBattleMap` does;
  cleared in `release()`.
- `apps/web/src/lib/components/shell/sheets/MapToolsSheet.svelte` — the existing
  `toolSubset` now reads `isBattleMap || isHexMap`.
- `apps/web/src/lib/components/shell/MapsPanel.svelte` — `addMap(gridKind)` and a
  second button, **"+ New hex crawl"** (`maps-add-hex`), plus a `Hex` badge on a
  hex row (`map-kind-{id}`, present in the DOM for every row, shown only for hex).

**Docs.**

- `README.md` — "Hex-grid maps" gained a "Rendering a hex map" subsection (the

- `PLAN.md` / `PLAN-COMPLETED.md` — WI-039 moved to §3.

## Visible behavior changes

- **Assets → Maps has a second create button, "+ New hex crawl".** A map made
  with it renders an infinite flat-top hex grid instead of the square lattice,
  with each hex's `q,r` in a small translucent pill on its bottom edge, and opens
  centred on `0,0`. Zooming far out drops the pills (they stop being readable)
  and, further out still, the grid.
- **A hex crawl's tool palette shows the View group only** — Pan, Eye, Measure,
  Ping. Selecting a hex map with a carve tool armed falls back to Pan.
- **A hex row in the maps list carries a `Hex` badge.** Square-grid maps are
  unlabelled, and nothing about them changed: same grid, same tools, same camera.

## How to verify

- `pnpm verify` — lint, typecheck, unit. The two new suites are
  `packages/shared/src/map/hex/grid.test.ts` and
  `apps/web/src/lib/map/vector-engine-hex.test.ts`.
- `pnpm verify:all` — the above plus rules/store/e2e against the emulator;
  `apps/web/tests/e2e/hex-map.spec.ts` is the acceptance run.
- By hand: create a room, open **Assets**, click **+ New hex crawl**, then
  **Switch to this map**, and return to the Map view. The hex grid should
  fill the canvas with `0,0` at the centre of the viewport and a coordinate pill on
  every hex; the Map tools sheet should offer four tools. Wheel-zoom out and the
  pills disappear before the grid does.

## Deviations

Two additions beyond "rendering + pills", both recorded here rather than left as
intake items because the work item is unshippable without them (RULE-015's
unblocking exception):

1. **The UI producer.** WI-038 left `createMap({ gridKind: 'hex' })` as the only
   producer, store-level — so before this change no user could reach a hex map,
   and neither could an e2e spec. Rendering a map type nobody can create is not a
   deliverable, and none of WI-040/WI-041 covers creation either. Hence
   `maps-add-hex` and the `Hex` badge.
2. **The View-tools-only subset**, which is WI-041's territory (SPEC-030 §5). Once
   a hex map is reachable from the UI, leaving the carve tools armed on one lets a
   gesture write square-lattice geometry onto a map whose coordinates are axial —
   the exact thing RULE-006 forbids. The blunt form (reusing the battle map's
   existing `toolSubset` path, ~10 lines) closes that hole; WI-041 still owns the
   real story, which is the overlay tools a hex map _should_ keep plus the hex-tile
   quick sheet, and it will replace this subset rather than inherit it.

Nothing else changed shape: no store method, no schema field, no security rule,
no migration, and no `data-testid` moved or was removed — the four new ones
(`maps-add-hex`, `map-kind-{id}`, `map-grid-kind`, `map-hex-size`) are additions.
