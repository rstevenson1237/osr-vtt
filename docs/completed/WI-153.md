# WI-153 — Seat the creator as Referee

SPEC-054 §2. Part of Batch 1 (WI-152–158) — one pull request, one combined summary.

**Changes made**

- `Lobby.svelte` — `createRoom` calls `store.joinRoom(roomId, 'Referee')` before
  `navigateToRoom`, exactly as the local build's `RoomShell` already auto-seats. The
  player join path and `joinRoom`'s contract are unchanged.

**Visible behavior changes** — a referee who creates a hosted room lands straight in
the room shell; they no longer meet the Display name / Join room gate for a room they
just made. A referee who opens the invite link in a second browser still meets the
ordinary gate.

**How to verify** — `pnpm verify:all` green. Manually: create a room on the hosted
build and confirm no join gate appears; open the same room's invite link in a second,
signed-out browser and confirm the ordinary gate still does.

**Deviations — the unblock exception (RULE-015).** This change makes the referee's own
`createRoomAndJoin`-style e2e helper — used across ~26 spec files — try to fill a join
form that no longer renders, hanging every affected test at its 180s timeout. Verifying
this item (step 6 requires a green `pnpm verify:all` before the summary is written)
was blocked until those helpers were fixed, so the fix is filed here as an unblock
rather than a separate intake item: across
`accounts-rooms/backgrounds/battle-map-capture/battle-map-lifecycle/combat-modes/
dice-overlay/dice-profiles/encounter-board-v2/encounter/fog/group-ownership/hex-map/
log-chat/map-draw-feedback/mobile/portability/presence/presentation/referee-engine/
room-lifecycle/rooms-manager/session-config/shared-roll/shell-navigation/
token-image-load/two-context.spec.ts` (+ `helpers.ts`), removed the now-dead
`join-display-name` fill + `join-submit` click that used to follow the referee's own
room creation — every genuine second-seat/player join (`player`/`gm2`-style pages) is
untouched. One test (`accounts-rooms.spec.ts`, "an anonymous visitor is offered
sign-in instead of a failing Create") explicitly asserted the join gate appeared for
the creator; updated to assert `room-name` instead. One test
(`dice-overlay.spec.ts`, "character quick sheet header shows and edits the seat name")
relied on a custom initial display name set via the join form, which WI-153 makes
impossible (the referee is always seated "Referee"); rewritten to rename via the
sheet's own edit affordance first, which is what the rest of that test exercises
anyway. Full `pnpm verify:all` (unit, rules, store, all 100 e2e specs) is green after
these fixes.
