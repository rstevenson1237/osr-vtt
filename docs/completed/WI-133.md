# WI-133 — A river is smoothed at render time, not at commit

**Spec:** SPEC-047 §16 · **From:** IN-126 (via DEC-095) · **Model:** `opus` · **Closed:** 2026-09-15

## Changes made

- **`apps/web/src/lib/map/vector-engine.ts`** — new exported
  `smoothHexLinePoints(points, segments = HEX_LINE_SMOOTH_SEGMENTS)` and
  `HEX_LINE_SMOOTH_SEGMENTS = 8`, beside `hexTerrainArtPx`/`hexContentsArtPx`. It samples a
  **centripetal** (α = ½) Catmull-Rom through a line's stored vertices, **in the thirds
  lattice** — `hexPointToPixel` is affine, so the curve is identical to one sampled in pixels,
  and the samples are free (non-integer) `HexPoint`s, which SPEC-047 §1 already admits.
  Endpoints are reflected rather than duplicated (the curve leaves the first click along the
  run's own direction); coincident consecutive clicks are dropped before the knot spacing is
  computed; fewer than three distinct vertices returns the run untouched. A small
  `lerpHexPoint` carries the barycentric weights.
  `strokeHexLine` — shared by the committed pass and §12's preview since WI-126 — gains a
  `smooth: boolean` parameter and smooths only when `smooth && line.join === 'round'`.
  `renderHexLines` passes `true`; `renderHexLinePreview` passes `false`.
- **`apps/web/src/lib/map/vector-engine-hex.test.ts`** — a new `smoothHexLinePoints` describe
  block: the curve passes through every clicked vertex and keeps the first and last exactly;
  it samples `1 + segments·spans` points; it does not mutate the input; a straight two-click
  run is returned as clicked; coincident clicks produce finite output; the curve leaves the
  straight legs of a dog-leg but drifts by under a third of a hex step.
- **`docs/spec/SPEC-047.md` §16** — a "Built by WI-133" note recording the parameterisation,
  where the flag is applied, and that an interpolating spline bows slightly *outside* a hard
  corner by design.
- **`README.md`** → "Hex overlays — symbols, roads and rivers" — a bullet for the render-time
  curve: nothing stored changes, it keys off the stored `join`, the preview stays raw.
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — ledger moves.

## Visible behavior changes

A **river** (any line whose stored `join` is `'round'`) now draws as a smooth curve through
the referee's clicks instead of a chain of straight segments — including every river already
drawn, with no redraw and no migration. A **road** is unchanged: it mitres and stays angular.
The in-progress **preview is unchanged** — it remains the raw polyline, so the smoothing
appears when the gesture commits, as SPEC-047 §16 asks. The curve bows slightly outside a hard
corner (~0.2 thirds on a 3-thirds span), which reads as a meander. Nothing is written anywhere
and no control moved.

## How to verify

- `pnpm verify` — lint, typecheck and unit, including the new
  `smoothHexLinePoints` block in `apps/web/src/lib/map/vector-engine-hex.test.ts`.
- In the app: on a hex map, draw a River click-to-click over several hexes. The ghost while
  drawing is straight-segmented; the committed line is curved. Draw a Road over the same
  clicks — it stays angular. Reload: an existing river is curved without having been touched.

## Deviations

- **The emulator battery (`pnpm verify:all`) was not run locally** — no `firebase` CLI in this
  sandbox, the same constraint WI-130/WI-131/WI-132 recorded. It runs in CI on the PR. The
  change is render-only and touches no store, rule or `data-testid`.
- **`strokeHexLine` gained a parameter** rather than the smoothing being applied at the
  `renderHexLines` call site. Required to keep §12's preview raw while the committed pass
  smooths, from the one shared function WI-126 deliberately left shared.
