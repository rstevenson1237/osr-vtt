# WI-081 — Background transform UI in the Assets activity

**Spec:** SPEC-038 §§3–5 · **From:** IN-053, IN-054 · **Decision:** DEC-063 ·
**Agent:** `claude-code` (`opus`) · **Effort:** high · **Closed:** 2026-08-12

The second and last half of SPEC-038. WI-080 gave a map any number of placed
background images (`maps/{mapId}/backgrounds`, schema v23) and rendered them;
this gives the referee a way to place, move, resize and remove them — and moves
background management out of Session config into the Assets activity, retiring
every `session-background-*` testid.

## Changes made

**New — the transform math (pure, unit-tested):**

- `apps/web/src/lib/map/background-transform.ts` — `fitBackgroundToGrid`,
  `moveBackground`, `resizeBackground` (aspect-locked from the image's native
  width:height, driven by whichever axis the pointer travelled further along,
  clamped to `MIN_BACKGROUND_CELLS = 0.5` rather than inverting the rect),
  `backgroundHandlePoint`, `backgroundHitTest` (`handle` > `body` > `null`) and
  `backgroundRectChanged`. Lattice units throughout (RULE-006); nothing here
  knows about `cellSize`.
- `apps/web/src/lib/map/background-transform.test.ts` — 16 cases, including the
  two the spec turns on: a resize never stretches (`w/h` stays native even for a
  rect the v22→v23 fold left grid-shaped), and a click that never moved reports
  no change.

**New — the alignment overlay (SPEC-038 §4):**

- `apps/web/src/lib/map/vector-engine.ts` — exported pure `alignmentGridLines`
  (grid lines clipped to a rect, edge-inclusive with float slack) and a new
  `VectorMapEngine.renderBackgroundAlignment(rect, cellSize, gridStep, subdivide)`
  (a `null` rect clears it). Draws the map's own grid over the selected image in
  `theme.selection` at reduced opacity, plus the rect outline and the one resize
  handle, on its own `PIXI.Graphics` in the never-persisted `tools` layer.
  Redrawn from `maybeRedrawViewport` (its line weight and handle size are in
  screen pixels, so a zoom must redraw) and from `setTheme`.
- `apps/web/src/lib/map/vector-engine-bg-align.test.ts` — 6 cases over the
  clipping arithmetic.

**New — the panel (SPEC-038 §5):**

- `apps/web/src/lib/components/shell/BackgroundsPanel.svelte` — GM-only.
  Lists the active map's placed images in paint order with a thumbnail, label
  and `x, y · w × h` readout; adds from the Bundled/Saved-URL picker (fitted to
  the grid at the image's **native** ratio, `order = max + 1`, then selected for
  adjusting, which puts the map back on stage); **Adjust on map** toggles
  `MapToolController.selectedBackgroundId`; **Fit** resets to the whole grid;
  **✕** removes. Carries the solid background **colour** over from the retired
  Session block (presets, custom hex, Clear colour).

**Changed:**

- `apps/web/src/lib/shell/map-tool-controller.svelte.ts` — added

## Visible behavior changes

- **Session settings no longer has a Background control.** It moved wholesale —
  images _and_ the solid colour — to **Assets → Background**.
- A map can now show **several** background images, each placed independently;
  adding one no longer replaces what was there.
- A newly added image lands **fitted to the grid at its own aspect ratio**
  instead of stretched across the whole grid.
- **New:** a referee can select an image and drag it around the map, or drag its
  bottom-right handle to resize it — always without stretching. While an image
  is selected, the map's grid is drawn over it in translucent yellow so the art
  can be lined up against the lattice; Escape (or clicking **Adjust on map**
  again) clears it. Players see none of this.
- Every `session-background-*` testid is gone; `background-*` replaces it.

## How to verify

- `pnpm verify` — lint, typecheck, and the unit suites, including the 22 new
  cases in `background-transform.test.ts` and `vector-engine-bg-align.test.ts`.
- `pnpm verify:all` — the above plus rules/store/e2e against the emulator;
  `backgrounds.spec.ts` is the acceptance flow.
- By hand: Assets → Background → **+ Add image** → _Starter map_. The app lands
  on the Map with the image selected and the yellow alignment grid over it. Drag
  it; drag the handle on its bottom-right corner and watch both dimensions move
  together. Escape, then back to Assets: the readout matches where it was left.
  Session settings has no Background field.

## Deviations

- **The alignment overlay is drawn in `theme.selection`, not `theme.grid`.**
  DEC-063 described it as "the theme's map-grid colour token at reduced
  opacity", but SPEC-038 §4 calls for **translucent yellow**, and `--map-grid`
  is `#000000` (parchment-dark) / `#1a2733` (keyed-blue) — a near-black overlay
  over dark map art is invisible exactly where it is needed.
  `--map-selection` (`#ffcc66` / `#e8a33d`) is the app's existing yellow
  affordance colour, so the spec's requirement and DEC-063's "a theme token, no
  new render primitive" are both satisfied. Everything else about the overlay
  follows DEC-063: the grid geometry is reused, and it shows the whole time a
  background is selected rather than only mid-drag.
- **The transform gesture is on the map canvas, not in the panel.** SPEC-038 §5
  puts "per-asset transform controls" in the Assets activity while §3 calls for
  a drag and a handle — and the Assets activity is a full-screen main view, so
  the map is not on screen while it is open. Resolved by splitting along the
  seam SPEC-016's superseded-in-place annotation already names ("on-canvas
  selection is introduced for the first time, gated GM-only"): the panel owns
  selection, addition, the colour, the readout, Fit and removal; the canvas owns
  the gesture, and selecting an image switches the main view to the Map so the
  two read as one flow.
- **Reordering was left out.** `setBackgroundOrder` exists from WI-080, but
  restacking is not "move/resize" and is named nowhere in the work item or in
  §§3–5, so it stayed out of scope (RULE-015). New images stack on top
  (`order = max + 1`), which makes add order the paint order. A referee who
  wants a different stack has to remove and re-add for now — worth an intake row
  if it comes up in play.
- **No confirm on removing an image**, matching the retired Remove background
  button rather than `MapsPanel`'s confirmed map delete: an image is cheap to
  re-add, and the retired control set the precedent.
