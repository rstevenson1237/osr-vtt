# WI-136 — A staging call blocks every other die control, and the referee can cancel it

**Spec:** SPEC-050 §3 · **From:** IN-132 · **Model:** `sonnet` · **Closed:** 2026-09-16

## Changes made

- **`packages/shared/src/store/campaign-store.ts`** — new `cancelSharedRoll(roomId: string):
  Promise<void>` on the `CampaignStore` interface (RULE-001): referee-only, sets the staging
  doc to `resolved` without writing a `Roll` and without touching the tracker.
- **`packages/shared/src/store/memory-store.ts`** and **`firebase-store.ts`** — implementations.
  Both no-op if no staging doc exists (mirroring `resolveSharedRoll`'s guard shape).
  `LocalStore` needs no change — it extends `MemoryStore` and inherits the method.
- **`packages/shared/src/store/campaign-store.contract.ts`** — two new cases in "shared rolls":
  cancelling a staging round writes no `Roll` and flips status to `resolved`; cancelling with
  none open is a no-op. Runs against `MemoryStore` (`test:unit`) and, in CI,
  `FirebaseStore`/`LocalStore` against the emulator.
- **`apps/web/src/lib/components/CombatTracker.svelte`** — a referee-only
  `combat-cancel-initiative` button next to `combat-roll-initiative`, calling the new
  `cancelInitiative()` → `store.cancelSharedRoll(roomId)`.
- **`apps/web/src/lib/dice/roll-or-stage.ts`** — no change; its exported `initiativeCallOpen`
  is reused by the UI components below rather than re-implemented per component.
- **`apps/web/src/lib/components/shell/sheets/RollSheet.svelte`** — new `sharedRoll` prop;
  `callBlocking = initiativeCallOpen(sharedRoll)` disables the quick-roll die buttons,
  `roll-button` and `roll-hidden-button`, and shows a `roll-sheet-call-blocked` note. Passes
  `blocked={callBlocking}` to `TrayControls`/`MacroList` (docked) and `sharedRoll` through to
  `DiceTray` (expanded).
- **`apps/web/src/lib/components/DiceTray.svelte`** — new `sharedRoll` prop, same
  `initiativeCallOpen` gate on `tray-add-dN`/`tray-add-custom`/the custom-die input; passes
  `blocked` to `TrayControls`/`MacroList`.
- **`apps/web/src/lib/components/dice/TrayControls.svelte`** — new `blocked` prop disabling
  the modifier input and every advantage/mode toggle button.
- **`apps/web/src/lib/components/dice/MacroList.svelte`** — new `blocked` prop disabling
  `macro-save` and `macro-replay-{id}` (guarded in the functions too, not just the buttons);
  `macro-delete-{id}` is untouched — deleting isn't a die action.
- **`apps/web/src/lib/components/SharedRollStaging.svelte`** — this panel drives an *ordinary*
  shared roll on the same `sharedRoll/current` doc, keyed by a bare uid; during an initiative
  call that doc's slots are `side:{groupId}`/`{uid}:{tokenId}`, so opening or resolving one here
  would corrupt the call rather than merely duplicate it. `isStaging` now excludes an
  initiative call, and a new `isInitiativeCall` branch shows a `shared-roll-call-blocked` note
  in its place — the "Open shared roll" and "Roll!" buttons for this panel simply don't render.
- **`apps/web/src/lib/components/SharedRollReadiness.svelte`** — same doc, same risk, from
  inside `CombatTracker` itself: its own `shared-roll-tracker-roll-button` and
  `shared-roll-add-slot-button` write/resolve the identical doc outside
  `combat-roll-initiative`/`combat-cancel-initiative`. Both now guard on a new
  `isInitiativeCall` derived value (function bodies and `disabled` attributes both), and a
  `shared-roll-tracker-call-blocked` note explains why. The readiness list itself stays
  visible — it's the same read-only information `combat-staging-note` already shows.
- **`apps/web/src/lib/components/RoomShell.svelte`** — threads its existing `sharedRoll` state
  (already subscribed for `TurnStrip`, WI-135) into `<RollSheet>`.
- **`README.md`** — "Dice (II.6)" gains a paragraph documenting the blocking behaviour and
  Cancel call, beside the existing Call for Initiative paragraph (RULE-018).
- **`apps/web/tests/e2e/shared-roll.spec.ts`** — new case: calling initiative blocks the Roll
  sheet's dice/Roll/Hidden buttons, the tray's add-die control, and the ordinary shared-roll
  panel; Cancel returns the room to a rollable state with no tracker change.
- **`PLAN.md` / `PLAN-COMPLETED.md` / `INTAKE.md`** — ledger moves.

## Visible behavior changes

- **While a Call for Initiative is staging, every unrelated die control disables and says
  why** — the Roll sheet's dice buttons and Roll/Hidden buttons, the dice tray's add-die and
  custom-die controls, saved macros (save and replay), the tray's modifier/advantage/mode
  toggles, the ordinary "Open shared roll"/"Roll!" panel in the Dice sheet, and the tracker's
  own add-slot/Roll-now controls. **The referee is not exempt anywhere** — their own
  `roll-button`/`roll-hidden-button` block too, per the user's answer to DEC-097.
- **A new referee-only Cancel call button** (`combat-cancel-initiative`, beside "Roll for
  Initiative") ends a staging round with no roll and no tracker change — the only way out of a
  call opened by mistake, since "Roll for Initiative" stays disabled while nobody is ready.
- Controls bound to an actor in the call (a card's die button, a profile roll shortcut, via
  `rollOrStage`) are unaffected — they still stage into the call exactly as before.
- No `data-testid` moved (RULE-005) — every new testid (`combat-cancel-initiative`,
  `roll-sheet-call-blocked`, `shared-roll-call-blocked`, `shared-roll-tracker-call-blocked`) is
  additive.

## How to verify

- `pnpm verify` — lint, typecheck, unit; green.
- In the app: as referee, start a Side- or Individual-mode encounter and press **Call for
  Initiative**. Open the Roll quick sheet (docked or expanded) — every die button, Roll,
  Hidden, tray add-die/custom-die, and any saved macro's Load/Save are disabled, with a note
  explaining why; the Dice sheet's "shared roll" panel shows the same note instead of its usual
  controls. Press **Cancel call** on the tracker — the note disappears everywhere, every
  control re-enables, and the tracker's rows are untouched (no initiative value written).
- `pnpm verify:all` runs the emulator-backed rule/store/e2e suites; not run locally in this
  sandbox (see Deviations).

## Deviations

- **The emulator-backed suites (`pnpm verify:all`) did not run locally** — no `firebase` CLI
  in this sandbox, consistent with every other work item in this batch. `pnpm verify` (lint,
  typecheck, unit — which includes the new `cancelSharedRoll` contract cases against
  `MemoryStore`) ran green; the full suite (including the same cases against `FirebaseStore`
  and `LocalStore`) runs in CI.
- **`SharedRollStaging` and `SharedRollReadiness` were gated beyond the three components SPEC-050
  §3 names by testid** (Roll sheet, dice tray, macros). Both drive the *exact same*
  `sharedRoll/current` doc an initiative call uses, under a slot-id shape (`{uid}`, or an
  arbitrary GM-chosen id) the call's own logic does not expect — leaving either reachable would
  let a stray "Roll!" press resolve or corrupt the call outside `combat-roll-initiative`/
  `combat-cancel-initiative`, which is the exact hole DEC-097 (b) is meant to close. Gating them
  is the same instruction ("a die control that is not this call's staging path is disabled and
  says why") applied to two controls the text's examples didn't happen to name, not a change of
  scope — logged here per RULE-015 rather than silently folded in.
